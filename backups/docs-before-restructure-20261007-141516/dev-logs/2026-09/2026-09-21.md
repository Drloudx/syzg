## UI 与交互

### 关卡图鉴：地区路线图节点对齐游戏（用户反馈轮）

用户给了三张游戏截图，指出地区路线图「名字位置不对、图标大小不对」。按交接说明的做法**先量后写**：从素材里量出真实尺寸再改 CSS，不再靠截图估。

- **名称牌位置**（三类节点各自对齐游戏）：
  - **关卡编号**：游戏里是**没有底板的白字 + 深色描边**，居中挂在石台下方。原先画的是深色小牌子（`.region-map__node-label` 带背景/边框/圆角），现在改成纯文字 + `-webkit-text-stroke` + `paint-order: stroke fill`，并补 4px 间距。
  - **地区名称牌**：改成挂在圆盘下缘（`top: 100%`），紧贴圆盘下方。
  - **副本名**：游戏里副本图**自带一块石牌**（`map_w1_cN_dM` 的 y 148..165 一带，180 高 => 距底 8.3%）。原先挂在图外下方（`bottom: 5%`，实测标签在图形底边外 5.8px，而且 `line-height` 让盒子高度算成 0），现在改成压在图上自带的牌子里（`bottom: 8%`）。
- **图标大小**：地区节点与副本节点改成按 **sprite 自身的圆盘/图形比例**推算，不再拍数字。地区盒子直接做成**圆盘本身**（56×56），sprite 用 `width: 57.4px` 反推着摆（`map_w1_cN_aM` 是 244×258，圆盘宽 238 = sprite 宽的 97.5%）。副本节点 72 → 74px。
- **「自由探索」标签**：补上游戏原图的 `map_a_tag`（120×24），挂在名称牌正上方。

### 第二轮反馈：去掉橙环、修正两个节点图的锚点

- **去掉橙环与角标**：`map_select_out` / `map_select_in` / `map_select_corner` 是 `AreaItemUI.selectGo` 的**选中态**装饰，本站没有「当前选中地区」这个状态，按用户要求不显示。四个 sprite 里只保留 `area_tag`，另外三个的矩形常量、导入项、产物文件一并删除（不留无引用素材）。
- **锚点修对了**：两个节点图的锚点语义和「sprite 居中摆放」不一致，之前照搬源码的偏移反而把图标抬离了节点。

### 第三轮反馈：图标尺寸恢复真实比例、名字牌位置紧密抱合、实现统一画布自然缩放

用户提供了实机对比截图，指出：「小地区和副本的图标太小了」、「名字位置不对，关卡名字位置也不对」、「放大的时候为什么只有底图放大了，这些都没放大」。

- **查源码查出的根本原因**：
  1. **缩放被刻意抵消了**：原实现写了 `transform: translate(-50%, -50%) scale(1 / zoom)`，试图让节点屏幕尺寸恒定，导致地图放大时节点被除以 zoom，纹丝不动。而游戏源码 `MapPanel.cs` 里所有节点（`mapLevelStageRoot`, `mapAreaRoot`, `mapInstanceRoot`）和底图全部挂在同一个 `areaZoom` 下，缩放是对整个场景统一进行的。
  2. **图标尺寸被过度缩水**：游戏源码中 `AreaItemUI` 与 `InstanceRoomItemUI` 均执行了 `MakePixelPerfect()`，即 100% 原图分辨率！地区建筑原图为 244×258（圆盘宽 238），副本为 172×200，关卡石台为 128×128。原先代码把地区压到 56px（缩小至 23%）、副本压到 74px、关卡压到 54px，造成小地区和副本小如豆子，而 156px 的名称牌比房子还宽 3 倍。
- **调整实施**：
  - **废除反向缩放**：移除 `scale(1 / zoom)`，所有节点直接基于 Canvas 像素在画布坐标系（如 3400×2100）下工作，随父级 `.region-map__canvas` 的 `scale(zoom)` 自然平滑缩放，底图放大时节点、建筑、文字同步等比例放大。
  - **尺寸与锚点对齐原版**：
    - **关卡石台**：恢复为 128×128（中心锚点），关卡短号采用紧贴底座下边缘的粗白字 + 3.5px 黑色浓描边（字号 22px），彻底解决编号掉落在离石台很远下方的问题。
    - **小地区建筑**：恢复为 244×258 真实像素（圆盘中心 75.4% 处锚点），「·自由探索·」标签紧扣在圆盘下边缘（top: 220px），名称牌紧扣在其正下方（top: 236px，两端菱形修饰），牌子与 238px 宽的圆盘比例协调。
    - **副本建筑**：恢复为 172px 真实宽度（圆盘底座 70% 处锚点），副本名称居中嵌入图片自带的深褐色牌子（中心距底约 40px）内部。
    - **金色连线**：调整为 6px 虚线，随着地图放大自然清晰。

### 第四轮反馈：小地区按底座基准对齐（消除建筑高度差异悬空）、副本文字内嵌深褐色底框（防遮挡迷宫挑战）

用户反馈截图指出：
1. **旧日修行所**：标签和名称牌浮在半空、压在教堂正门上；
2. **旅店地窖（副本）**：名字向上覆盖了自带的「迷宫挑战」标志。

- **逐像素分析与根本原因**：
  1. **小地区建筑高度不一致**：小地区建筑图片高度并不固定（驿站 258px、旧日修行所 299px、观星高地 268px），但**所有建筑的圆盘底座均紧贴图片底沿（底边距底 13~14px，圆盘中心距底 63.5px）**。之前写死了 `top: 196px`，以顶部为基准往下算，导致 299px 高的旧日修行所牌子浮在教堂半山腰。
  2. **副本文字框偏高压顶**：副本图片的深褐色底板实际高度为 **24px（bottom: 26px ~ 50px）**，而上方的“迷宫挑战”在 **bottom: 62px ~ 66px**。此前将文字容器设为 `height: 44px; bottom: 26px`，容器顶边达到 `bottom: 70px`，直接压住了上方的“迷宫挑战”。
- **针对性调整**：
  - **小地区改为底座绝对基准（bottom）**：
    - 节点容器 `transform: translate(-50%, calc(-100% + 63.5px));`，以圆盘中心精准落位；
    - 建筑 `art` 设为 `bottom: 0`（尖顶自然向上延展）；
    - 自由探索标签设为 `bottom: 38px`，地区名称牌设为 `bottom: -2px`；无论建筑是 258px 还是 299px，底座石阶与铭牌位置 **100% 绝对一致**，彻底解决悬浮错位。
  - **副本文字精准内嵌深褐色底框**：
    - 文字容器设为 `height: 24px; bottom: 26px; font-size: 18px;`，文字中心严格对齐深褐色底板中心（38px），上边缘距离“迷宫挑战”留有 12px 清晰间隙，彻底杜绝重合遮挡。


## Bug 修复

### 地区名称牌文字用了会随主题翻转的颜色

名称牌是深青底，文字原用 `color: var(--paper)`——`--paper` 在暗色模式下会变深（`#2e2217`），字和牌底糊在一起，暗色模式几乎读不出。改用 `--on-wood-text`（深底上的亮色前景，明暗同色），实测暗色模式下仍是 `rgb(223, 206, 179)`。这正是 UI 规范里「不能拿随主题变化的背景色充当前景」那条。

### `chapterMapLayout.mjs` 的图集矩形常量是错的（重跑导入会切出空图）

核对产物与图集 `mSprites` 表后发现三处常量与真实来源不符：

| 常量 | 原值 | 实际来源 |
| --- | --- | --- |
| `AREA_TITLE_RECT` | `(317,683,164,52)` — **切出来是空白**（只有 36 个不透明像素） | `map_a_title` `(317,1342,164,52)` |
| `STAGE_PLATFORM_RECT` | `(402,1004,126,126)` | `map_s` `(401,1662,128,128)` |
| `STAGE_PLATFORM_LOCKED_RECT` | `(402,1133,126,126)` | `map_s_lock` `(401,1791,128,128)` |

已有的 `.webp` 产物内容是对的（逐像素比对确认来自正确的 sprite），但常量一旦重跑就会写坏。现在全部改成**直接取图集 `mSprites` 表**的值（源码 `LevelStageItemUI` 用的就是 sprite 名：未开放 `map_s_lock`、单难度 `map_s_1st`、多难度 `map_s`）。同时把 `ATLAS_PATH` 指到**完整尺寸**那张：同目录 `MapPanelAtlas.png` 是 2047×1389 的缩略版，sprite 表的 y 会越界（`extract: bad extract area`），完整版是 2048×2048 的 `MapPanelAtlas #11770.png`。核对入口 `scripts/dev/scratch/find-sprite-origin.mjs`。

   - **普通单层关卡**：按闯关顺序统一命名为 **`房间 1`**、**`房间 2`**、**`房间 3`**……；
   - **多层关卡（如 2-9, 4-2）**：按层数与顺序统一命名为 **`房间 1-1`**、**`房间 1-2`**……，第 2 层为 **`房间 2-1`**、**`房间 2-2`**……；
   - **自由探索（小地区）**：有具体地点名（如“驿站住民区”、“枯草小径”、“莉拉的修行所”等）的房间完整保留原名；若有少数缺名字的房间（如索利德山地），统一兜底命名为 **`房间 1`**、**`房间 2`**……。
