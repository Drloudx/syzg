## 数据与解析

### 评论审核词表取自游戏词库，但只取高置信子集

- 来源是游戏聊天风控词库 `Config_decrypted/words.json`：**不是 JSON 对象，而是逗号分隔的单个字符串**，
  95,050 字符、去重后 **14,078 条**。
- 实测词表性质：中国互联网垃圾广告词库（赌博 / 壮阳药 / 迷药 / 成人 / 政治敏感 / 垃圾域名与手机号）。
  其中激素类只有 2 条（`促性腺激素`、`蛋白合成激素`），用户印象中的"激素表"实际以**壮阳/迷药类**为主（24 + 10 条）。
- **整表同步被否决，两条独立理由**：
  1. **误伤**：表内含大量日常词——`比例`、`真实`、`购买`、`买菜`、`我爸`、`炸鸡`、`善良`、`香港`、`港口`，
     以及 464 个单字词（含 `草`、`妈`、`爸`、`鸡`、`&`）。"这里的比例不太对，真实伤害是 305%"会被全表命中。
  2. **性能**：Workers 免费版每次调用只有 10ms CPU。本地实测每条评论匹配耗时——
     **全表扫描 0.82ms / 筛后词表+首字索引 0.076ms / 类别正则 0.0040ms**。
- 最终形态：`src/config/commentBlocklist.js` 用**7 条类别正则**（赌博/色情/违禁药/违禁品/诈骗/引流/政治敏感），
  按低误伤写法逐个挑选（例如「赌」只收 `赌博/赌场/赌球/下注/博彩`，不收单字 `赌`，否则"别赌气"被拦），
  外加 2 条结构性规则（外链、HTML 标签）。命中语义是**进待审而不是拒收**。
- `scripts/dev/sync-comment-blocklist.mjs` 是**只读校验**而非生成器：把类别正则套用到游戏词库上，
  报告每类命中数（22/19/32/4/1/6/9 条），并自检"正常评论零误伤、垃圾样本零漏检"。
  缺游戏配置目录时静默跳过，不参与 `npm run verify`。
- **中途纠正了一次自己的错误**：初版按印象逐词列举，校验脚本抓出 27 个游戏表里根本不存在的词
  （`私聊`、`刷单`、`加微信`、`洗钱`、`qvod`…）。改为按类别正则从游戏表实测导出后，词表与来源一致。

### 头像清单与「存 ID 不存路径」

- 新增 `scripts/dev/sync-avatar-catalog.mjs`：扫 `public/images/HeadIconAtals/`，按前缀生成

  Worker 读不到 `public/` 下的文件，硬编码白名单会与素材脱节。
  非法 ID 丢弃为 `null`、回退昵称首字占位，**不因此拒绝整条评论**（已单测）。
- 迁移：远端与本地 D1 都已加 `avatar` 列（`ALTER TABLE ... ADD COLUMN`）。

### D1 表结构

- 库 `myrzg-comments`，id `5f0d4c37-107f-4811-bc5e-768f73c51a3a`，region WNAM。
  `comments` + `rate_limits` 两张表，**只建 2 个索引**：写入按行计费（索引也算行），
  全局清理用的 `created_at` 索引经权衡后**刻意不建**——D1 读便宜（500 万行/天）、
  写贵（10 万行/天），而清理查询极少执行。
- `comments` 关键字段：`status`（1 显示 / 0 待审 / 2 已隐藏）、`token_hash`（浏览器自删令牌的 SHA-256）、
  `review_reason`（命中的审核类别）、`avatar`（头像 ID）、`ip_hash`（限流用）。
- 增量迁移（远端与本地都已执行）：`token_hash` → `review_reason` → `avatar`。

### 移除 Gravatar（邮箱生成头像）

初版用邮箱哈希拼 `cn.gravatar.com` 取头像，**已删除**。用户问"邮箱生成头像是什么意思"时自查发现两条硬伤：
① Gravatar 是 Automattic 的服务，**国内用户绝大部分没有账号**，拿到的是随机几何图，不是本人头像；
② 它要把邮箱标识发给第三方，与"只存哈希、不存明文邮箱"的隐私取向**自相矛盾**。
现在头像用游戏素材自选，无头像时回退昵称首字。`comments.email_hash` 列保留但不再使用
（SQLite 删列代价高，留历史数据无害）。列表响应也**不再返回 `emailHash`**，已加断言锁住。

## 架构与决策

### 评论方案与免费额度（官方文档核实）

- Cloudflare 免费版可支撑：Functions 10 万次/天、D1 读 500 万行/天 + 写 10 万行/天 + 存储 5 GB、
  Turnstile **完全免费且挑战次数不限**、静态资源请求免费不限量、无 egress 费用。
- **CPU 10ms 是硬约束**：实测 PBKDF2-SHA256 —— 10,000 次 2.5ms、100,000 次 18.7ms、
  **600,000 次（OWASP 现行推荐）104ms**。
- **决策：一期不做账号体系**。理由：① 免费版 CPU 上限让"自己存密码"只能压到安全推荐值的约 1/60；
  ② 想安全就得引入托管认证（独立一期更合适）；③ 它解决不了真正的问题（防机器人靠 Turnstile + 限流，
  删评论管理员已能做），反而增加注册/登录/找回密码等管理工作；④ 存邮箱带来隐私保护义务。
  迁移余地已留（将来加 `users` 表 + `user_id` 外键即可，不用重建数据）。
- 用户自删走**浏览器令牌**：发表时自动下发并存 localStorage，用户无需记任何东西；
  换设备/清浏览器数据后需联系管理员。相比"设密码 + 忘密码 + 没救"是更优取舍。

### 三个实测出来的坑

1. **SPA 兜底会吃掉 API 请求**：`public/_redirects` 是 `/* /index.html 200`，实测线上 `/api/health` 返回
   **200 + `text/html`**。已加 `/api/* /api/:splat 200` 放行规则（`_redirects` 不支持 `!` 取反，
   只能显式放行）。本地验证 `/api/health` 已返回 `application/json`，且 SPA 兜底仍正常。
2. **EdgeOne 不缓存 JSON**（同一 URL 连打三次的对照实验）：`/ui/logo.webp` → `HIT`、`Age` 递增；
   `/data/parsed/items.json?same=1` → **`MISS`、`Age=0` 始终不变**，而源站已带
   `immutable, max-age=31536000`。说明该域名按**文件类型**缓存，只缓存图片。评论接口是 JSON，
   天然不受影响；仍保留 `/api/*` 的 `no-store` 与 EdgeOne 规则建议作为防御。
3. **EdgeOne 回源确认**：控制台显示源站类型 `IP/域名`、源站配置 `myrzg.pages.dev` →
   回源到 Cloudflare Pages，Functions 方案成立（若源站是静态存储桶则方案作废）。

## Bug 修复

- **开发环境跑不了评论（用户实际遇到）**：现象是点发表报"评论服务返回了非预期内容"。
  实测根因：`npm run dev`（Vite）**不认识 `functions/` 目录**，Pages Functions 只在
  `wrangler pages dev` 里运行，于是 Vite 把 `/api/*` 回退成 `index.html`
  （`curl` 实测返回 `200` + `text/html`），前端解析 JSON 失败。
  **这是我的疏漏**：我验证时用的是 `wrangler pages dev`，没覆盖用户日常的 `npm run dev`。
  修法：`vite.config.js` 加 `server.proxy` 把 `/api/*` 转发到 8788，并新增 `npm run dev:api`；
  浏览器始终开 5173。另在 `commentApi.js` 对 502/503/504 给出指向解决办法的提示。
- **`postComment` 静默丢弃 `avatar`**：函数参数解构还是旧的 `{ pageKey, nick, email, body, token, hp }`，
  没有 `avatar`，所以传进去的头像被丢掉——表现是"账号弹窗里选了头像，评论列表却只有首字占位"。
  靠 `page.on('request')` 打印真实请求体才定位到（请求体里确实没有 avatar 字段）。
  已修正签名，并移除已废弃的 `email` 参数。
- **蜜罐字段对用户可见**：初版只用 `left: -9999px` 移出视口，键盘 Tab 与屏幕阅读器仍会撞上那个输入框。
  改为 `visibility: hidden` + `opacity: 0` + 尺寸归零 + `padding/border` 清零，并对意外聚焦做 `blur()`。
  刻意不用 `display:none`（部分机器人只跳过它）。由浏览器验证断言"蜜罐不可见"抓出。
- **测试脚本自身的两个假失败**（非产品缺陷，但会误导判断）：
  ① "保存后账号弹窗关闭"用整页文字匹配判断，被物品详情里的文本干扰；改为按 `.account-input` 可见性判断。
  ② 头像断言曾因 `postComment` 丢字段而误报，定位后一并修正断言依据（基于元素状态而非文案）。

# 2026-10-02（下半场）讨论区

上半场只把评论挂在物品详情。下半场按用户要求扩到全站，并新增「站内讨论区」。
**接手请优先读 [项目交接说明](../../HANDOFF.md) 的「〇、最新状态」一节**，那里是给接手者的入口。

## 挂载范围

讨论区从"只挂物品详情"扩到**全部主要图鉴**：角色、魔物、家具、副本、关卡、怪物、任务、事件。

新增 `src/utils/commentApi.js` 的 `COMMENT_PAGE_PREFIX` + `buildPageKey()`：**一处维护所有前缀**，
不再让各视图手写 `hero:${id}`；服务端 `PAGE_KEY_RE` 白名单与之对应。

三个刻意的设计决定：

1. **符石与菜谱不单独挂**：其实体 ID 本身就是 `item_xxxxx`，且点卡片走的是**全局物品详情**
   （`RecipesView.handleRecipeClick` 就是 `router.push({ query: { itemId } })`），那里已有讨论区。
   再挂一份会让同一个东西出现两个讨论区。服务端也**刻意不开放** `rune:` / `recipe:` 前缀。
2. **关卡用 `stage:` 而非 `chapter:`**——讨论对象是具体关卡（含难度），不是整章。
3. **副本用 `battle:`、怪物用形态 ID**——详情都是按具体 battle / 形态打开的。

顺带修掉一个真 bug：管理页只改了账号弹窗显示 `pageLabel`，**管理端卡片漏了**，
一直显示 `hero:hero_019` 这种内部标识。

## 站内讨论区（`/#/discussions`）

顶栏聊天图标进入**独立路由**，展示网站自己的一个讨论（`site:general`），
与各图鉴页面的讨论**完全分开**、不聚合。为什么用路由：链接可分享可刷新、
滚动天然隔离、不必让 11 个视图各自接入"聊天模式"状态。

> 曾先做成"全站最新"聚合列表（混入各页面讨论），用户明确否掉：那看起来像
> "别的页面的讨论被搬过来"，他要的是一个站内讨论区。

右栏「最新讨论」同时换成**站内讨论区**的最新（`/api/recent` 只取 `site:general`），
带 30 秒边缘共享缓存。

## 交互定稿（用户逐轮验收出来的）

- **聊天式排序**：站内讨论区**最新在最下**（紧挨输入框）；图鉴详情里仍是"最新在上"的列表形态。
  服务端接口不变（仍倒序返回），由 `CommentsPanel` 的 `reverse` 在展示层反转；分页也跟着 prepend。
- **发表区固定在滚动容器之外**（用户要的"悬浮在底部"）——留在容器里消息一多就被推出视野。
  为此把发表区拆成独立组件 `CommentComposer.vue`。
- **上滑自动加载更早消息**，不设「加载更多」按钮，也不提示"往上滑动""已经是最早"（用户说没必要）。
- **正文上限 200 字**（原 1000）。前端 `maxlength` + 计数器同步；
  服务端按**原始输入**显式拒绝并说明上限——原先只靠 `sanitize()` 的 `.slice()` 会**静默截断**，
  用户写 300 字发出去只剩 200 且毫无提示。
- 右栏每条带**缩小头像**（24px）；去掉逐条的「站内讨论区」标签（冗余）；
  入口文案「进入→」；交流群与昵称同字号同字重（13px/700）。

## 三个反复踩的坑（都在注释里写明了）

1. **服务端改了就必须重启 API**：`npm run dev:api` 起的 wrangler 不会热加载 `functions/`。
   本轮在 `MAX_BODY`、`site:` 前缀白名单上各踩一次（改了没生效、以为代码错）。
2. **`scroll` 事件不冒泡，且 capture 只能捕获后代的滚动**。
   "上滑自动加载"最初把监听挂在面板自己身上（capture），而滚动容器是它的**祖先**——
   永远收不到。必须找到真正的滚动祖先挂上去；且不能只在 `onMounted` 找一次
   （那一刻列表可能还没撑出滚动高度），要用 watcher 重试绑定。
3. **prepend 必须做锚点补偿**：更早的消息插到最前面时浏览器保持 `scrollTop` 不变，
   正在看的内容会下移。加载前后测同一条锚点相对容器顶部的位置并把差值补回，
   同时用 `loading-earlier` 事件让父组件**抑制"自动滚到最新"**，否则刚补完又被拽回底部。

## 闪烁问题的处理与**遗留**

用户反馈"发表时闪一下 / 滚动条变高变短 / 底部露出输入框一角"。已定位三个成因并修掉两个半：

| 成因 | 处理 |
| --- | --- |
| 发表后 `reload()` 重拉整页 → 全部列表项销毁重建 | ✅ 改为只插一条（`addPostComment` / `addRecentComment`），仅"待审"才重拉 |
| 浏览器**滚动锚定**与"滚到最新"互相打架 | ✅ 滚动容器加 `overflow-anchor: none` + `scrollbar-gutter: stable` |
| 面板高度靠 `--vh100` 推算，与真实可用空间有偏差 | ⚠️ **改法被回退**（见下） |

第三项当时改成"用脚本量出高度"（`innerHeight - panelTop - 8` + ResizeObserver），
用户实测**高度不对**，已 `git revert` 回 CSS 固定值。
**因此"底部露出输入框一角"这类闪烁是否彻底消失，尚未确认** —— 接手者若仍能复现，
从这里继续（`docs/technical/COMMENTS_BACKEND.md` 有该节的完整分析）。
