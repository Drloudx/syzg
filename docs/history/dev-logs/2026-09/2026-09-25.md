# 2026-09-25 开发汇总

> 本日针对「词条」页面进行方案 A 全自动化百科重构，从底层配置数据查看器升级为真正面向玩家的游戏机制与状态 Wiki 百科。

## 核心痛点与方案 A 重构总结

此前词条页存在的问题：
1. **数据表与百科概念错位**：把 `buff.json` 里的 1649 条策划配置实例直接摊在前端，导致玩家看【流血】或【燃烧】看到 10~14 个杂乱的内部版本，看【穿甲箭头】变成了技能升级面板；
2. **割裂感强**：静态「名词解释」与动态「状态词条库」拆成了两张皮，查找体验不连贯；
3. **技术痕迹重**：充斥着 `配置 ID`、`机制键`、`emptyPayload`、`代码文件行号` 等逆向调试字段，阅读体验冰冷。

本次落地「方案 A（全自动化游戏 Wiki 百科）」：
- **概念模型升级**：消除双 Tab 割裂，建立【异常与状态】、【战斗属性】、【核心机制】三大知识板块，全站词条统一为标准百科 Entry 模型；
- **全自动化数据管道**：
  - 自动扫描全量 `buff.json`，根据 `STATUS_RULES` 自动匹配各状态；
  - 自动聚合计算持续时间区间（如 `3 ~ 10 秒`）、跳字结算频率（如 `每 1 秒结算一次`）、伤害元素属性；
  - 自动反查施加来源（`hero.json` / `mon.json` / `pet.json` / `item.json`），提取施加角色、怪物、魔物伙伴与道具并附带对应技能名；
  - 自动捕捉新配置的精英怪异变状态，绝不漏数据；
  - 未来游戏更新配置表，仅需运行 `npm run data:build`，所有新角色、新怪物、新技能、新数值范围全自动同步更新，零人工维护成本。
- **页面与交互重构**（`src/views/GlossaryView.vue`）：
  - 顶栏：全文搜索（支持搜词条名、描述、机制规则、施加角色/怪物名） + 一级板块 Tabs + 二级分类筛选胶囊；
  - 卡片网格：等高羊皮纸卡片，展示图标、中文名、分类 Tag、人话百科摘要、动态特征胶囊（持续时间/频率/伤害类型）、来源概览徽标；
  - 详情弹窗：展示大图、完整百科定义、【机制与结算规则】键值列表、以及【施加来源】；
  - **图鉴深度联动跳转**：在施加来源中，点击角色直接跳转角色图鉴（`/heroes?id=`），点击怪物直接跳转怪物图鉴（`/monsters?id=`），点击魔物跳转魔物图鉴（`/pets?id=`），点击道具直接打开全局物品详情。
