## 功能：首页内容可配置化（P1~P4）

首页 6 个板块（海报 / 公告 / 图鉴 / 工具 / 角色 / 底栏）从 `HomeView.vue` 硬编码搬到 D1，由后台超管维护。

完整设计见 [HOME_CONTENT.md](../../../context/technical/HOME_CONTENT.md)。

### 数据层

| 项 | 内容 |
| --- | --- |

**公告合并而非拆表**：站点（site）与官方（official）字段 90% 相同，仅 chat 频道多 `version` / `features_json` / `source_url` 三个可空列。拆分成本低（半天），故先合并。

### API

| 端点 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/home-config` | 公开 | 一次拿全 5 块；60 秒内存缓存，`?fresh=1` 绕过 |
| `GET /api/admin/home` | 超管 | 后台读全量（含停用项），不走缓存 |
| `POST/PATCH/DELETE /api/admin/home/notices` | 超管 | 公告单条 CRUD，DELETE 为软删 |
| `PUT /api/admin/home/{banners\|links\|heroes\|blocks}` | 超管 | 整组替换，`DB.batch()` 先删后插 |

**公告排序在应用层做**（`orderNotices()`）：固定项按 `slot` 插回原位、滚动项按日期倒序填空位。纯 SQL `ORDER BY tier, slot` 会把两条固定项都挤到最前，破坏「第 1 条免责 + 第 4 条社区规则」的既定布局。

**权限口径**：全部管理端点要求 `role >= 2`（超管），与「系统设置」同级。普通管理员 `role=1` 读写均 403，管理员能进后台但看不到「首页管理」入口。

## 修复：首页海报图格式不符合项目规范

`public/images/banners/` 是全项目**唯一**还用 `jpg` 的目录（其余 40+ 目录全为 `webp`）。

| 项 | 结果 |
| --- | --- |
| 原图 | 3 张 1280×720 JPEG，合计 **623 KB** |
| 处理后 | 960w / q85 WebP，合计 **370 KB（−40.6%）** |
| PSNR | 35.8~36.4 dB，并排对比肉眼无差 |
| 缩尺寸依据 | 海报区实际显示宽 552px（1920 视口），960 留足 2x 屏余量 |
| 质量依据 | 参照同类大背景图 `chapters/map_w1_c0_bg.webp`（2032×1144 / 316 KB） |
| 备份 | `backups/images-before-webp-20261101/`（SHA-256 逐文件核对） |

**工具改动位置纠正**：`convert-remaining-to-webp.mjs` 才是管 WebP 转换的脚本（原本固定无损）。给它加 `--lossy / --quality / --max-width` 三个参数，而非在 `compress-images.mjs`（管 PNG 调色板 / JPEG 重编码）里另开一套。

为什么不能用无损：JPEG 本身已是有损，转无损 WebP 要存解码后像素，体积会变大（该脚本注释里早有实测：2 个 JPEG 合计 +150 KB）。

## 审查与修复：Gemini 的 UI / 逻辑改动

对并行引入的改动（导航数据源统一、后台 confirm 换 UiModal、底栏行可点击）做了审查，发现 5 处隐患并全部修复。

### Gemini 改了什么

| 文件 | 改动 |
| --- | --- |
| `NavigationMenu.vue` | 删掉自带 `defaultNavList` 与 `CATEGORY_DEFINITIONS`，改用 `navRoutes.js` 的 `getGroupedNavRoutes()` |

| `AdminSettingsPanel.vue` | 原生 `confirm()` → `UiModal` 确认框 |
| `AdminHomePanel.vue` | 路由 combobox（可搜索）+ 底栏行 `actionType` 编辑器 |
| `HomeView.vue` | 底栏条目支持点击跳转 |

**审查通过项**：导航 21 项分 14/3/4 组全部正确、图标 0 坏图；无残留原生 `confirm`/`alert`；combobox 点外部可关、无溢出。

### 修复 1（中）：底栏可点行无法键盘操作

**问题**：`actionType` 非 `none` 时行会加 `.is-clickable` 与 `›` 箭头，但模板只有 `@click`，没有 `tabindex` / `role` / `@keydown`。
**这次是**新增的可点元素漏了与图鉴卡同一套无障碍属性**。

**修复**：补 `:role`、`:tabindex`、`:title`、`@keydown.enter.prevent`、`@keydown.space.prevent`；
把「是否可点」抽成 `isRowClickable(row)`，避免三处内联判断改漏。

### 修复 2（中）：后端不校验底栏行 `actionValue`

**问题**：`normalizeBlocks()` 原为 `JSON.stringify(blk.rows)` 整体透传。
实测 `actionType='external' + actionValue='javascript:alert(1)'` **返回 200 并存库**（对照：海报的同类请求返回 400）。

前端 `dispatchAction` 有第二道 https 校验挡着，但数据层的闸不能只靠前端 —— 导出、其他端渲染时会失去保护。

**修复**：新增 `normalizeBlockRow()` 与 `BLOCK_ACTION_TYPES` 白名单：
- 未知 `actionType` → 归一为 `none`（不报错，避免旧数据卡住保存）
- `route` 有值必须 `/` 开头
- `external` 有值必须 `https://`，拒绝 `javascript:` / `data:` / `vbscript:`
- `notice` 有值不接受协议或斜杠
- 只写入声明的 5 个字段，不透传原始对象

### 修复 3（低）：底栏点击复用了海报的 `handleBannerAction`

**问题**：`handleBlockRowAction` 直接调 `handleBannerAction(row)`，而后者的第一行是 `if (hasSwiped) return` —— 那是「刚横向滑过海报，别误触按钮」的海报专用状态。底栏离海报很远，用不到它，但会让「刚滑过海报的瞬间点底栏」被静默吞掉。

**修复**：抽出 `dispatchAction(type, value)` 承载三种行动；海报的 `handleBannerAction` 只负责「先挡 hasSwiped 再分发」，底栏直接调 `dispatchAction`。

### 修复 4（低）：`askConfirm` 并发调用泄漏 Promise

**问题**：`confirmModal.value = {...}` 是覆盖赋值。若前一个确认框未关就再次调用，前一个 `resolve` 被丢弃，`await` 它的函数**永久挂起**。

**修复**：`askConfirm` 开头先结算未完成的确认框（按「取消」处理）；`onConfirmAccept` / `onConfirmCancel` 消费后清空 `resolve`。

### 修复 5（低）：底栏行用数组索引作 `:key`

**问题**：`:key="i"` 在后台上移/下移或删除中间行时会复用错 DOM（`AdminSettingsPanel` 的注释记过这个坑：输入框焦点与内容错位）。

**修复**：改用 `rowKey(sectionKey, row, index)` = `区块:标签:名称:索引`。底栏行没有 id，这三项在单块内足以区分。
