## 客户端与配置 Bug 定位
- **料理台自由制作与食谱制作冲突 Bug 分析（`CookData.cs`、`menu.json`）**：
  - **现象定位**：游戏中 5 个通过任务/道具解锁的特定食谱（`hiddenMenu: false`）中，其余 3 个均可在料理台自由放入食材烹饪，唯独「武僧火锅」（`item_30040`）与「果香肉酱通心粉」（`item_30042`）在料理台直接放入食材时 100% 无法做出，必然降级为「山野风干肉」或「香炸酥肉」；但在食谱界面点击目标料理制作时却能成功烹饪。
  - **根因分析**：
    1. 料理台自由烹饪调用 `CookData.CheckItemToMenuData(List<CookItem> cookItems, ...)`，遍历 `menuConf`，仅当 `(menuItemConf == null || menuItemConf.level < item.Value.level)` 时更新候选菜谱；
    2. 武僧火锅（`level: 2`，需风干肉+菌菇+肉）被排在前面的山野风干肉（`item_30037`，`level: 2`，需风干肉+菌菇）完全覆盖，因 `2 < 2` 为 false 而被拦截；
    3. 果香肉酱通心粉（`level: 2`，需面粉+风干肉+浆果）中风干肉被判定为肉类（`foodType: "1"`），被排在前面的香炸酥肉（`item_30041`，`level: 2`，需面粉+肉类）完全覆盖，因 `2 < 2` 为 false 而被拦截；
    4. 食谱界面点击制作调用重载 `CheckItemToMenuData(list, selectMenuTypeId, ...)`，直接读取单一菜谱，不进行全表遍历与 level 比较，因此制作成功。
  - **文档输出**：编写技术分析报告 `docs/feedback/料理台制作与食谱逻辑冲突Bug分析.md` 并转为标准 Word 文档 `docs/feedback/料理台制作与食谱逻辑冲突Bug分析.docx`，便于提交官方修复。
