# 2026-11-02 开发汇总

## UI 与交互

### 后台搜索改为显式提交

- 公告管理、评论审核、用户管理、首页管理·公告插槽四处搜索框，全部去掉输入即查（原 300ms 防抖），改为**点「搜索」按钮或按回车才发请求**；清空输入时立即生效。
- 动机：每次按键都打 D1，`rows_read` 无谓消耗。改动只影响请求时机，结果集不变。

### 公告编辑页简化

- 删除「有新公告时自动弹窗提示」勾选框，改为只读提示（仅站点频道显示）。
- 弹窗行为改由后端按频道强制：`site` 恒定 1，`official` 恒定 0，**忽略前端传值**。

### 审计日志修复

- 目标类型从「`user` 否则显示为评论」的二元判断改为显式映射表，补齐 `notice` / `home` / `keyword` / `preset`。此前首页与公告管理的操作全部被错标成「评论」。
- 操作名称补齐 `home.*` 系列中文映射；`home.notice.delete` 归入破坏性操作（红色标记）。

### 首页公告位置编辑改「填 ID + 回显标题」

- 去掉下拉选择与候选搜索，改为直接填公告 ID（`site-1` 形式）。
- 填入后立即在本地校验并回显标题：有效显示 `✓ 标题`（绿），无效显示 `⚠ 找不到该 ID`（红 + 输入框标红）。
- 保存前统一校验，存在无效 ID 时拦下并列出具体位置。
- 留空仍走动态默认，并预测「会取到哪条」。

### 装备图鉴

- 搜索范围从 3 个字段（名称/描述/ID）扩到 6 类：新增套装名与套装效果全文、适用职业、基础属性词条、品质名、附魔说明。
- 支持多词 AND（空格分隔，需全部命中）。
- 搜索框占位文案同步更新。

### 首页速览卡

- 恢复「优先取带 `version` 的官方公告」策略。带版本号的才是版本日志，普通修复通知放上去会只剩标题没有要点。

### 图鉴类页面左右平齐

- 筛选后内容较少时，正文面板底边与左右两栏齐平。修复前实测缺口：魔物 591px、怪物 586px、物品 559px、角色 371px。
- 规则集中在 `App.vue` 的桌面端媒体查询内（`.app-main :deep(.page-view-container > [data-main-scroll]) { flex: 1 0 auto }`），6 个图鉴页共用，不逐页写。

### 搜索框占位文案

- 装备图鉴：`搜索名称、套装效果、属性、职业…`（去掉括号说明）。
- 角色图鉴：`搜索角色、技能、档案、互动文本…（空格=“且”，、=“或”）`。原文案「支持中英文/数字；空格=且、=或」两项均与实现不符：`=` 并非运算符，且「中英文/数字」是对内部拼接字段（如 `5星 5 star rarity`）的含糊描述。

## 数据与解析

### 货运站页面（`/freight`）

新增 `scripts/parse/freight.mjs` → `parsed/freight.json`（26 KB），并在 `scripts/parse/index.mjs` 注册。数据取 `market.json`（51 件货品）、`newOrder.json`（40 个订单）、`item.json`、`homeLevel.json` 的 `carriage`、`playerAbilityInit.json`、`reward.json` 的 `carriage01`。

新增 `scripts/dev/import-freight-atlas.mjs`，导入 53 张图到 `public/images/FreightPanel_Atlas/`（15 图集精灵 + 4 独立大图 + 34 NPC 立绘），无损 WebP，2995.1 KB → 1844.3 KB（−38.4%）。图集精灵与 `_atlas.png` 按矩形裁剪结果逐像素核对，不通过即报错。

三条口径来自源码而非配置：
- 价格档位 `FreightMarketItemTemp.cs:51-99`，`step = (1.4 − 0.6) / 5 = 0.16`，严格大于阈值才升级。
- 订单报酬 `FreightOrderItemTemp.cs:90`，`(int)(Σ(sellPrice × num) × orderValue + baseValue)`，40 条实测 447 ~ 1393。
- 等级加成 `CampResearchData.RefreshPlayerAbilityInitData` 逐级累加，Lv3 的 `orderWeight` 是 15（表里写 10），加基础 20 得满级 35。

**网页不显示实时价**：`priceScale` 由服务端下发，配置表无此字段。页面按 A 口径给「基础价 × 档位阈值」的区间与该档代表价，不编造当前价、不按 `priceRandomArea` 随机生成。

`order-card` 的台词条改用 `cart_order_say` 九宫格 `border-image`：该精灵是深色底，整图拉伸会把下尖角横向扯宽，且文字必须用浅色 `#f4e6c8` 才读得出。

新增 `tests/unit/freight.test.mjs` 8 条，守档位边界（等于阈值仍留在低一档）、区间换算、报酬公式、等级累加与标量配置。

**市场卡片按游戏原版重排**（同日修订）：
- 卡片改成两行网格：行 1 = 图标 + 名称/徽章/主价签/库存，行 2 = 5 档对照跨满整卡宽度、落在图标下方。行高 fr auto 让第二行贴底，否则同排两卡「有无库存行」会让档位对比错开约 20px。
- 名称行改为「名称 + 品质徽章 + 买入/卖出徽章」同排，三枚都用 UiTag 的 adge-N（同套品质色边框）；删掉正文里旧的 meta 行。
- 筛选文案：只看基价→基价，可买入/可卖出→买入/卖出。
- 中途误删过 5 档对照块，已恢复（用户明确要保留）。
- 买入 / 卖出徽章改回 UiTag 默认灰，只有品质徽章用品质色；主价签旁「可能」改为「价格范围」。
- 5 档数值口径写进测试：`round(基价 × (下界 + 上界) / 2)` 是该档区间中值，不是当前价。以金铃草（基价 300）为基准钉住 396 / 348 / 300 / 252 / 204 与各自区间。
- 档位筛选收回到市场：订单页那行是自造的，游戏里没有。查证：`FreightOrderItemTemp.cs` 无 `priceBg` / `priceType`，报酬是 `moneyLabel` 一个纯数字；`priceType` 只出现在 `FreightMarketItemTemp.cs` 与 `ItemOrderTip.cs`。顺带删掉 `orderTierOf` / `orderRewardBounds`。
- 档位选中态调淡：底色 0.07→0.09，去掉 inset 描边，只靠档位名变强调色区分。
- 主价签改用 `cart_price_*` 整条精灵（64×28，箭头已画在图里），内放银币 `item_00001` + 数字，九宫格 `border-width: 0 24px 0 8px`。踩过的坑：写 `border: 24px` 会真的占掉上下各 24px，把内容盒压成 0，所以上下必须显式 0。
- 5 档对照不再重复价签：卡片正文约 290px，5 条价签每条不足 55px（箭头 24 + 银币 17）必然压字，改成文字 + 小箭头。
- 库存与补货改回卡片底部一行小字，且**只在 `buyIn = true` 时显示**。依据 `FreightMarketItemTemp.Init(typeId, num, haveNum, isBuy)` 的 `haveNum` 只在买入列表有意义，源码对 `isBuy && !buyIn` 直接置遮罩。51 件里 20 件不可买入，此前给它们标库存是编的。

- 公告正文统一为 HTML。迁移 6 条旧标记文本（`**粗**` / `{red}字{/red}` / `- 列表` → 对应 HTML 标签），已迁移的跳过，重复执行幂等。
- 修复 `home_links` 中 `core` 段位 1（角色图鉴）的描述：原文含字面 `\n` 与真实换行，修正为单行。
- 海报 `home-banner-4/5` 由 PNG 转 WebP：950 KB → 80 KB、774 KB → 70 KB（−92% / −91%），数据库 `image_url` 同步改扩展名。原图备份在 `backups/images-before-webp-20261102/`，SHA-256 已核对。
