## 抽卡记录分析方案勘察（未实施）

新增 [GACHA_RECORD_ANALYSIS.md](../../../context/technical/GACHA_RECORD_ANALYSIS.md)，记录「纯官方端用户如何获取抽卡记录」的勘察结论。仅文档，无代码。

### 核心结论

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 手机端无 root 能取数吗 | 不能 | TCP + protobuf，客户端不落盘 |
| 模拟器能吗 | 能 | Frida Hook / TCP 透明代理 |
| 有设备绑定吗 | 没有 | 登录仅发 `token`，无 deviceId |
| 有反外挂吗 | 没有 | 7 个程序集无任何反作弊模块 |
| 最大风险 | 模拟器本身 | 客户端无模拟器检测代码 |

### 为什么原神能断网查而本游戏不能

| 项 | 原神 | 本游戏 |
| --- | --- | --- |
| 记录页 | WebView + H5 | 原生 Unity UI（`HeroPoolTips.cs`） |
| 协议 | HTTP(S) | 裸 TCP + protobuf（`ReciveFilter.cs`） |
| 断网表现 | 暴露请求 URL | 只提示连接失败 |
| 是否落盘 | 接口可复现 | 内存 `cacheData`，关页即丢 |

### 协议事实

- 分帧：`int32 长度前缀 + N 字节 Protobuf`
- `ProtocolPacket` 8 字段：`Signature(1)` / `RouterType(2)` / `ServerPushType(3)` / `MessageSeqNum(4)` / `Code(5)` / `Desc(6)` / `ServerTime(7)` / `BodyData(8)`
- 签名：Ed25519，私钥硬编码在客户端（`SignUtil.cs`）
- 抽卡记录路由：`441` queryPageParams、`442` queryPageData
- 记录字段：`id` / `typeId` / `poolId` / `crateAt`

### 澄清一处先前的误判

先前认为 `SAVE.gameRecords` 在客户端 `userSave` 里，实际不是：
- `SAVE` 是单机化工程 `game_server.js` 的内存对象，写服务端自己的文件
- 官方客户端存档 `persistentDataPath/save/userSave` 存的是 `ClientSaveData`，**无抽卡记录字段**（`ClientSaveData.cs` 全字段核对）
- 抽卡记录**只在服务端**
