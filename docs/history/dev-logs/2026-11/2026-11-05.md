## 神匠之塔 / 怪物详情弹层审计与修复（同日第二轮）

审计范围：`/tower` 与副本、关卡、日常三页的怪物图鉴。逐项实测定位（Vite dev + Chrome，桌面 1440×900 / 移动 390×844 / 1024 断点，CDP 取堆与节点数）。

### P0 — `/tower` 桌面端只渲染前 24 层

- **根因**：`App.vue` 在 ≥1025px 把 `[data-main-scroll]` 强制 `overflow-y: visible`，滚动由 `.app-container` 承担；而 `TowerView` 的 `@scroll` 挂在 `#towerScroll`（永不产生事件）、`IntersectionObserver` 又把 `#towerScroll` 当 `root`。该元素高度等于内容高度，哨兵相对它恒定可见 → 只在首次回调一次 `true`。
- **实测**：走查 IO 只触发 2 次；卡片数停在 24，滚轮 60 次、`scrollIntoView`、窗口缩放均无变化；同视口降到 1024（内部可滚）则 12→80 正常。
- **连带**：`首领关卡 (16层)` 只出 12 张、`61 - 80` 只出 12 张，计数徽章却写 16 / 20。
- **修复**：`root: null`（视口）；滚动改挂 `window` 捕获阶段（与 `useLazyList` 同构）；`loadNextBatch()` 加一次 `requestAnimationFrame` 自检，防止单批不足以把哨兵推出阈值时又停住。
- **复测**：12 → 36 → 60 → 80，哨兵随之移除；筛选 16/16、20/20 与计数器一致。

### P1 — `/monsters` 挂了两份 `MonsterDetailModal`

- `MonstersView` 保留自有实例，`App.vue` 又有全局实例，两边同时可见。
- **实测**：2 个重叠 overlay（z 均 2000，内层 `visibility: hidden`）、2 个重复 `#monsterModalScroll`、2 个可见 `.ui-back-to-top` 且 rect 重合、`/api/comments?page=monster:010` 请求 **2 次**。
- **修复**：移除页面内实例与其 `isModalVisible`，改由 URL `?id=` 驱动全局实例。
- **复测**：overlay 1、滚动面板 1、重复 id 0、评论请求 1 次。

### P1 — crazy 变体详情弹窗只剩讨论区

- **根因**：`loadMonster()` 用 `monsters.json` 的**原始下标**当 `currentFormIndex`，而渲染用 `allForms`（去重后）。去重规则会剔除「属性/技能数/阶级与本体全同」的克隆体，`007crazy`/`008crazy`/`009crazy`/`037crazy`（只多一个 `monCrazy_s` 狂暴 buff）正好在 2 号位被剔，`currentForm` 变 undefined。
- **实测**：日常计划「药草山林」14 个胶囊里 6 个点开空白，只剩「还没有人讨论」；`/monsters?id=007crazy` 同样空白。
- **影响面**：被剔形态在 `daily.json` 被引用 9 次、`dungeons/*` 20 次、`stages/*` 123 次。
- **修复**：抽出 `resolveForms(entry, forceId)`，`forceId` 命中的形态**强制保留**；`loadMonster` 改为按形态 id 在 `allForms` 里定位，不再用原始下标。默认（无 `forceId`）去重行为不变。
- **复测**：5 个 crazy 变体全部有属性与技能；日常 10/10 胶囊正常。

### P2 — 硬编码与取数口径

- **首通奖励曾是字面量**：`isBoss ? 150 : 50` / `isBoss ? 20 : 5`。改为逐层读 `onceReward.ke` 与 `reward` 里兑换货币规则的 `min`。产物数值不变（5600 / 640），但已与表联动。
- **前端硬编码**：`80` 层、`5600`/`640` 兜底、`15 理智`、`item_25002`/`item_00002` 图标路径、`首领关卡 (16层)`、四个 `1-20` 之类的分段——全部改由 `summary` 输出或现算。新增 `tiCostPerLayer`（各层众数）、`totalTiCost`、`tiItemTypeId`/`exchangeItemTypeId`/`keItemTypeId` 及三个 `*Icon`。

- 构成：波次头像 707、立绘 80、两只奖励图标 160、理智图标 80。

### 滚动抖动

- `contain-intrinsic-size: 0 170px` 只有实测卡高（273~337px）的一半，离屏卡片按 170px 占位、滚到跟前重算 → `scrollHeight` 单次最大跳 **453px**。
- 改为 `0 300px` 后实测跳变 **0px**；20 步滚动布局耗时 34ms，本身不卡。

### 窗口化（方案 A）

分批 `slice` + 哨兵是**只增不减**的：滚到底 80 张卡与 787 个 `<img>` 全留在 DOM，离屏仍有 735 张解码（约 14.3 MB 位图）。`loading="lazy"` 覆盖 787/787、网络层面确实只按需下载（距视口 20000px 外已解码数为 0），所以瓶颈在元素与解码，不在请求。

改为 `UiVirtualGrid`（`@tanstack/vue-virtual`，关卡图鉴/任务图鉴/物品图鉴同款）：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 卡片元素 | 80 | **15**（视口内 + overscan） |
| `<img>` | 787 | **158** |
| DOM 节点 | 13350 | **1787** |
| 滚完全程后 | 仍 80 卡 / 787 img | 仍 15 卡 / 160 img |
| 离屏已解码图 | 735 | 129（回顶后 155） |

- `estimate-size` 取 310：实测单列 80 张只有 7 种高度（263~337，中位 305，最常见 337×25）。
- 删掉按卡片的 `content-visibility` / `contain-intrinsic-size`：窗口化靠 `measureElement` 量真实高度排队列，该属性会让离屏元素按估值占位、量到的不是卡高。
- 深链改为 `gridRef.scrollToItem(index)`，两处坑：
  - 传的是**数组索引**不是层号（直传会整体错位一层；`?layer=80` 超出返回 -1 完全不滚）；
  - 必须在 `loading=false` 且 `v-else` 渲染后两拍再调，否则组件尚未挂载、`gridRef` 为 null 被静默跳过；
  - 站内改 hash 时 `items` 未变、组件不重挂，需 `watch(() => route.query.layer)`。
- **复测**：三种视口下 `?layer=80` 均 `is-targeted` 且与视口相交 54%~71%（1440/1024/390）；滚动位置随层号单调推进；点立绘开怪物详情正常；筛选 16/16、20/20 与计数器一致。

### 窗口化上线后回归：布局被压成细条

首版窗口化只用 DOM 计数验证（cards=15、imgs=158 都「正常」），**没有看渲染结果**，上线后整页只剩卡片表头：

- **根因**：`UiVirtualGrid` 从 `getComputedStyle(.ui-card-grid).gridTemplateColumns` 数出列数，再以**内联 style** 写到每行 `.ui-virtual-grid__row`。我把 `grid-template-columns` 写在了「行」上 —— 内联样式永远赢，于是落回 `UiCardGrid` 默认的 `minmax(120px, 1fr)`：1440 宽被分成 **5 列 × 136px**，塔卡挤成细条、内容竖排到 **2201px** 高（实测 `cardRect.w=136 / h=2201`），一屏只看得见表头。
- **修复**：列模板改写到 `.tower-scroll-container :deep(.ui-card-grid)`，`minmax(460px, 1fr)`、`gap: 14px`。复测 1440 单列 738×337、1024 双列 481×502、390 单列 342×652，卡内文本 245 字完整。
- **同时修掉**：塔卡缺 `user-select: none`，移动端手指拖动滚动会选中文字、整块变蓝并盖住立绘（截图里立绘显示为蓝方块）。补 `user-select/webkit-user-select: none` 后拖动选中长度 0。
- **护栏**：`tests/unit/tower-and-monster-forms.test.mjs` 增一条源码断言 —— 列模板必须在 `:deep(.ui-card-grid)`、不得写在 `:deep(.ui-virtual-grid__row)`、最小列宽 ≥ 460px。单测 441 → **442**。

> 教训：性能类改动不能只数元素。DOM 计数正确不等于布局正确，必须看几何尺寸（宽/高/列数）与截图。
