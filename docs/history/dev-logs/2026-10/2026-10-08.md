## 桌面端吸顶裁切：从「文档只写一句」到「三层防护」

用户反馈「新建带滚动页面的图鉴时，正文总会从筛选框上面滚出去」，且「以前写过、更新时又遇到」。
根因不是 bug，是**这条约定只在开发日志和代码注释里，规范里没有** → 每次重新踩。

### 机制（实测确认，非推断）

桌面端（≥1025px）滚动发生在整个 `.app-container`（`App.vue` 的 `overflow-y: auto`），
正文容器 `[data-main-scroll]` 被强制 `overflow-y: visible`。正文上滑经过吸顶筛选框区域时，
必须按筛选框底边裁掉，否则内容会盖到筛选框上方。

- 裁切量 = 筛选框底边 − 内容容器顶边 → 写入 `--sticky-clip-top` → 由 `clip-path: inset(... 0 0)` 消费。
- 1440×900 滚 300px 实测：`/items` 筛选框 bottom 235、容器 top −53 → **288px**，与公式一致。
- **失败静默**：不报错、不抛异常，只是内容跑到筛选框上方。

### 实施（三层防护）

**① 显式标记，不再靠 class 猜名**（`UiFilterPanel.vue` + `App.vue`）

- `UiFilterPanel` 根元素加 `data-sticky-filter`，并写明「这是约定标记、删了会静默失效」。
- `App.vue` 的 `updateStickyClipping()` 选择器由
  `:scope > .filter-panel, :scope > .filter-sticky-bar, :scope > [class*="-filter-panel"]`
  改为 **`:scope > [data-sticky-filter]`** —— class 名从此可自由追加（`dungeon-filter-panel`、`pet-filter-sticky` 等都不再参与匹配，改名不会漏）。

**② 开发期不静默**（`App.vue` 新增 `warnStickyClipping()`）

- 每次路由变化体检：页面有 `[data-main-scroll]` 内容容器、却没有直接子级的 `[data-sticky-filter]` → `console.warn('[sticky-clip] …')`，附修法。
- 仅 `import.meta.env.DEV` 生效，生产静默。
- **反向验证**：注入一个「有内容容器、无筛选框标记」的假页面 → 警告如期输出；正常页面 0 噪音。

**③ 回归护栏**（新增 `tests/ui/sticky-clip.spec.js`，20 条）

- 覆盖 19 个带筛选框的路由 + 1 个豁免路由，断言**实际写入值 == 期望值（筛选框底边 − 容器顶边）**，容差 1px。
- 用「实测 = 期望」而非写死像素：同时抓「根本没写」「写错容器」「基线取错元素」三类问题。
- 豁免走白名单（当前仅 `/partner-mails`），并要求豁免前提**每轮都成立**（`is-mail-reader` 布局 + 外层 `overflow: hidden` + 无页面级滚动容器）；前提变化即报错，避免豁免悄悄过期。
- 实测 **20/20 通过**，exit 0。

- 用户两次指出「实际所有页面都正常」，我此前两轮分析**都错了**：① 误以为「筛选框必须是直接子级」是硬约束（当时未注意查内容用的是任意深度的 `querySelectorAll`，且 `<template>` 不是 DOM 节点）；② 靠读代码推断而未实测。本轮改为**先跑浏览器量真实计算值**再下结论。

### 1. 🔴 黑名单字段名写错 —— 照做会被静默忽略

原文：

> 按地区名匹配必须传 **`mapName`**（`黑森林`）而不是 `chapter` 代号（`c4`）

实测（`isBlacklisted` 传「黑森林」）：

| 字段名 | 是否触发隐藏 |
| --- | --- |
| `name` / `desc` / `tip` / `source` / `label` / `keywords` | ✅ |
| `category[]` / `categories[]` / `place[]` / `mark[]`（**数组**） | ✅ |
| **`mapName`** | ❌ **不触发** |
| `region` / `chapter` / `map` | ❌ 不触发 |

**`mapName` 不在 `isBlacklisted` 读取的字段清单里**（清单见 `blacklist.js` 的 `parts` 拼装）。

原文的**本意是对的**，但表述把**字段名**和**值来源**混了：现有代码写的是
`label: d.mapName` —— 把 `mapName` 这个**值**塞进 `label` 这个**被读的字段**。
照字面理解写成 `mapName: ...` 就完全失效（**代码看着改了、行为没变**）。

另补一条实测：数组字段**必须传数组** —— `place: '黑森林'`（字符串）会被
`...item.place` 按字符展开成 `黑 森 林`，反而匹配不到。
