## 审查与修复（UI 线提交后复核）

对 UI 线上述 4 个提交（`ab078563` / `48cdd7b3` / `a24c4145` / `9a0bdeca`）做了功能、性能与额度的复核，结论与处置：

### 〇、用户指认的布局与入口调整（2026-10-14）

- **评论审核表格：正文限宽 + 操作三按钮横排**。根因是正文列不设 `width`、吃掉全部余量，操作列被压到装不下「放行/隐藏/彻底删除」三个按钮 → 逐行换行。处置：正文 `.admin-comment-body` 加 `max-width`，操作列 `140 → 210px`，并补 `flex-wrap: nowrap` / `white-space: nowrap` / `flex-shrink: 0`。
- **用户表格：`注册 / 最近登录` 改为只留 `最近登录`**。注册时间与右侧档案的「注册时间」重复，表格再列一遍是冗余且占宽。
- **顺手修掉两个同类缺陷（中文字段换行）**：
  - 用户表格操作列在桌面端**逐字换行**（「封/禁」「删/除」）—— `white-space: nowrap` 原先**只写在手机端 `@media` 里**，桌面端完全没有。而这些操作是 `<span>`，中文可在任意处断行。
  - 角色列「超级管理员」折成「超级管理/员」—— 同一原因，`.role-badge` 缺 `nowrap`。
  - 判据：**英文单词默认不断行、中文才会**，所以这类缺陷只在中文字段上出现，且要改窗口宽度才暴露。
- **回首页入口收敛**：删掉顶栏「前台」文字链（与「退出」完全同效，都 `router.replace('/')`）、删掉侧栏底部「前往首页」（与新入口重复）；「回首页」语义搬到**顶部品牌区**（`div` + `role=link` + `tabindex=0`，键盘可达）。前台 `App.vue` 的**标题区**同样加点击回首页，且已在首页时不重复 `router.push`（避免重置滚动）。
- 新增两条常驻用例：`🔴 回首页入口：品牌区可点，重复入口已收掉`（后台，守"重复入口不许回来"）、`前台顶部标题区可点击回首页`。

### 一、改版打挂既有后台用例（52 条）

### 四、概览统计加模块级缓存（2026-10-14）

- 用户确认「待审滞后可接受」，且指出**不该拿当前数据量当依据** —— 内测期没评论是必然状态，应按长期设计。据此给概览加缓存。
- 关键认知：**索引救不了概览**。它的 9 条聚合里 7 条是「计数一遍」，索引本质无法降低 `COUNT(*)` / `GROUP BY` 的读行数（实测加索引后仅降 8%）。要降只能**缓存**或**预计算**。
- 实现 `src/config/adminStatsCache.js`：模块级 30 秒 TTL，与 `getReviewMatcher` 同范式（TTL + in-flight 合并 + 失败不落缓存 + 测试钩子）。
- **9 个写路径主动失效**：评论改状态/彻底删评论/封禁解封/彻底删用户/改角色/发表评论/自删评论/注册/注销。理由：滞后可接受，但「处理完待审回概览看到旧数字」会被当成操作失败。
- **踩到的坑（已修）**：`computeAdminStats` 原返回 `json(...)` 的 `Response`，而 Response body 只能读一次 → 缓存后第二次返回 500。改成返回**纯数据对象**，序列化交给路由层。这个坑是端到端验证抓出来的，单测（5 条）没覆盖到 —— 因为单测的 `compute` 返回普通对象，绕开了真实的序列化形态。
- **另一个坑（判据选错）**：验证失效时最初拿 `ts` 做判据，但 `ts` 是 `nowSec()` **秒级**，读写落在同一秒时值相同 → 误判「没失效」。改用 `total`（内容，不受时间分辨率影响）。

### 五、去掉档位条数 + TTL 提到 5 分钟（2026-10-14）

**用户决策**：把四个档位胶囊上的条数去掉，TTL 改 5 分钟。

- **去掉档位条数**：那条 `GROUP BY status` 占单页成本 **91%~99%**，且**每翻一页都跑**（而各组行数翻页时不变），并随评论量线性增长（实测 10 倍表 → 8.38x）。评论 2.5 万条时每天翻 200 页就能吃满额度。而档位不需要预先知道条数 —— 点进去自然看到有多少条。
  - 一并删掉游标模式（旧路径）的 `pendingCount`，否则"每页多一条 COUNT"会原地复活。
  - 前端 `statusCounts` / `pendingCount` 两个 ref 无消费者后也删除。
  - 效果：第 2 页起约 **50 行/页**（原 ~3,698），降 **98.6%**，且不再随库规模增长。
- **TTL 30 秒 → 5 分钟**：30 秒**几乎无效** —— 判据是"同一段操作内的查看间隔是否小于 TTL"，而管理员真实节奏一轮约 4 分钟 > 30 秒，故每次都过期重算。实测（3 管理员 × 3 工作段 × 每段 5 次）：30 秒重算 45 次（占额度 23.2%）、5 分钟重算 9 次（4.6%）。取 30 分钟无额外收益，却把滞后拉长 6 倍。
- **跨日强制重算**（让长 TTL 无代价的前提）：概览的「今日/昨日/7 日趋势」基于 UTC 日界线（= 北京时间 08:00）。缓存里记下"算它时的 `dayStart`"，请求时若已跨日则强制重算 → **跨日零滞后**。
- **补上登录的失效**：`authLogin` 新建会话会影响「活跃会话数 / 今日 DAU」，此前漏了。30 秒 TTL 时几乎看不见，5 分钟后会显形。

### 六、管理后台两处修复 + 分页显示总数 + 本地清库（2026-10-14）

- **修「点用户行屏幕变灰」（两轮才修对）**：
  - 现象：桌面端在用户列表点任意一行，整个后台被一层黑色半透明遮罩盖住。

### 九、深色模式两处位移缺陷（2026-10-14）

Gemini 完成深色适配后，用户反馈「切深色后页面向下向右移动」「物品卡那里的也会上移」。两处**根因不同**，但都出在 Vue scoped 样式的写法上。

#### 缺陷 1：整页右下位移（宽 +10px、高 +6px）

- **现象**：切深色后 `html` 被加上 `padding: 2px 4px` + `border: 1px` → 根元素宽 1440→1450、高 900→906，`body`/`.app-container` 被推 5px / 3px。
- **根因**：`dark-mode` 类加在 **`html`** 上（`useNativeShell.js` 的 `document.documentElement.classList.toggle('dark-mode')`），**不在组件元素上**。而多个组件写了 `:global(.dark-mode) .xxx`，Vue scoped 把**括号之后的部分丢掉**，编译成两条并列选择器：
  ```
  .dark-mode, .dark-theme, .dark-mode .ui-item-card__name[data-v-7058cf59] { … }
  ↑↑↑ 凭空多出的裸 .dark-mode
  ```
  裸 `.dark-mode` + `!important` → 命中任何带该类的元素（`html`、`.app-container`）→ 整页位移。
- **定位方法**（值得复用）：`git stash` 逐条排除不奏效（多个组件互相掩盖），改用**扫描编译后的 CSSOM** —— 遍历 `document.styleSheets`，找出「选择器解析后含裸 `.dark-mode` / `.dark-theme`」且「带布局属性」的规则。共 3 条：`UiItemCard`、`UiTag`、`UiSection`、`RewardPools`。
- **修法**：`:global(.dark-mode) X` → 普通 `.dark-mode X`（scoped 会编译成带 `[data-v-*]` 的后代选择器，`.dark-mode` 那截保持裸选择器用于匹配祖先 —— 这正是想要的）。13 个文件、共 112 处。
- ⚠️ `AdminView.vue` 的 3 处 `:global(.dark-mode .admin-shell ::-webkit-scrollbar-track)` 是**正确用法**（整个选择器都在括号内），不动。
- **验证**：修后编译产物里裸 `.dark-mode` 规则 **0 条**；`html` / `body` / `.app-container` / `.app-header` 的 `x/y/w/h` 全部不变。

#### 缺陷 2：物品卡网格上移 4px

- **现象**：物品网格整体上移（实测第二行 y: 372 → 368）。
- **根因**：另一类问题 —— 选择器写对了，但**深色规则改了盒模型**。卡名浅色是 `border: 4px solid transparent` + `border-image`（九宫格木框）与 `padding: 1px 2px`；深色写成 `border: 1px` + `padding: 2px 4px` → 净高 −4px → 卡片 115→111px → 网格行高变小、整片上移。
- **修法**：**保持 `4px` 边框 + `1px 2px` 内边距**，只把木框图换成深色底。
- ⚠️ **中途一次错误尝试**：为了"不占布局的细描边"改用 `box-shadow: inset 0 0 0 1px`，结果在圆角上画出一圈生硬方框、紧贴文字显得多余（用户反馈「怎么多一个边框」）。**已撤回** —— 深底 + 暖白字对比度足够，不需要额外描边。
- 同类修正：`RewardPools` 的 `.reward-slot__box` 深色原写 `border-width: 1.5px`，而基线是 `2px` → 盒子变小。**改回 2px**（我第一版误判成"该与 1px 一致"，实为 2px，已纠正）。

#### 新增回归用例

`tests/ui/dark-mode-layout.spec.js`，6 条，两类判据：
1. **几何不变**：切深色前后 `html`/`body`/`.app-container`/`.app-header` 的 `x/y/w/h` 一字不差；`html` 的 `padding` 必须为 `0px`、`border-width` 为 `0`。
2. **盒模型不变**：全页每个元素的 `border-*width` 与 `padding` 一字不差（不含颜色）—— 覆盖物品页/角色页/符石页/怪物收益。

**为什么必须用几何断言**：这类缺陷只在深色下、只在切主题那一瞬间可见，静态读代码看不出来。
