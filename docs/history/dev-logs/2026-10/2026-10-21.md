### 为什么 Cloudflare 和 EdgeOne 两边都有（回答了本次的疑问）

不是二选一，是**串联两层**：

```
用户 → DNSPod 指到 EdgeOne（大陆加速）→ 回源 syzg.pages.dev（CF 源站）
     → CF 按「自定义域」认 Host，交给 Pages 项目 syzg
```

- **CF 面板里的「自定义域」= 源站绑定**：只用于回源时认 Host，不是给用户解析用的。
- **用户头一跳是 EdgeOne**：DNS 在 DNSPod，绕过了 CF 的 DNS。

实测判据（`curl -I https://syzg.yxzmy.top/`）响应头**同时**出现：

| 头 | 来源 |
| --- | --- |
| `EO-LOG-UUID`、`EO-Cache-Status: MISS` | EdgeOne |
| `CF-RAY`、`Server: cloudflare` | Cloudflare |

只看到一组 = 链路少一环。这条判据已写进 RUNBOOK §7.1。

## 途中排掉一个非本项目的构建阻塞

改完域名后 `npm run verify` 报 `build` 失败，106 条错误全是：

```
Failed to load PostCSS config (searchPath: .../vue-myrzg): [SyntaxError] Unexpected end of JSON input
```

### 排查过程（值得记下来）

| 步骤 | 结论 |
| --- | --- |
| `git stash` 回退本次改动再构建 | **同样失败** → 与域名改动无关 |
| 删掉 `vite.config.js` 构建 | 仍然失败 → 与项目配置无关 |
| 最小复现（临时目录 + Vite 8.2.2） | **成功** → 不是 Vite 8 的通用 bug |
| 读 Vite 源码 `getDefaultSearchPlaces()` | 搜索列表第一项是 `package.json`，且 `noExt: jsonLoader` 会对无扩展名文件做 `JSON.parse` |
| 逐个检查项目内候选路径 | `package.json` 合法（2379 字节），项目内**没有任何 postcss 配置文件** |
| 检查上级目录 | **`E:\Desktop\html\package.json` 是 0 字节空文件** |

根因：cosmiconfig 会**向上级目录搜索**，命中 `E:\Desktop\html\package.json`（0 字节），
`JSON.parse('')` 抛 `Unexpected end of JSON input`，Vite 把它包装成 `Failed to load PostCSS config`。

### 处理

那个空文件创建于 2026-10-20 12:03，位于 `E:\Desktop\html` 根，会污染该目录下**所有**含
`package.json` 的子项目（如 `_pristine_web`）。

- 先备份为 `package.json.empty-backup-20261021-000050`（0 字节，可核对）
- 再删除
- 复验：`npx vite build` **exit 0，`✓ built in 7.39s`**

> 这个坑不在仓库里，`git status` 看不到，只能靠「向上搜索」这个行为去推断。
> 已把「构建报 PostCSS 配置解析失败」记进排查路径，下次直接查上级目录。
