## Bug 修复

### 词条「施加角色」chip 点击无反应

- 现象：词条详情「施加角色」里点「阿迪拉」「格薇勒」「艾茵」「米托拉（旧）」，页面**毫无反应**，既不跳转也不报错。
- 根因：这 4 个角色在原表 `hero.json` 中 `hide: true`，`heroParser` L111 `if (h.hide === true) return null` 因此不进 `parsed/heroes.json`；而 `buildBuffSourceIndex` 反查来源时**不看 `hide`**，仍把它们的技能挂进 `sources.heroes`。前端 `navigateToHero` 推 `?id=hero_047`，`HeroesView.openFromQueryId` 找不到就静默返回。
- 定性依据：`hide` 不是脏数据。源码 `PicHandBookPanel.cs:375` 用 `!x.Value.hide` 过滤图鉴，游戏内同样不显示；但这 4 个角色有完整技能（阿迪拉 8 个技能全在 `skill.json`/`skillTrigger.json`）与大量剧情文件（`adila_c2_*`、`gewelle_c1_*`、`fav_hero_047_*`），技能**确实会施加状态**。
- 修法：**在构建期按三张图鉴的可见 id 过滤来源**（不是前端标注）。
  - `scripts/parse/glossary.mjs` 从同一次构建的 `heroes` / `pets` / `monsters` 产物取可见 id 集合，传 `visibleHeroIds` / `visiblePetIds` / `visibleMonsterIds`。
  - `glossaryData.buildGlossaryData` 透传；`buffSourceIndex.buildBuffSourceIndex` 在三条反查路径（`buffType` 前缀、技能反查、怪物 `forms`）各加一道可见性判断。
  - `scripts/parse/index.mjs` 把 `heroData` / `petData` 传给 `buildGlossaryFile`（jobs 顺序已保证这三者先于 glossary）。
  - 前端 `GlossaryView` 的 `hidden` 标注、`disabled`、虚线样式与 `navigateToHero` 早退**全部撤除** —— 来源里已不存在不可点的条目。
- 为什么不运行时过滤：词条页只加载 `glossary.json`（146 KB）；运行时过滤需额外拉 `heroes.json` 1959 KB + `monsters.json` 527 KB + `pets.json` 140 KB ≈ **2.6 MB**。构建期过滤零额外开销。
- 为什么不补进图鉴：5 个 `hide` 角色全部无 `heroStar` / `heroLevel` / `heroRank` 数据，补进去详情页是空壳，且与游戏内图鉴口径不一致。
- 影响面：角色来源 chip **86 → 76**（去掉阿迪拉 4、格薇勒 2、艾茵 2、米托拉（旧）2）；魔物 61、怪物 113 断链均为 0；词条总数仍 **58**（无词条丢失）；`glossary.json` **150 → 146 KB**。
- 兜底：`visibleXxxIds` 不传时退回不过滤（单元测试只喂原表时不会被清空），防「漏传导致来源全没」。
- `hero_053_c4`（艾薇杜尔 `hide`）无独立 buff 归属，不产生 chip；`hero_002` 与 `new_hero_002` 技能表不同（`00201`–`00208` vs `new00201`–`new00208`），**未按同名合并**。

## 重构与维护

### 触发粒度排查（buff detectType 在多段伤害下的次数）

- 起因：核对「梅莉莉一次技能投多把飞刀，能否多次触发利齿恐兽的『连击技巧』」。答案是**能**，且一次技能就叠满 10 层。
- 方法：把 `BuffDetectType` 全部 77 个枚举值按 `CheckDoBuff(...)` 调用点归到宿主函数，得出唯一判据 —— **触发点写在哪个函数里**，不是看名字。
- 四类粒度：
  - **动作级**（`Unit.cs:2450-2462` 的 `PlaySkill`、`SkillBase.cs:374` 的 `SkillConsume`）：`normalAtk`、`doSkill`、`spSkill`、`atkAndDoSkill`、`atkTm`、`skillConsume`、`doSkillCheckFri`。一次普攻/技能动作只触发一次，与刀数、目标数无关。
  - **每段伤害级**（`CombatPanel.cs:5727-6022` 的 `CalculateMaster`）：`normalAtkDam`(L5747)、`skillAtkDam`(L5811)、`normalAtkAddNewDam`(L5994)、`beHit`(L5946)、`damCrit`(L6004)、`atkDamElement`(L5918)、`atk`(L5758)、`skillAtk`(L5963) 等 40 项。每把刀、每段伤害各判一次。
  - **周期级**（`BuffControl.cs:29-35` 的 `Update`）：`spTime`，纯时间驱动。
  - **事件级**：`everyReply`（`CombatPanel.cs:7339`，每次回复 HP）、`dead`、`roomChange`、`bulletAdd`。
- 顺序差异：`normalAtkDam` 在 `CalculateFinalDamage`（L5751）**之前**，`normalAtkAddNewDam` 在扣血**之后**；前者另受 `ignoreBuffCheck_normalAtkDam` 门禁。
- 宠物特性实测分布：236 条 `buffEffect` 以 `pet_` 开头的记录，16 种 `detectType`。`beHit` 与 `normalAtk` 各 28 条最多，`none` 47 条靠 `StartAction` 生效。
- 截图 5 例全部核对一致：角布林 / 源泉猫 / 元素电荷 → `normalAtk`（只算 1 次）；囊袋恐兽 → `normalAtkDam`、提灯妖精 → `normalAtkAddNewDam`（两把刀各判一次）。
- 16 处源码行号引用逐一脚本核对通过。
