## Bug 修复

### 一、分享图右下角出现无背景区域（合成器漏乘画布缩放）

- 现象：窗口宽于 1534 CSS px（如 1920×1080）时，魔物蛋池与角色池「分享」保存的 PNG 右边与下边各有一条**透明带**（用户报的「右下角有无背景区域，不应该是全图吗」）。
- 根因：`utils/gachaShareImage.js` 的输出画布按 `getBoundingClientRect()` 开，即**视觉（CSS）像素**、已含画布 `transform: scale()`；而图层矩形由 `toDesign()` 换算成**设计像素**。上下文变换只写了 `ctx.scale(OUT_SCALE, OUT_SCALE)`，**漏掉画布 `scale`**，两套单位不一致。
- 同一根因的另一个方向：`scale < 1`（1440×900 → 0.9387）时内容溢出把整张盖满，**看不出问题**。1440×900 恰好是所有既有 UI 用例的默认视口，这是缺陷长期隐形的原因。手机竖屏 `scale` 仅 0.256，旧实现会裁掉约四分之三场景。
- 修复：上下文变换改为 `ctx.scale(OUT_SCALE * scale, OUT_SCALE * scale)`。换算成立：`设计像素 × (OUT_SCALE × scale) = 视觉像素 × OUT_SCALE = 输出像素`。
- 影响面：角色池 `renderGachaResultImage` 与蛋池 `renderGachaPetImage` 共用该合成器，两池同时修好。

### 二、触摸竖屏分享图是竖版乱图

- 现象：手机竖屏下分享出的 PNG 为 786×1702 **竖版**，且每个图层宽高错位。
- 根因：`GachaViewport` 在触摸设备竖屏时给整页内容套 `rotate(90deg)`，此后 `getBoundingClientRect()` 返回**旋转后的轴对齐包围盒**（画布设计盒 1624×750 横版，包围盒却是 393×851 竖版）。输出尺寸取包围盒、图层矩形也按包围盒宽高算，等于把横版场景塞进竖版画布。
- 修复：新增 `contentQuarterTurn(el)`，沿祖先累加 `transform` 矩阵的旋转角（只取整 90° 倍数），把包围盒**逆变换回内容自身（未旋转）坐标系**；输出尺寸改用未旋转的 `visualW/visualH`，保持**横版构图**——分享的是场景本身，不是「用户侧着头看」的那一帧。
- 判据：同一场景在竖屏与横屏下必须合成出**尺寸完全相同**的横版图（比「看输出是不是横的」更严，同时锁住取景与图层取位）。

### 三、分享图左右两侧没有背景（合成器把 `cover` 当成 `contain`）

- 现象：角色池结果页分享出的 PNG，美术内容居中、**左右两侧各有一条未着墨的空带**；货币条、关闭按钮、分享按钮这些贴边 HUD 反而压在空带上（用户报的「角色的背景也有问题，左右俩侧没显示全」）。
- 根因：`utils/gachaShareImage.js` 的 `drawImageFit()` 只判了 `fill`，其余取值**一律走 `Math.min` 等比居中**，即 `contain`。结果页背板是 `.result-backdrop__bg { object-fit: cover }`，在分享图里被缩到 `min` 比例居中 → 两侧露出下层 `.gacha-bleed` 的暗色。实时页面走浏览器原生 `cover` 铺满，所以**页面级断言看不到这个缺陷**。
- 为什么既有用例守不住：上面两条用例量的都是**输出 alpha 包围盒**（「有像素的地方有没有漏」）。本缺陷的特征是**两侧被多画了东西**且画出来的是**不透明**的暗色，包围盒仍是满幅，两条用例必然通过。
- 修复：`drawImageFit()` 改为逐值复现 CSS —— `fill` 拉伸、`contain` 取 `min`、`cover` 取 `max`、`none` 原尺寸、`scale-down` 取 `min(1, min)`；`cover`/`scale-down`/`none` 超出矩形时按矩形 `clip`（等价 CSS 溢出裁切）。与同文件 `bgOnly` 分支既有的 `Math.max` 实现对齐。
- 影响面：`renderGachaResultImage` 与 `renderGachaPetImage` 共用该函数。蛋池背景走 `bgOnly` 分支（`.gacha-bleed`），本来就正确；角色池背板走 `IMG` 分支，是本次修复对象。全仓仅这两个消费者。

### 四、分享图里按钮底板与资源槽底牌丢失（合成器漏读 `border-image` 与 `<button>`）

- 现象：角色池结果页分享出的 PNG 里，「招募十次」按钮**只剩文字、底板丢失**；右上角三个资源槽的底牌也消失，只剩图标与数字（用户报告分享图少了按键背景与资源后的背景）。
- 根因一（`border-image` 从未被读取）：收集器只判 `cs.backgroundImage !== 'none'`。资源槽底牌 `.currency-slot__bg` 是 `.g-slice--top-item`，样式为 `border-image: url('/images/Common_Atlas/com_top_item.webp') 0 20 0 20 fill / 0 20px stretch` —— **只挂 `border-image`、没有 `background-image`**；该 div 又无文本，于是被归入「文字层」画了空内容。整个结果舞台里它是**唯一**一个 `border-image` 元素。
- 根因二（标签白名单漏掉 `button`）：收集器选择器是 `'img, canvas, p, span, em, div'`，抽取按钮是 `button.g-slice.result-btn`，**`button` 不在白名单**，该元素整层没被枚举；它的底板挂在 `.g-slice--btn-y` 的 `background-image` 上（`com_btn_Y_sp_292x72.webp`），本可被读到，却因为宿主标签被排除而丢失。白名单漏一个标签就**静默丢一层**。
- 为什么既有用例守不住：三条既有分享用例量的都是**输出 alpha 包围盒**。这两处缺陷都发生在画面**内部**，背板仍铺满全幅，包围盒一直是满的。与「三」同源：包围盒类断言只能发现「有像素的地方漏了」，发现不了「该有的东西没画」。
- 修复：
  - 收集器改为 `querySelectorAll('*')` **全量枚举后代**，去掉标签白名单；每个元素按 CSS 绘制顺序产出多个图层（`background-image` → `border-image` → 内容文字），图层带 `kind ∈ {canvas, image, bg, border, text}`，绘制循环按 `kind` 分派。
  - 新增 `drawBorderImage()`：按九宫格合成而非整图拉伸。切片、`border-image-width`、`fill` 均取自 computed；非均匀切片（`0 20 0 20`、`0 15 0 15`、`4 4 4 4`、`16 4 16 4`、`0 8 0 8`）逐格绘制；切片/宽度超出源图或盒子时按比例收缩。
  - 新增 `drawBackgroundImage()` 取代原先只服务 `.gacha-bleed` 的 `bgOnly` 分支。旧实现把 `cover` 写死了，而 `.g-slice--btn-*` 用的是 `background: … / 100% 100%`（整图拉伸），按 `cover` 画会等比放大后居中裁切、**底板四边被切掉**，故 `background-size` 必须按 computed 值逐项复现（`resolveBackgroundSize` / `resolveBackgroundAxis`）。
  - computed 里的绝对长度是 **CSS 视觉像素**，图层矩形是**设计像素**，两者相差画布 `scale`；长度类取值（`background-size`、`background-position`、`border-image-width` 的 px 值、`border-width` 倍数）一并按 `scale` 折算。百分比与倍数无量纲，不折算。
- 影响面：`renderGachaResultImage` 与 `renderGachaPetImage` 共用该合成器，两池同时修好。`GachaPoolPanel.vue` 有同一套 `.currency-slot` / `.draw-cost` 结构，收集器层面的修复同样覆盖。
- 已核实为**非缺陷**：消耗行底板 `.draw-cost__plate` 是 `<img>`（`position:absolute; inset:0`），本就走 `IMG` 分支正常绘制。三次测量中该区数值完全不变（页面亮度 36.8 / 分享 35.3），与修复前一致。

### 五、分享图缺星光辉光（合成器只认 `url()` 背景图，渐变与 `background-color` 一律不画）

- 现象：蛋池揭晓结果的分享 PNG 里，菱形蛋框外围的**星光辉光整层缺失**（页面正常，只有分享图少一层）。
- 根因一（`background-image` 只认 `url()`）：`drawBackgroundImage()` 用 `cs.backgroundImage.match(/url\(["']?(.*?)["']?\)/)` 取源，取不到就 `return`。`.pet-diamond__glow` 是 `radial-gradient(circle, …)`，正则必然不匹配 → **静默早退**。收集器按 `cs.backgroundImage !== 'none'` 已把图层入栈，画的时候什么都没画，于是「图层存在、无像素」。
- 根因二（`background-color` 从不绘制）：全模块没有 `backgroundColor` 分支。纯底色元素（无背景图）连图层都不入栈。
- 根因三（`border-radius` 不参与裁切）：背景只按 `ctx.rect()` 的矩形裁切，带 `border-radius` 的元素会画成方块。
- 为什么既有用例守不住：与「三」「四」同源，分享用例此前只量**输出 alpha 包围盒**，背板已铺满全幅，内部少画几层照样满幅通过。
- 修复：
  - 新增 `paintGradient()`，支持 `linear-gradient` / `radial-gradient` 及 `repeating-` 前缀：方向/形状/尺寸/位置配置按 CSS 规则解析（含 `to <角>` 的方向向量、`closest/farthest-side/corner` 默认半径）；停靠点缺位置按 CSS 补位（首 0 / 末 1 / 中间按两侧均分）。`conic-gradient` 未实现（全仓无使用者）。
  - `background-color` 先于所有背景图铺底；多层 `background-image` **倒序**绘制（CSS 里先列的画在上面）。
  - 新增 `applyBorderRadiusClip()`：四角八值 + CSS 重叠同比收敛规则；computed 圆角长度按 `scale` 折算。**只用于背景支路**——`border-image` 不受 `border-radius` 裁切，九宫格支路保持矩形裁切。
  - 收集判据补上 `background-color`：只判 `background-image` 会把纯底色元素整层漏掉。
  - 非法颜色值（认不出的写法）返回 `null` 跳过该层，不赋给 `fillStyle`——非法值会被**静默忽略**，于是用上一次的颜色把整块涂错。
- 影响面：`renderGachaResultImage` 与 `renderGachaPetImage` 共用。角色池结果面板无渐变、无 `background-color`、无 `border-radius`，不受影响；蛋池 `.pet-diamond__glow` 是唯一实际缺陷。
- 已核实为**非缺陷**：`.pet-black`（`background: #000`）在 `camSettled` 置真后 `opacity: 0`，被收集器的 `opacity` 判据跳过；`.pet-egg__shine` 在 `eggStage === 'settled'` 后同样 `opacity: 0`。`GachaStage.vue` 的 `.gacha-stage` 底色 `#0b0703` **结构性**不参与合成（收集器遍历 `querySelectorAll('*')`，舞台根自身不入列），两池都由 `backdrop` 的 `.gacha-bleed` 铺底遮蔽，无可见缺陷。

## 验证

- 新增四条常驻用例，均在 `tests/ui/gacha.spec.js`：
  - `魔物蛋分享图在放大视口下仍满幅（无透明带）`：**强制 1920×1080**（desktop 默认 1440×900 下 `scale < 1`，无鉴别力），直接驱动真实合成器量输出 alpha 包围盒；并自检 `scale > 1`，避免以后被改成静默通过。
  - `触摸竖屏分享图与横屏一致（不产出竖版乱图）`：仅触摸项目运行；先断言内容层矩阵为 `matrix(0, …)`（确实被旋转了）再比较竖/横两次输出。
  - `分享图合成器按 object-fit 取值铺图（cover 不缩成 contain）`：用合成夹具（100×100 红框蓝心图放进 400×200 盒子）而非游戏素材，`cover` 取 `max` 时最左/最右列必落在源图最外圈（红），`contain` 取 `min` 时最左列**完全未着墨**（alpha 0）。同一盒子的 cover/contain 对照把取值钉死，不依赖视口尺寸与真实美术。
  - `分享图合成器画 border-image 底板与 button 背景图`：同样用合成夹具（纯绿 64×28 源图作 `border-image` 底板、纯品红 292×72 源图作 `<button>` 背景），断言的是**具体位置的像素内容**而非包围盒。空白对照点先自证透明，避免采样本身失效而静默通过。
  - `分享图合成器画 background-color、渐变与圆角裁切`：合成夹具四项——纯 `background-color` 块、`radial-gradient` 块、`to right` 双向渐变块（左绿右黑，**方向错了也守得住**）、`border-radius: 50%` 圆块。径向渐变同时断言中心与外缘的**色相**（只判「有像素」守不住画成纯色），圆角块断言圆心着墨 + 四角透明。
- 负向验证（全部复原，`grep NEGVAL src` 无残留）：
  - 上下文变换退回 `ctx.scale(OUT_SCALE, OUT_SCALE)` → 放大视口用例失败，报错数字与用户现象一致：`maxX: 3261`、`maxY: 1966`（期望 3839 / 2159，输出 3840×2160、scale 1.2516）。
  - 旋转判定强制为 0 → 竖屏输出退回 786×1702，与横屏「尺寸一致: false」，像素平均差 47.25、明显不同占比 48.80%。
  - `cover` 分支退回 `containScale` → object-fit 用例失败：`cover 左边缘应已着墨，实测 [0,0,0,0]`（alpha 0，即空带本身）。同时**上面两条 alpha 包围盒用例仍然通过**，反证它们对这一类缺陷没有鉴别力。
  - 关闭 `border-image` 采集 → 新用例失败：`底牌采样点 0 应已着墨（border-image 未被采集），实测 [0,0,0,0]`；按钮断言仍通过。真实分享图上该区分享亮度 55.9 → 65.2、与页面平均绝对差 10.4 → 17.8。
  - 选择器退回标签白名单 → 新用例失败：`按钮采样点 0 应已着墨（button 未被枚举），实测 [0,0,0,0]`；底牌断言仍通过。真实分享图上抽取按钮区分享亮度 53.3 → 18.5、与页面平均绝对差 3.4 → 37.7。
  - 两次负向验证各自只打中一个轴、另一个轴仍通过，说明 `border-image` 与标签枚举是**两个独立可分辨的根因**，未被合并成一条断言。
  - 关闭渐变绘制 → 夹具用例失败：`径向渐变未绘制，实测 [0,0,0,0]`，同时底色/圆角断言仍通过。
  - 关闭 `background-color` 采集 → 夹具用例失败：`纯 background-color 未绘制，实测 [0,0,0,0]`，同时渐变/圆角断言仍通过。
  - 圆角裁切强制走矩形分支 → 夹具用例失败：`border-radius 外的四角应透明，实测 [255,255,0,255]`（黄块涂满四角），同时底色/渐变断言仍通过。
  - 三个轴各自独立可分辨，未被合并成一条断言。
- 现象复现与修复前后像素对照（临时探针已删除）：
  - 用户视口 1548×736 实时渲染满幅；修复前分享 PNG 左边缘 1% 处 `(2,7,11)`，修复后 `(19,36,48)`，与实时页面的 `(22,39,48)` 一致。
  - 修复后分享 PNG 与同视口页面截图逐区对比（页面像素域，平均绝对差）：资源槽 10.4、消耗行 16.0、抽取按钮 3.4、分享键 1.7、背板 0.6；全图平均差 1.26、显著不同占比 0.25%。差异集中在文字抗锯齿与 WebGL 人物立绘，底板/底牌区域已着墨。
  - 蛋池星光辉光（1920×1080，输出 3840×2160，辉光框 375×375 视觉像素）：以「隐藏辉光后重合成」为差分基准，辉光区域变更像素 **6424 → 0**（关掉渐变绘制时）；合成器**首帧与后续帧有差异**（连合四次差值 `[134925, 0, 0]`，第 2/3/4 次逐像素一致），探针已丢弃首帧并断言稳定后两次逐像素一致（本底 0），否则差值无鉴别力。
