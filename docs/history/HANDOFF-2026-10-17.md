## 二、召唤物属性展示

### 结论（源码核实，这是本批最重要的产出）

召唤物**只继承 5 项**：物攻、魔攻、物防、魔防、生命。

| 项 | 规则 | 源码 |
| --- | --- | --- |
| 继承 | 物攻/魔攻/物防/魔防/生命，按 `summonData` 的 `atkPercent`/`defPercent`/`hpPrecent` 比例 | `Unit.cs:1471-1482` |
| 固定（不继承） | 攻速、暴击率、暴击伤害 —— 取自**怪物配置表** | `UnitAttribute.cs:609/613/614` |
| 穿透 | **不继承，且召唤物自身穿透恒为 0** | `UnitAttribute.cs:621` + `CombatPanel.cs:6144` |
| 全体加成 | **生效**（召唤物进入 `allHeros`，全体技能遍历不排除它） | `Unit.cs:1613-1627` + `XiLu_Skill2.SkillPointAction` |
| 宠物被动特性 | **不生效** | `BattleManager.cs:7604` 的 `if (unit.summonUnit) continue` |

**关键机制**：继承是**召唤瞬间的快照**。`UnitAttribute` 的 `phyAtk`/`phyDef`/`maxHp` 都是计算属性
（`phyAtkAddNum + PhyAtk * (1 + phyAtkAdd)`），所以**召唤那一刻角色身上的装备与 buff 会被乘进基数**，
之后不联动。

### 两个必须记住的坑

**① 天赋的召唤配置不在 `levelData` 里**

```
06504「驻守指令」 levelData = { skillName, des, buffId: 'hero065Talent' }
                      ↓ 没有 aniEvents、没有 summonData
buff['hero065Talent'].para.summonData = { monTypeId: '065Summon2', ... }
```

只查 `aniEvents` 会整条漏掉天赋。`resolveSummonConfig()` 覆盖两条路径。

**② `noAtk: 1` 的召唤物不能显示攻速/暴击/爆伤**

`UnitAI.cs:701` 是 `WaitUntil(() => self.noAtk <= 0)`，`noAtk` 恒为 1 时 AI 永不出手。
此时配置表的 `0.35 / 35% / 125%` 只是**该表默认占位**（实测 14 个不攻击的召唤物几乎都是这套值）。
典型：反击假人（`noAtk=1` + `rebDam=100`，靠反伤）。显示它们会让人误以为「假人有 35% 暴击」。

## 七、接手时的注意事项

1. **先 `git status`** —— 工作区可能有他人未提交改动。
2. **`scratch/` 已 gitignore** —— 审计报告不会随仓库传递，需要时重新生成或让上游补。
3. **`functions/` 不热加载** —— 改了 API 必须重启 `npm run dev:api`。
4. **改 `.mjs`/`.js` 后跑 `node --check`** —— 本批有一次编辑把 `raw-sync.mjs` 弄出语法错误
   （多了一个 `*/`），单测不 import 该文件所以照过，是后来 `node --check` 才发现的。
5. **不要用「按注释当依据」** —— 本批有 4 处错误源自「看到注释就下结论，没回源码核对」
   （`TAG_LABELS` 的「无官方名称」、`tag` 类型名、`passStage` 位置、`canelSummon` 的用途）。
   凡是涉及游戏行为的结论，都要落到 `源码文件:行号`。
