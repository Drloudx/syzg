# history —— 历史归档索引

> **追溯历史时先搜索，再读命中上下文。** 不要通读本目录。
> 归档内容**不是当前规范**：其中的结论可能已被后续改动取代。
>
> **何时读**：需要追溯某个决策、故障或改动的来历时（**先按主题定位，再读命中上下文**）。
> **何时更新**：发生必要归档时（新增主题归档、迁移文件到本目录）。

## 一、怎么查

| 我知道 | 用 |
| --- | --- |
| **改的是哪个功能** | 查下方[主题索引](#二主题索引) → 拿到日期 → 读那几篇 |
| **只知道关键词** | 全文搜（见下） |

```powershell
Select-String -Path docs/history/dev-logs/**/*.md -Pattern "关键词" -Encoding UTF8
```

日志按日汇总，**同一天涉及多个模块也在同一份文件里** —— 不要按单次改动找文件。

## 四、写新日志

模板与规范见 [../dev-logs/README.md](./dev-logs/README.md)。要点：

| 规则 | 说明 |
| --- | --- |
| 按日汇总 | **同一天一份**，不按单次改动新建 |
| 只记结论 | 保留最终有效实现与重要取舍；**不留**反复尝试、逐条聊天回应、重复构建输出 |
| 标注未执行 | 未做的项**必须明确标注**，不把「准备执行」写成「验证通过」 |
| 不能替代规范 | 长期规则变化要同步对应权威文档 |

**新增主题归档时**，在本文件第二节补一节，不要新建索引文件。
