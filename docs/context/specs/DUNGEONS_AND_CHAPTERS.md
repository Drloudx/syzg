# 副本、关卡与章节地图

> 本文件是副本图鉴、关卡图鉴与章节地图的业务契约。
> 房间内容与奖励池的展示整形由 `utils/roomDisplay.js` 统一提供，两个页面共用。
> 提取输入与来源定位的深入规则见本文件第四节。
>
> **何时读**：改动副本、关卡、章节地图或房间掉落时。
> **何时更新**：该领域规则变化时。**只改这一个领域文件，不要把别的领域内容搬进来。**

---

## 一、副本图鉴

**入口** `/dungeons` · **页面** `DungeonsView.vue`

| 数据 | 加载时机 |
| --- | --- |
| `parsed/dungeons.json` | 先取摘要 |
| `parsed/dungeons/{battleId}.json` | 打开关卡再取 |

**不把全部路线和房间放进首屏请求。**

### 职责分工

| 模块 | 负责 |
| --- | --- |
| 页面 | 地图/关卡、房间详情、掉落 |
| `DungeonRouteMap` | 路线切换、节点聚合、缩放、鼠标/触摸拖动、选择事件 |

**父页面不复制手势状态。**

### 路线与节点

- 节点和连线取**真实布局**。
- 同一节点多个候选房间**标明候选**，不当成每次必然遭遇。
- 房间 `layer` 和 `1/2/A/start/boss` 等布局标记**不作为**玩家楼层或实际房间名。

### 房间内容

按波次显示怪物，保留 NPC、采集实体、自动掉落和结构化效果。

| 项 | 规则 |
| --- | --- |
| 多波 | **不跨波合计** |
| 重复采集 | 可**合并数量** |
| 女神 / 泉水 | **不能**只剩房间名而丢掉效果 |

### 采集与掉落

采集沿 `spObj.caijiTypeId → roomCollect → roomCollectType → reward`。

| 模式 | 含义 |
| --- | --- |
| `mode:equip` | 可追踪的**固定装备** |
| `mode:equipGroup` | **随机池** —— 展示类型/品质**不证明**某件装备实际掉落 |

### 奖励区

- 首通、结算、特殊、BOSS、房间箱子等**按配置区分**。
- `showReward` 名称统一「副本预览掉落」，**只与当前关卡真实结算/BOSS 链匹配**；**不能按同名补造**宝箱或采集来源。
- 特殊、结算、预览掉落**默认折叠**；首通**直接展示**。
- 来源直达展开相应区块，房间定位同步候选。
- 重复路线引用同一奖励组**不叠加概率**；**不把**前一关卡箱子复制到后一关或噩梦。

### 交互

普通滚轮交给详情内部滚动；**Ctrl/Meta+滚轮才缩放**。
封面近视口加载且保留占位；**图片优化不重编码原图**。

### URL

| 参数 | 含义 |
| --- | --- |
| `map/q` | 筛选 |
| `battle` | 打开详情 |
| `drop/dropTab/dropEntry` | 定位物品、奖励区或房间 |
| `dropTab=settlement|first|rooms` | 定位奖励区 |
| `chest` | 旧值，保持兼容 |

物品叠加 `itemId` 后可返回原关卡位置。

提取输入、房间过滤与结构化效果见本文件[第四节](#四路线提取与房间过滤)。

## 二、关卡图鉴

**入口** `/chapters` · **页面** `ChaptersView.vue`

| 数据 | 加载时机 |
| --- | --- |
| `parsed/chapters.json` | 先取章节与关卡索引 |
| `parsed/stages/{stageId}.json` | 打开关卡再取 |

数据来自**完整原表** `chapterInfo/area/levelStage/battle/room`，**不使用**副本专用的裁剪表。

### 章节与难度

| 项 | 规则 |
| --- | --- |
| 章节来源 | `chapterInfo.json`（`c0`～`c5`）与 `area.datas[spN_map]`（幽夜古堡、黏滑溪谷） |
| 关卡顺序 | 取 `area.map.levelStage`，与游戏章节地图一致；**不按 ID 排序** |
| 难度展开 | 每个关卡按 `battle1/battle2/battle3` 展开简单/普通/困难 |
| 三难度房间 | **各自独立**（`roomTypeId` 带难度后缀）；**不能合并**成一份布局 |
| 逐难度取值 | 体力、限时、推荐等级、奖励组 |

### 解锁文案

按源码 `LevelStageShowPanel` 生成：

| 难度 | 判据 |
| --- | --- |
| 普通 | `chapterInfo[chapter].exBattleOpenCondition` |
| 困难 | 是否通关普通 |

**不把**地图连线或 `hide` 当作解锁前置。

> `hide: true`（92 关中 74 关）在游戏里是「未解锁时在地图上隐藏」。
> 本站不连账号，**不做解锁模拟**，一律正常展示。
### 复用

房间、怪物波次、采集物与掉落**复用副本图鉴的解析与展示组件**（`roomDisplay.js`、`RoomContentList.vue`、`RewardPools.vue`），**不另写一套**。
怪物按波次分行；采集与自动掉落按奖励池展示；随机候选房间**标明候选而非必然遭遇**。

### 搜索

覆盖关卡名、短号、描述与构建期汇总的 `searchText`（含奖励物、怪物与采集物名称），因此**可以按掉落反查关卡**。
难度筛选按该关卡**实际存在的难度**判断。

### 展示规则

| 项 | 规则 |
| --- | --- |
| 章节按钮 | 显示**地区名**（不带宽高代号数字，如「索利德山地」而不是「2 索利德山地」） |
| 卡片难度标签 | **只显示一个**：按当前难度筛选显示对应难度；筛选为「全部」时默认显示「普通」 |
| 无「普通」时 | 退回它**实际有的第一个**难度 |
| 卡片推荐等级 | 跟着这个难度走 —— 三难度的 `battleLevel` 不同，索引里按难度存 `levels`，**不用单一等级** |

### 难度切换控件

关卡详情的难度切换用 `UiFilterRow` + `UiFilterPill`（与列表页的难度筛选同款），**不用 `UiSegmentedTabs`** —— 后者是深色木条、为深色底设计，放在羊皮纸弹窗里不搭。

详情徽标行沿用各详情页共用的 `.detail-badges`（`display:flex; gap`）；漏了这条样式，标签之间就只剩空白字符的间距。

### 黑名单

按副本图鉴的**同一口径**处理：命中地区名（如黑森林、霜烬平原）的章节**整章不出现**在筛选按钮与列表中，避免按钮与内容不一致；直接链接同样**不打开**被隐藏的关卡。

### URL

| 参数 | 含义 |
| --- | --- |
| `chapter` | 选章节（缺省 `all`） |
| `stage` | 打开关卡详情 |
| `diff` | 选难度 |
| `q` | 同步搜索 |

关闭详情**只清理** `stage/diff`，保留章节与筛选；奖励与材料只追加 `itemId`。

### 列表

- 单列虚拟网格，与[任务图鉴](QUESTS_AND_EVENTS.md)同构。
- 换章节后由 `UiVirtualGrid` **自行**把列表滚回顶部，页面**不额外滚动** —— 用 `scrollToItem` 会以居中方式滚动整页，把上方的地图推出视口。
- **显隐按端区分**：手机端**常驻**（没有地图，列表就是主视图）；桌面端属于列表视图 —— 由「展开列表」或点地块进入，地图不再出现，搜索框右侧的「进入地图」切回。
- 搜索词**在列表视图内生效**（地图视图没有搜索框）。

## 三、章节地图

`/chapters` 的主视图是游戏原版的地图，分两级：世界地图（底图 + 章节拼块）→ 点地区进入该章节的地区路线图。

### 两级结构

| 状态 | 视图 |
| --- | --- |
| 未选章节 | 世界地图（6 个章节拼块） |
| 已选章节 | 该章节的**地区路线图**（`map_w1_cN_bg` 底图 + 关卡/地区/副本/探索节点 + 连线） |

层级**由 `chapterId` 推导、不另存状态**，刷新与分享自然一致：
`/#/chapters` 是世界地图，`/#/chapters?chapter=c1` 是秋日荒野的路线图。

### 节点坐标与锚点

- 节点坐标取 `area.map`，连线直接取 `area.map.link`。
- **摆放偏移不要照搬源码**：源码给地区节点上移 80、副本入口上移 75，那是给 `AreaItemUI` / `InstanceRoomItemUI` 在它自己的 prefab 层级里用的；网页版是「sprite 居中摆放」，照搬会把图标整体抬离节点。本站两个偏移**都取 0**，改用各 sprite 自己的锚点定位。
- 探索点**只画点不标名** —— `explorePoint.json` 只有一条配置，真正的点位来自玩家存档。

#### Y 轴必须翻转

配置是 Unity UI 的 `localPosition`（+y 向上），而 CSS 的 `top` 是 +y 向下，直接用整张地图会**上下镜像**。

- 判据来自游戏截图：2-6 在 2-5 上方，而配置 `y(2-6)=1095 > y(2-5)=957`。
- 统一 `y_css = size.h − y_unity`；偏移量**在 Unity 坐标里先加再翻**。
- 节点、连线、底图中心**都要翻**。

#### 只有关卡节点可点

地区/副本/探索点是地图装饰（源码里地区节点的 `BoxCollider` 是 `enabled = false`），用非按钮元素 + `pointer-events: none`。
否则 104px 宽的立体图会盖住关卡节点、把点击吃掉；层级上关卡节点 `z-index` 最高。

#### 节点图形

| 节点 | 图形 |
| --- | --- |
| 关卡 | 石台（图集 `map_s`） |
| 地区 | 立体图 `texture/area/icon/<area.icon>` |
| 副本入口 | 立体图 `texture/area/icon/<map.instance[].img>` —— **不是** `instance.icon`（后者是副本自己的平面图标） |

图下面挂编号/名称牌；名称牌走 `border-image` 用图集里的 `map_a_title`（两端菱形是装饰、中段随名字伸缩，**整张缩放会把菱形拉扁**）。连线是金色虚线。

#### 三类节点的锚点语义不同

尺寸与锚点都要**按各自 sprite 量**：关卡石台 128×128、地区立体图 244×258、副本入口图 172×180。

| 节点 | 锚点 |
| --- | --- |
| **关卡** | 石台以**自身中心**落在节点坐标上；名称牌挂在石台下方。编号在游戏里是**没有底板的白字 + 深色描边**，不是深色小牌子 |
| **地区** | 锚点在**圆盘中心**（sprite 高度的 75.4% 处，比 sprite 中心低 25.4%），所以 sprite 要往上挪（`top: -17.8px`）才能让圆盘落在节点坐标上；不这么做整棵建筑会往下压、看起来「没落在节点上」。名称牌挂在圆盘下缘，上方还有一块 `map_a_tag` 小标签（游戏里写「自由探索」） |
| **副本入口** | 图以**自身中心**落在节点坐标上；名字压在图上**自带的石牌**里（sprite 的 y 148..165 一带），不再另挂一层边框 |

判据来源：`area.map.link` 的端点就是节点坐标本身，把金色虚线打点画出来即可看出端点落在哪。

#### 其他约束

- 地区名称牌可以**轻微**压到下方关卡石台（游戏本身就这样，石台在上层），但**不能整块盖住**石台、让水晶从牌子里戳出来 —— 回归断言按「重叠不超过牌子高度的一半」判。
- 图集里的 `map_select_out` / `map_select_in` / `map_select_corner`（两层同心橙环 + 四角回纹角标）是 `AreaItemUI.selectGo` 的**选中态**装饰；本站没有「当前选中地区」这个状态，**不显示也不导入**。
- **节点锚点只由图形决定**：名称牌绝对定位挂在图形下方；参与布局会把节点整体上推，落点就不准。
- **绝对定位的 `<button>` 里不要用百分比宽度**：按钮是 shrink-to-fit，与子元素的百分比宽度形成循环依赖，浏览器会退化成「按钮撑满、内容居中」。「世界地图」标题条即为此例，给按钮**显式宽度**即可。

#### 关卡石台切片

石台不是独立素材，在 `atlas/uiatlas/mappanel/MapPanelAtlas.png` 里。

| 项 | 规则 |
| --- | --- |
| 矩形来源 | **直接取图集的 sprite 表**（`mSprites` 的 `map_s` / `map_s_lock` / `map_s_1st`，源码用的就是这些 sprite 名） |
| **禁止** | 另用连通域或估的坐标 —— 旧常量 `(402,1004,126,126)` 与真实来源不符 |
| 必须用 | **完整尺寸**那张图集（同目录另有 2047×1389 的缩略版，sprite 表的 y 会越界） |

### 缩放、平移与画布

- 地区画布比可视区大得多（2727×2406 ~ 3456×2144），所以需要缩放平移：用**显式的平移偏移**而不是 `scrollLeft`（缩到比容器小时 `scrollLeft` 恒为 0，拖动会**完全失效**）；画布比容器小时锁居中，大时限制在边界内。
- 初始视图**贴合节点包围盒**（加 180 边距）而不是整张画布 —— 节点通常只占画布的一小块（c1 节点跨度 1454×871，画布 3456×2144），按画布适配会让节点挤成一团。
- 节点标记按 `1/zoom` **反向缩放**，屏幕上保持恒定大小，否则缩小后标签读不清。
- viewport 上有拖动监听并会 `setPointerCapture`，因此**任何按钮上都不启动拖动**：捕获后 `pointerup` 落在 viewport 上，按钮的 `click` 就不再触发（缩放条、返回、节点、胶囊**全是按钮**）。拖动从地图**空白处**开始。
- 底图按 `bgPos` 居中摆放，宽度用图片自身像素换算成画布百分比，所以产物里**不必存**底图宽高。
- 底图路径按**章节 id**（`map_w1_c1_bg`）而不是地区 id（`c1_map`）—— 两者差一个 `_map` 后缀；拼错时 SPA fallback 会对不存在的图片返回 200 + HTML，只有解码失败才会暴露。

### 地图视图与列表视图互斥

由**显式的视图状态**决定（不是从 `chapter` 推导，否则「全部章节」的列表没有可分享的 URL）：

| 视图 | 内容 |
| --- | --- |
| 地图视图 | 整块区域只有地图；点地块进入该地区的路线图、点路线图上的关卡节点打开关卡详情；右上角「展开列表」切到列表 |
| 列表视图 | 不出现地图；桌面端搜索框右侧的「进入地图」切回 |

列表视图无章节时 URL 带 `view=list`，刷新与分享能回到同一屏。

> **地图只在桌面端出现**：手机宽度下拼块里的章节名只有约 9px 高、读不清，一张读不了的地图占掉大半屏反而更差。手机端恒为列表视图，用章节按钮切章节（「进入地图」也不显示）。
> 断点与 `ChapterMapCanvas` 内的 `767px` 判断一致。

### 世界地图

| 项 | 规则 |
| --- | --- |
| 地图区高度 | **左右面板底部 − 地图区顶部**，由页面测一次给两个地图组件共用 |
| 为什么取左右面板 | 两侧 sticky 面板要留底部安全区，比视口底还高一点；按视口算地图会比面板长出一截 |
| 画布底部 | **不留外边距** —— 留了同样会超出面板，页面多出一条无意义的滚动条 |
| 上限 900px | 为了限制正方形舞台的裁切量 |

**铺满方式**：底图是正方形而区域是长方形，所以画布内部放一个正方形**舞台**按 cover 缩放居中，超出画布的部分裁掉 —— 裁掉的是边缘云朵，大陆本身不动。

> **命中判定必须用舞台矩形换算**（舞台可能比画布大），**不能**用画布矩形。

**画布描边**沿用全局 `.paper-panel`（与左侧导航面板同一套 2px 描边、阴影与圆角），**不另写**一套面板样式。
世界地图画布内只有「展开列表」是真按钮，其余覆盖层（标题条、底部标签）都 `pointer-events: none`，不挡地图点击。

**幽夜古堡、黏滑溪谷**不在世界地图上，由页面通过画布的 `extra` 插槽在地图视图里补入口 —— 否则地图视图**没有任何路径**能进这两个章节（当前两者已进黑名单，入口随之为空）。

### 底图、拼块与命中判定

- 底图 `map_w1_bg.png`（1680×1680）与 6 块章节彩色拼块来自 `ChapterPanel` 预制体。
- 拼块在底图上的坐标**不是配置项**（prefab 导出里没有 Transform 节点），由模板匹配测得并固化为构建期常量，见 `scripts/parse/chapterMapLayout.mjs`；重测入口 `scripts/dev/measure-chapter-map-tiles.mjs`。
- **底图换图或换尺寸必须重测**，不能沿用旧值。

#### 归属图

命中判定用构建期烘焙的**归属图**（`chapters.json.map.owner`，256×256 RLE，约 4.6 KB）。

| 为什么不能只用矩形热区 | 说明 |
| --- | --- |
| 拼块包围盒互相重叠 | c0 的框有 **57%** 被 c3 压住，矩形热区会点错章节 |
| 不透明区域之间也有重叠 | 所以归属**按渲染顺序**定 |

运行时**按格查表**，不用 canvas 取 alpha（原生端 CDN 跨域会污染 canvas）。

#### 标题条

「世界地图 · 选择需要前往的章节」标题条在世界地图画布**左上角**（同时是「你在这里」的标识）；在地区路线图里它是**「返回世界地图」按钮**，当前章节标签在底部居中。
世界地图上其余覆盖层都 `pointer-events: none`，不挡地图点击。

#### 拼块渲染

- 只渲染**可见章节**：被黑名单隐藏的地区不出现，该区域保持底图原样（等同游戏里未探索的样子）。
- 幽夜古堡、黏滑溪谷同样在模糊名单里（整章隐藏），世界地图上本来也没有它们的拼块。
- 地图视图里的 `extra` 入口由 `visibleChapters` 推导，**被隐藏后自动消失**。
- 未选中具体章节时整张地图保持原色；选中后当前地区高亮、其余压暗，底部标签显示当前章节与关卡数。
- 鼠标进入地图后，指着的那块**浮起**（放大 1.045、提亮、加投影、提到最上层），其余压暗到 0.55 —— 默认状态所有拼块同色，没有这个反馈就分不清指着哪一块。

#### 无障碍与默认状态

- 画布 `aria-hidden`：地图是鼠标/触摸的快捷入口，等价的可聚焦控件是同一页的章节按钮，键盘用户用它切换；折叠开关是**真按钮**，放在 `aria-hidden` 之外。
- 手机端**默认收起**（拼块里的章节名在 390px 宽下只有约 9px 高，读不清，又占掉大半屏）；桌面**默认展开**，两端都可手动折叠。

## 四、路线提取与房间过滤

> 本节是[路线提取与房间过滤]的深入规则；主规范见本文件前面的领域小节。

### 数据与页面边界

`DungeonsView.vue` 先读取 `data/parsed/dungeons.json` 摘要，打开关卡后按需读取 `data/parsed/dungeons/{battleId}.json`。摘要不嵌入全部房间和路线详情，也不在浏览器重新加载原始配置。构建期由 `instance.json`、副本战斗/房间/路线提取表、`reward`、`consume`、采集表、怪物和物品表生成。

页面筛选使用 `map`、`q`；`battle` 打开关卡详情。物品来源可附加 `drop`、`dropTab=settlement|first|rooms` 和 `dropEntry` 定位奖励区或房间条目，旧 `chest` 定位保持兼容。关闭详情应保留筛选和外层滚动位置。

### 路线、房间与效果

路线图使用提取的节点坐标、连线、起点/终点和布局概率。节点只展示配置明确提供的战斗、事件、宝箱、采集和掉落；同一节点存在多个候选房间时标明候选数量，不把候选当作必然遭遇。地图不拦截普通滚轮，交由详情内部滚动容器处理；Ctrl/Meta+滚轮阻止默认事件并缩放，拖动和触摸平移由 `DungeonRouteMap` 管理。

房间详情按配置显示逐波怪物、NPC、采集实体、自动掉落和结构化效果。多波战斗保留“第 N 波”，不跨波合计；房间 `layer` 是布局索引，不显示为玩家楼层；内部 ID、制作描述和无法证明的连接关系不作为用户文案。重复采集实体合并为“名称 ×数量”。女神房、泉水房等效果来自提取的结构化配置，不只显示房间名。

### 掉落与来源定位

- 房间采集沿 `spObj.caijiTypeId → roomCollect → roomCollectType → reward` 关联，不能用场景对象 ID 直接查奖励。
- `mode:equip` 保留具体装备、品质、等级和奖励组概率，可建立固定装备来源；`mode:equipGroup` 只是随机池，按 `showItemTypeId/qualityGroup` 展示并允许查看对应物品，不能反推其为实际固定产物。
- 通关、首次通关、BOSS、金银铜箱和房间奖励按实际配置归类；随机路线重复引用同一奖励组不叠加概率。
- 正文按物品 ID 去重并按品质展示；“3boos大”等内部池名称不是物品，不参与搜索。缺少配置证明时显示配置未注明，不猜测奖励。
- 副本来源由 `parsed-dungeon-sources.json` 合并进 `item-sources.json`。详情只消费简短说明和 `type/id/name/des/dropTab/dropEntry` 定位字段，完整规则留在构建产物与本专题。

### 展示与维护

- 特殊、结算、预览掉落默认折叠，首通奖励直接显示；来源直达展开对应区域，`rooms` 同步房间及候选，箱子按金银铜排序。
- `showReward` 标为“副本预览掉落”，只与当前关卡结算/BOSS 实际掉落链交叉匹配，未知显示“预览配置未注明”，不能按同名补造宝箱来源。关卡和采集消耗显示真实体力/货币/物品，不显示 consume ID。
- 原始停用项保留、运行时过滤。未停用的“大扫除/回忆/测试”及 `sldsd_*` 入口归剧情区；混合矿坑配置 `dungeonD` 不纳入标准卡片。正式副本为零的地图不显示，每张可见卡保留剧情栏，空剧情显示禁用入口。
- 同图不同关卡必须按各自路线引用显示宝箱，不把前段铜箱补进后段或噩梦。房间名等于内部编号时按实际类型兜底，不展示配置制作描述。
- 路线提取用 `scripts/parse/extractDungeonRoutes.mjs`，不由普通构建自动执行；女神/泉水结构化效果用 `npm run data:dungeons:effects` 维护，再构建副本。详情按关卡会话缓存，构建报告最大文件大小作优化提示，不设固定体积失败阈值。
- 封面近视口才加载，保持尺寸占位，不为加载优化重编码原图。提取输入不得裁剪覆盖完整 `battle/room`；验证按关卡检查路线、波次、采集外键、效果、来源定位与返回位置。
