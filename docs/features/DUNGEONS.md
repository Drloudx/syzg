# 副本图鉴

## 数据与页面边界

`DungeonsView.vue` 先读取 `data/parsed/dungeons.json` 摘要，打开关卡后按需读取 `data/parsed/dungeons/{battleId}.json`。摘要不嵌入全部房间和路线详情，也不在浏览器重新加载原始配置。构建期由 `instance.json`、副本战斗/房间/路线提取表、`reward`、`consume`、采集表、怪物和物品表生成。

页面筛选使用 `map`、`q`；`battle` 打开关卡详情。物品来源可附加 `drop`、`dropTab=settlement|first|rooms` 和 `dropEntry` 定位奖励区或房间条目，旧 `chest` 定位保持兼容。关闭详情应保留筛选和外层滚动位置。

## 路线、房间与效果

路线图使用提取的节点坐标、连线、起点/终点和布局概率。节点只展示配置明确提供的战斗、事件、宝箱、采集和掉落；同一节点存在多个候选房间时标明候选数量，不把候选当作必然遭遇。地图不拦截普通滚轮，交由详情内部滚动容器处理；Ctrl/Meta+滚轮阻止默认事件并缩放，拖动和触摸平移由 `DungeonRouteMap` 管理。

房间详情按配置显示逐波怪物、NPC、采集实体、自动掉落和结构化效果。多波战斗保留“第 N 波”，不跨波合计；房间 `layer` 是布局索引，不显示为玩家楼层；内部 ID、制作描述和无法证明的连接关系不作为用户文案。重复采集实体合并为“名称 ×数量”。女神房、泉水房等效果来自提取的结构化配置，不只显示房间名。

## 掉落与来源定位

- 房间采集沿 `spObj.caijiTypeId → roomCollect → roomCollectType → reward` 关联，不能用场景对象 ID 直接查奖励。
- `mode:equip` 保留具体装备、品质、等级和奖励组概率，可建立固定装备来源；`mode:equipGroup` 只是随机池，按 `showItemTypeId/qualityGroup` 展示并允许查看对应物品，不能反推其为实际固定产物。
- 通关、首次通关、BOSS、金银铜箱和房间奖励按实际配置归类；随机路线重复引用同一奖励组不叠加概率。
- 正文按物品 ID 去重并按品质展示；“3boos大”等内部池名称不是物品，不参与搜索。缺少配置证明时显示配置未注明，不猜测奖励。
- 副本来源由 `parsed-dungeon-sources.json` 合并进 `item-sources.json`。详情只消费简短说明和 `type/id/name/des/dropTab/dropEntry` 定位字段，完整规则留在构建产物与本专题。

## 展示与维护

- 特殊、结算、预览掉落默认折叠，首通奖励直接显示；来源直达展开对应区域，`rooms` 同步房间及候选，箱子按金银铜排序。
- `showReward` 标为“副本预览掉落”，只与当前关卡结算/BOSS 实际掉落链交叉匹配，未知显示“预览配置未注明”，不能按同名补造宝箱来源。关卡和采集消耗显示真实体力/货币/物品，不显示 consume ID。
- 原始停用项保留、运行时过滤。未停用的“大扫除/回忆/测试”及 `sldsd_*` 入口归剧情区；混合矿坑配置 `dungeonD` 不纳入标准卡片。正式副本为零的地图不显示，每张可见卡保留剧情栏，空剧情显示禁用入口。
- 同图不同关卡必须按各自路线引用显示宝箱，不把前段铜箱补进后段或噩梦。房间名等于内部编号时按实际类型兜底，不展示配置制作描述。
- 路线提取用 `scripts/parse/extractDungeonRoutes.mjs`，不由普通构建自动执行；女神/泉水结构化效果用 `npm run data:dungeons:effects` 维护，再构建副本。详情按关卡会话缓存，构建报告最大文件大小作优化提示，不设固定体积失败阈值。
- 封面近视口才加载，保持尺寸占位，不为加载优化重编码原图。提取输入不得裁剪覆盖完整 `battle/room`；验证按关卡检查路线、波次、采集外键、效果、来源定位与返回位置。
