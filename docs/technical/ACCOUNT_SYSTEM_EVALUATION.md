## 一、用户想要什么

评论目前是**本机身份**（昵称 + 头像存 localStorage，`utils/identity.js`）：
不注册、不登录、不跨设备同步，也**防不了冒充**（谁都能把昵称设成你的名字）。

用户希望升级为**真账号**：邮箱注册 + 改密码 + 能验证身份（"感觉可以做"）。
评论功能本身已经可用，这是**增强**而非阻塞项，所以排在后面。

## 二、三条路线与成本对比

| | A. 托管认证（Supabase / Clerk / Auth0） | B. 自己实现（Workers + D1 + 邮件服务） | C. 邮箱验证码登录（无密码） |
| --- | --- | --- | --- |
| 密码哈希 | 对方做（不受 CPU 限制） | **受 Workers 10ms CPU 限制** | 不需要 |
| 忘记密码 / 改密码 | 对方现成提供 | 全部自己写 | **概念不存在**（重发验证码即可） |
| 开发量 | 约 1~2 天 | 约 4~7 天 | 约 2~3 天 |
| 新增外部依赖 | 1 个（认证服务） | 2 个（邮件服务 + 防滥用） | 1 个（邮件服务） |
| 用户数据在哪 | 在对方 | 全在自己库 | 全在自己库 |
| 月费用 | 0 元（免费额度内） | 0 元 | 0 元 |

**推荐顺序：C > A > B**。
C（邮箱验证码）顺手消灭了"忘记密码"这个需求本身，是最省事的一条；
若坚持要密码，走 A 让专业服务做密码学，我们只存用户资料映射。

## 三、🔴 必须先解决的技术坎：10ms CPU

Workers 免费版每次调用只有 **10ms CPU**（等网络不算）。实测 PBKDF2-SHA256：

| 迭代次数 | 耗时 | 结论 |
| --- | --- | --- |
| 10,000 | 2.5ms | ✅ 安全但**远低于推荐值** |
| 100,000 | 18.7ms | ❌ 超限 |
| **600,000（OWASP 现行推荐）** | **104ms** | ❌ 超 10 倍 |

**结论：自己实现邮箱+密码，必然要把哈希强度压到远低于安全推荐值**——这是实质妥协，
不是"麻烦"。绕开办法：托管认证（A）或不用密码（C）。

## 四、发信方案（已核实，2026-10-02）

### 4.1 为什么不能"直接用我的邮箱密码"

| 问题 | 说明 |
| --- | --- |
| **Workers 封禁 25 端口** | Cloudflare 官方原文：`Workers cannot create outbound TCP connections on port 25`。必须用 587/465 |
| **IP 信誉** | Workers 出口 IP 来自不对外公布的共享 IP 池，收信方易判垃圾 |
| **🔴 国内邮箱异地登录风控** | QQ/163 对"新地点登录"会拦截，而 Workers 出口 IP 每次可能不同 → **反复被拦，甚至锁号**，会持续复发 |

用户提到"自己项目做过连发 100 封、间隔 5 秒没问题"——那条通道是通的，**瓶颈在频率与
登录地点风控**，不在能不能连上。

### 4.2 云厂商邮件推送（推荐路线）

**两家都要求绑定并验证自己的域名**（配 SPF/DKIM DNS 记录），**不能直接用个人邮箱账号**。
好处是走 **HTTP API 发信**，因此**绕开了上面的端口封禁与 IP 信誉问题**。

#### 腾讯云 邮件推送 SES

来源：[官方价格说明](https://cloud.tencent.com/document/product/1288/47930)（核实于 2026-10-02）

| 项目 | 数值 |
| --- | --- |
| 免费额度 | 每个账号 **1000 封**，**不限有效期、用完为止** |
| 超出后 | 日结后付费，**0.0019 元/封** |
| 独立 IP（可选） | 900 元/个/月，每月最多 3 个 |

#### 阿里云 邮件推送 DirectMail

来源：[官方计费页](https://help.aliyun.com/zh/direct-mail/billing-methods)（核实于 2026-10-02）

| 项目 | 数值 |
| --- | --- |
| 免费额度 | 每个主账户 **共 2000 封**，**每天最多免费发 200 封** |
| 按量单价 | **2 元 / 1000 封** |
| 资源包（6 个月有效） | 1 万封 ¥19.98 / 5 万封 ¥90 / 50 万封 ¥840 / 100 万封 ¥1590 |

> ⚠️ **两家的免费额度都是"一次性总量"，不是每天/每月刷新**——极易误解，已逐字核对原文。
> 阿里云的"每天 200"是**限速上限**，不是每日刷新额度。

### 4.3 用量是否够

事务邮件（注册验证、密码重置）个人站一天几条到几十条。
腾讯云 1000 封按每天 5 封可用约 200 天；之后 0.0019 元/封，一年成本几元。
**额度不是瓶颈。**

### 4.4 其他可选项

- **Resend**：第三方技术文提到免费每天 100 封（**非官方来源，未经核实**）。
- **企业邮箱**（腾讯/阿里企业邮）：自建 SMTP 路线里最靠谱的，支持 587/465 且有 SPF/DKIM 配置项。

## 五、实施前需用户确认（阻塞项）

1. **愿意为 `yxzmy.top` 加 DNS 验证记录吗？**（DNSPod 控制台，SPF/DKIM/CNAME 几条）
   - 愿意 → 推荐**腾讯云 SES**（免费不限有效期 + 单价更低 + 域名与 DNS 都在腾讯云）
   - 不愿意 → 只剩"个人邮箱 SMTP 直连"，要接受异地登录风控与垃圾箱风险
2. **要密码，还是只要邮箱验证码？**（决定走 A/C 还是 B）
3. **谁维护用户数据**：接受把用户资料放托管服务（A），还是必须全在自己 D1 里（B/C）？

## 六、与现有评论体系的关系（迁移路径）

好消息：**现有评论数据不用重建**。`comments` 表已有 `nick` / `avatar` / `page_label`，
加账号只需：

1. 新增 `users` 表（`id` / `email` / `email_hash` / 密码哈希或空 / `nick` / `avatar` / `created_at`）；
2. `comments` 加 `user_id` 外键（可空——历史匿名评论保持 `null`，仍然显示）；
3. 前端 `utils/identity.js` 从"纯 localStorage"升级为"已登录走服务端，未登录走本机身份"。

**本机身份不删除**：没账号的人继续匿名评论，这是现有已上线行为，不要因为加账号而回退。

## 七、非技术成本（比开发量更值得先想）

存了用户邮箱就承担**个人信息保护义务**：隐私政策、删除请求响应、泄露风险。
这是从"纯静态工具站"上台阶到"有用户数据的服务"，性质变化比工作量更大。

## 八、如果决定实施，建议的第一步

**先做 ≤20 行的发信最小验证**（不改现有代码，只加一个临时接口）：

1. 用腾讯云 SES 的控制台创建发信域名 + 发一封测试邮件；
2. 确认**落收件箱还是垃圾箱**；
3. 确认连续发 5 封不被限流。

跑通这一步再谈账号实现——发信不通，后面全都白做。
