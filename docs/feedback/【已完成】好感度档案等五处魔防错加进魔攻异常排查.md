## 一、 问题总览

`HeroBattleAttributeGroup.cs` 中共有 **5 处**复制粘贴错误：读取固定数值魔法防御 `magicDef` 时，累加/赋值目标误写成了魔法攻击字段（`*_magicAtk`），导致对应养成或套装中的固定魔防加成**完全不涨魔防，反而等额加到魔攻面板上**。

| 序号 | 所属模块 | 源码位置 | 当前 1.7.15 配置触发状态 | 实际影响 | 严重程度 |
| --- | --- | --- | --- | --- | --- |
| 1 | **好感度档案（`AddArchiveAttribute`）** | `HeroBattleAttributeGroup.cs` 第 1082~1085 行 | **已大范围触发**：`heroArchives.json` 共 **45** 名英雄中 **43** 名在好感 45 级配了 `magicDef: 500` | 好感达到 45 级后，本应增加的 **+500 魔防全部错加为 +500 魔攻**，魔防 0 收益 | **高** |
| 2 | **装备套装（`AddEquipSuitAttribute`）** | `HeroBattleAttributeGroup.cs` 第 1395~1398 行 | 当前套装均配在 `magicDefPer` 百分比分支（第 1479~1482 行正常），暂无固定 `magicDef` | 只要后续套装效果使用固定 `magicDef`，同样会错加为 `equipSuit_magicAtk` | **中（隐患）** |
| 3 | **星阶被动（`AddHeroStarSkillAttribute`）** | `HeroBattleAttributeGroup.cs` 第 777~780 行 | 当前星阶被动未配固定 `magicDef`（暂未触发） | 若星阶被动新增固定 `magicDef`，会错加为 `heroStarSkill_magicAtk` 且零收益魔防 | **中（隐患）** |
| 4 | **职业潜能（`AddPotentialAttribute`）** | `HeroBattleAttributeGroup.cs` 第 954~957 行 | 当前 `potential.json` 未配 `magicDef`（暂未触发） | 若潜能节点后续新增固定 `magicDef`，会错加为 `heroPotential_magicAtk` | **低（隐患）** |
| 5 | **家园家具（`AddHomeLevelAttribute`）** | `HeroBattleAttributeGroup.cs` 第 1173~1176 行 | 当前 `homeLevel.json` 无非零 `magicDef`（暂未触发） | 更危险的**直接覆盖 `=`**：一旦家园配出 `magicDef`，会直接覆盖掉已有 `heroHomeLevel_magicAtk` | **中（隐患）** |

> 注：百分比魔防字段（`heroStarSkill_magicDefPer`、`equipSuit_magicDefPer`、`campResearch_magicDefPct`）以及普通装备/附魔词条读取的 `equip_magicDef` 均写入正确，不受这 5 处 Bug 影响。

## 二、 实测现象对照：46 级与 50 级无装备德莉面板反常

在角色属性界面（`HeroAttributeUI.cs` 直接读取 `HeroBattleAttributeGroup.GetAttrValue()`）实测两位满星、全卸装备德莉的数据如下：

| 属性项 | 50 级德莉（默认皮，好感未达 45） | 46 级德莉（糖果皮，好感已满 45+） | 差值（46 级 − 50 级） | 是否反常 |
| --- | --- | --- | --- | --- |
| 生命值 | `9703` | `8625` | `-1078` | 正常（等级低 4 级） |
| 物理攻击 | `1753` | `1647` | `-106` | 正常（等级低 4 级） |
| **魔法攻击** | **`3126`** | **`3390`** | **`+264`** | **异常反超** |
| **物理防御** | **`848`** | **`1334`** | **`+486`** | **同步多出约 500**（档案正常兑现） |
| **魔法防御** | **`1091`** | **`1003`** | **`-88`** | **反而更低**（魔防 500 被吞） |

对照 `heroArchives.json` 中德莉好感度 45 级档案条目 `hero_060_9`（「海纳百川的王国」）：

```json
{
  "typeId": "hero_060_9",
  "unlockFavValue": 45,
  "unitData": { "phyDef": 500, "magicDef": 500 }
}
```

* 物防侧：代码写对了 `heroArchive_phyDef += unitData.phyDef`，因此 46 级德莉正常拿到 `+500` 物防，抵消 4 级等级差后净高出 `486`；
* 魔防与魔攻侧：代码将 `unitData.magicDef` 错加进 `heroArchive_magicAtk`，导致 **46 级德莉魔防不仅没拿到 +500，反而因少 4 级成长低于 50 级（`1003 < 1091`）**，而错位转正的 **`+500` 固定魔攻**直接抹平 4 级成长与部分研究差，造成低 4 级却魔攻反超 `264` 的怪象。

## 三、 5 处 `magicDef` 错加进 `magicAtk` 源码定位与修改建议

### 1. 好感度档案：`AddArchiveAttribute` 将 +500 魔防全算成 +500 魔攻（已触发，波及 43 名角色）

* **游戏内表现**  
  角色好感度达到 45 级解锁最后一条双防属性档案时，面板**物理防御正常 +500、魔法防御纹丝不动，魔法攻击却凭空暴涨 +500**。全表 **45** 名英雄中 **43** 名的 45 级档案均配置了 `{ "magicDef": 500 }`，且全部命中该错误分支；包括纯物理输出角色在内，只要好感度刷到 45 级就会白白多出 500 面板魔攻、少 500 魔防。

* **原因定位**  
  ```csharp
  // HeroBattleAttributeGroup.cs 第 1078~1085 行（AddArchiveAttribute）
  if (unitData.phyDef != 0f)
  {
      heroArchive_phyDef += unitData.phyDef;
  }
  if (unitData.magicDef != 0f)
  {
      heroArchive_magicAtk += unitData.magicDef; // ← 错写成 heroArchive_magicAtk，应为 heroArchive_magicDef
  }
  ```

* **修改建议**：将 `HeroBattleAttributeGroup.cs` 第 1084 行改为 `heroArchive_magicDef += unitData.magicDef;`。

---

### 2. 装备套装：`AddEquipSuitAttribute` 固定魔防加成写进套装魔攻（隐患）

* **游戏内表现**  
  当前 1.7.15 的 4 个防御型套装技能（`suit_312`、`suit_331`、`suit_512`、`suit_531`）配置的是百分比 `magicDefPer`，走第 1479~1482 行的正确分支，暂未暴露问题。但若后续新装备套装配置固定数值 `magicDef`（`skillType == 0` 的静态属性套装），穿齐套装后同样只会增加角色魔攻而不加魔防。

* **原因定位**  
  ```csharp
  // HeroBattleAttributeGroup.cs 第 1391~1398 行（AddEquipSuitAttribute）
  if (passiveSkillAttribute.phyDef != 0f)
  {
      equipSuit_phyDef += passiveSkillAttribute.phyDef;
  }
  if (passiveSkillAttribute.magicDef != 0f)
  {
      equipSuit_magicAtk += passiveSkillAttribute.magicDef; // ← 错写成 equipSuit_magicAtk，应为 equipSuit_magicDef
  }
  ```

* **修改建议**：将 `HeroBattleAttributeGroup.cs` 第 1397 行改为 `equipSuit_magicDef += passiveSkillAttribute.magicDef;`。

---

### 3. 星阶被动：`AddHeroStarSkillAttribute` 固定魔防错加进星阶魔攻（隐患）

* **游戏内表现**  
  目前星阶静态被动（`paSkillList` 中 `starSkill*`）尚未配置固定 `magicDef`，暂未触发；但源码分支已存在相同错位写法，且同方法配套的初始化函数 `InitHeroStarSkillArribute()` 第 880、882、885 行连续写了 3 次 `heroStarSkill_magicAtk = 0f;`（无害冗余）。

* **原因定位**  
  ```csharp
  // HeroBattleAttributeGroup.cs 第 773~780 行（AddHeroStarSkillAttribute）
  if (passiveSkillAttribute.phyDef != 0f)
  {
      heroStarSkill_phyDef += passiveSkillAttribute.phyDef;
  }
  if (passiveSkillAttribute.magicDef != 0f)
  {
      heroStarSkill_magicAtk += passiveSkillAttribute.magicDef; // ← 错写成 heroStarSkill_magicAtk，应为 heroStarSkill_magicDef
  }
  ```

* **修改建议**：将 `HeroBattleAttributeGroup.cs` 第 779 行改为 `heroStarSkill_magicDef += passiveSkillAttribute.magicDef;`，并清理第 880~885 行重复的 `heroStarSkill_magicAtk = 0f;` 初始化语句。

---

### 4. 职业潜能：`AddPotentialAttribute` 固定魔防错加进潜能魔攻（隐患）

* **游戏内表现**  
  当前 `potential.json` 中尚未配置 `magicDef` 属性（暂未触发）；若后续版本开放含固定魔防的潜能节点，点亮后将变成增加角色魔攻、魔防无效。

* **原因定位**  
  ```csharp
  // HeroBattleAttributeGroup.cs 第 950~957 行（AddPotentialAttribute）
  if (unitData.phyDef != 0f)
  {
      heroPotential_phyDef += unitData.phyDef;
  }
  if (unitData.magicDef != 0f)
  {
      heroPotential_magicAtk += unitData.magicDef; // ← 错写成 heroPotential_magicAtk，应为 heroPotential_magicDef
  }
  ```

* **修改建议**：将 `HeroBattleAttributeGroup.cs` 第 956 行改为 `heroPotential_magicDef += unitData.magicDef;`。

---

### 5. 家园家具：`AddHomeLevelAttribute` 用 `magicDef` 直接覆盖 `heroHomeLevel_magicAtk`（隐患）

* **游戏内表现**  
  当前 `homeLevel.json` 仅料理台（`cook`）配了 `maxHp` 加成，无非零 `magicDef`（暂未触发）。此处比前 4 处多了一层危害：它使用的是赋值符号 `=` 而非 `+=`，一旦家具属性出现 `homeLevelAttr.magicDef != 0f`，不仅不加魔防，还会**把前面第 1167 行刚赋上去的 `heroHomeLevel_magicAtk` 直接覆盖成 `magicDef` 数值**。

* **原因定位**  
  ```csharp
  // HeroBattleAttributeGroup.cs 第 1165~1176 行（AddHomeLevelAttribute）
  if (homeLevelAttr.magicAtk != 0f)
  {
      heroHomeLevel_magicAtk = homeLevelAttr.magicAtk;
  }
  if (homeLevelAttr.phyDef != 0f)
  {
      heroHomeLevel_phyDef = homeLevelAttr.phyDef;
  }
  if (homeLevelAttr.magicDef != 0f)
  {
      heroHomeLevel_magicAtk = homeLevelAttr.magicDef; // ← 错写且直接覆盖 heroHomeLevel_magicAtk，应为 heroHomeLevel_magicDef
  }
  ```

* **修改建议**：将 `HeroBattleAttributeGroup.cs` 第 1175 行改为 `heroHomeLevel_magicDef = homeLevelAttr.magicDef;`。
