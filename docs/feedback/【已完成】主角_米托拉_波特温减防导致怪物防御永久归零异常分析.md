## 一、 问题概述

在游戏战斗中，当队伍中编入具备破甲/减防机制的角色——**主角（希尔）**、**米托拉** 与 **波特温** 时，受影响怪物的物理防御（以及魔法防御）会出现不可逆的永久扣减：

1. **防御力逐轮暴跌**：即使减防 Buff 的持续时间结束（图标消失），怪物的防御力也无法恢复至初始值，而是在每次施法循环中呈几何级数流失；
2. **极速清零**：在主角、米托拉与波特温三人连续施法数轮后，怪物的防御力会被彻底削减至 **0**，受到的物理伤害完全变为无视护甲的真实伤害；
3. **怪物自身增防机制彻底瘫痪**：当怪物的防御力归零后，怪物/Boss 释放自身的任何防御增益技能（例如精英怪增防 50%、Boss 狂暴护甲强化等），其实际有效防御力**依然锁死在 0，完全无法提升**。

## 二、 复现条件与步骤

### 1. 必要前置条件
1. **主角（希尔）**：达到 3 星，激活天赋【大巧不工】（`5029` / `5032`，1 技能降低目标 15%~30% 物理与魔法防御）；
2. **米托拉**：达到 2 星，激活天赋【落幕之殇】（`new00206` / `5032_0001`，2 技能终结一击降低目标 15%~25% 物理与魔法防御）；
3. **波特温**：达到 2 星，激活天赋【酸蚀毒雾】（`03106` / `hero031Star2AddBuff`，2 技能降低目标 20%~35% 物理防御）。

### 2. 触发过程
1. 进入任意高防御怪物关卡或 Boss 战，记录怪物受击初始伤害。
2. 战斗开始后，波特温释放 2 技能【毒雾箭头】施加酸蚀毒雾。
3. 紧接着主角释放 1 技能【重锤眩晕】、米托拉释放 2 技能【落幕之舞】终结一击。
4. 等待 8~10 秒，直至三名角色施加的减防 Debuff 图标全部自然消失。
5. 再次让角色对怪物进行攻击，观察伤害数值：
   - 怪物的防御力并未恢复到战前水平，造成的伤害显著高于战前基准；
   - 随技能循环进行 4~8 轮后，物理攻击伤害跳字达到理论真实伤害上限（防御减免系数降至 0）；
   - 若怪物此时释放“防御力提升 50%”等增益技能，观察伤害跳字，伤害数值未出现任何衰减，怪物增防完全无效。

## 三、 代码底层根因分析

排查客户端底层逻辑发现，该现象是由**「属性 Setter 误将结果写入底层白值」**、**「波特温百分比减防被意外固化」** 与 **「回退公式存在乘积衰减漏洞」** 共同作用导致的严重连锁：

### 1. 致命缺陷一：属性 Setter 误写，直接篡改怪物的「永久底层白值」

在客户端属性系统 `UnitAttribute.cs` 中，怪物的物理防御 `phyDef` 为属性包装器（Property）：

```csharp
// UnitAttribute.cs 第 278~288 行
public float phyDef
{
    get
    {
        // 实际有效防御 = 固定值加成 + 基础白值 * (1 + 百分比增减)
        return phyDefAddNum + PhyDef * (1f + phyDefAdd);
    }
    set
    {
        // 关键点：setter 写入的是怪物的底层基础属性字段 PhyDef！
        PhyDef = value;
    }
}
```

而**主角 3 星天赋**与**米托拉 2 星天赋**共用了同一脚本 `Buff_Xier_LevelStar3_def.cs`：

```csharp
// Buff_Xier_LevelStar3_def.cs 第 18~23 行
public override void StartAction()
{
    base.StartAction();
    target.unitData.phyDef += target.unitData.phyDef * float.Parse(para["value"].ToString());
    target.unitData.magicDef += target.unitData.magicDef * float.Parse(para["value"].ToString());
}
```

* **逻辑分析**：在 C# 中，`target.unitData.phyDef += X` 展开等价于：  
  `target.unitData.phyDef = target.unitData.phyDef + X;`
* **实际影响**：
  - 等号右侧读取 getter，取出了包含所有百分比修正后的**当前有效防御**；
  - 运算完成后，等号左侧执行 setter，**直接将计算后的最终值覆盖到了怪物的底层永久字段 `PhyDef`**；
  - 从而使临时状态直接破坏了实体的基础原始白值。

---

### 2. 致命缺陷二：波特温临时百分比减防被“烙印”为怪物的永久白值损失

* 波特温 2 星天赋生成的减防 Buff（`hero031Star2AddBuff`）采用的是规范的 `Buff_AttributeAdd.cs`，它修改的是百分比加成字段：  
  `target.unitData.phyDefAdd += -0.2`（或满级 `-0.35`）；
* 当波特温命中怪物时，怪物通过 getter 计算得到的实际物理防御为 `PhyDef * (1 - 0.2) = 0.8 * PhyDef`；
* 此时若主角或米托拉的技能命中怪物：
  - `Buff_Xier_LevelStar3_def.cs` 右侧读取到的基数已经是被波特温削减过后的 `0.8 * PhyDef`；
  - 再次减去 15% 后，计算结果为 `0.8 * 0.85 * PhyDef = 0.68 * PhyDef`；
  - 该结果被 setter 直接赋值给了 `PhyDef`！
* **后果**：波特温原本属于临时生效 8 秒的 20% 减防，被主角/米托拉的脚本**永久写死进了怪物的基础属性中**。即使 8 秒后波特温的 Buff 正常消散（`phyDefAdd` 恢复为 0），怪物的白值防御也已经被不可逆地剥夺了。

---

### 3. 致命缺陷三：`EndAction()` 回退算法存在数学逻辑错误，单人每轮也必永久缩水

在 `Buff_Xier_LevelStar3_def.cs` 中，Buff 结束时的卸载算法设计如下：

```csharp
// Buff_Xier_LevelStar3_def.cs 第 30~35 行
public override void EndAction()
{
    base.EndAction();
    target.unitData.phyDef -= target.unitData.phyDef * float.Parse(para["value"].ToString());
    target.unitData.magicDef -= target.unitData.magicDef * float.Parse(para["value"].ToString());
}
```

以基础防御 $100$、减防 $15\%$（`value = -0.15`）进行数学推导：
1. **施加时（`StartAction`）**：  
   $\text{PhyDef} = 100 + 100 \times (-0.15) = 85$
2. **结束时（`EndAction`）**：  
   代码并非将原本扣除的 $15$ 点加回，而是使用**当前缩水后的 $85$ 点**乘以 $0.15$ 进行恢复：  
   $\text{PhyDef} = 85 - 85 \times (-0.15) = 85 + 12.75 = \mathbf{97.75}$！
3. **单轮损失**：单次 Buff 循环怪物便**永久损失 $2.25\%$ 的基础防御**；
4. 若主角达到 4 星（减防 30%）：$0.70 \times 1.30 = 0.91$，**单次 Buff 结束就会直接蒸发 9% 的防御白值**！
5. 此外，主角与米托拉的减防 Buff 在配置表中类型相同（`buffType: ""`），互相施放时会频繁触发 `RemoveOldBuff` 与提前 `BuffOver`，使该错误回退在高频交替中被连续执行，导致防御力加速崩解。

---

### 4. 为什么防御归零后，怪物自身的所有防御增益技能彻底失效？

游戏内所有怪物/Boss 的防御增益技能（如护甲强化、狂暴体质等），在客户端代码中均是通过百分比加成（`phyDefAdd` 或 `Buff_AttributeAdd`）实现的：

$$\text{最终有效防御} = \text{phyDefAddNum} + \mathbf{PhyDef} \times (1 + \text{phyDefAdd})$$

* 当怪物的底层基础防御力 $\mathbf{PhyDef}$ 经历数轮削弱归零（$\mathbf{PhyDef} = 0$）后：
* 无论怪物的技能为自己增加多少百分比防御（即使 $+50\%$、$+100\%$ 乃至 $+500\%$）：  
  $$\mathbf{0} \times (1 + 500\%) = \mathbf{0}$$
* **乘数项为 0，无论百分比增益多大，计算结果依然恒为 0**！怪物防御力被永久封死在 0，再也无法通过自身机制提升。

## 四、 供参考的排查与处理方向

可参考以下解决思路：

### 方向一：规范减防机制，改用标准的百分比加成字段
主角与米托拉的减防逻辑无需单独操作 `target.unitData.phyDef`，可直接复用成熟的 `Buff_AttributeAdd.cs`（同波特温及其他常规减防角色）或修改 `phyDefAdd` 字段：
* 减防生效时：`target.unitData.phyDefAdd += value;`
* 减防结束时：`target.unitData.phyDefAdd -= value;`
* 优点：仅在计算层做百分比减扣，生命周期结束严格归零，绝不触碰和污染底层 `PhyDef` 基础白值。

### 方向二：若保留独立脚本，修正加减值记录机制
若需维持 `Buff_Xier_LevelStar3_def.cs` 独立运作：
* 在 `StartAction()` 中记录当时扣除的具体数值：
  ```csharp
  private float reducedPhyDef;
  private float reducedMagDef;
  
  public override void StartAction()
  {
      base.StartAction();
      reducedPhyDef = target.unitData.PhyDef * float.Parse(para["value"].ToString());
      reducedMagDef = target.unitData.MagicDef * float.Parse(para["value"].ToString());
      target.unitData.PhyDef += reducedPhyDef;
      target.unitData.MagicDef += reducedMagDef;
  }
  ```
* 在 `EndAction()` 中精确恢复该数值：
  ```csharp
  public override void EndAction()
  {
      base.EndAction();
      target.unitData.PhyDef -= reducedPhyDef;
      target.unitData.MagicDef -= reducedMagDef;
  }
  ```

### 方向三：完善 `UnitAttribute` 的 Setter 防呆与基础属性保护
在 `UnitAttribute.cs` 中增加安全机制：
* 避免外部脚本直接通过 `phyDef` 属性 setter 覆盖底层未加成字段 `PhyDef`；
* 为基础防御设置合法下限或记录原始初始值，防止在异常连乘后属性归零锁死。
