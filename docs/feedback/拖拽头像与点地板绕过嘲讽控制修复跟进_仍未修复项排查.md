## 二、 漏检源码精确定位

### 1. 通用门禁 `Unit.CanMove`（`Unit.cs` 第 450~460 行）

```csharp
public bool CanMove
{
    get
    {
        if (!isDieOrNearDie && noMove == 0 && !inSkill && !confusion && !isInCollecting) // ❌ 写了 !confusion，未写 !HasRidicule
        {
            return !unitMove.navAgent.isPause;
        }
        return false;
    }
}
```

### 2. 拖拽头像 / 场景拖线入口与指令缓存

`MoveControllerUI.LineEndMove()`（第 1214 行）调用 `dragUnit.DragMove(...)`，而 `Unit.DragMove()`（第 3129~3333 行）三个分支均直接暂停 AI 并改写目标/清空 `target` 寻路，最后仅判断 `if (CanMove)`：

```csharp

if (RaycastHit2D.op_Implicit(hitMon))                         // ① 拖到其他怪物：第 3178~3181 行
{
    UnitAiControl.instance.PauseAI(this);
    target = ...;                                             // ❌ 强行改写为非嘲讽怪物
    lockTarget = true;
    ...
}
else if (Object.op_Implicit((Object)(object)interTemp) && ...) // ② 拖到采集物/倒地队友：第 3260~3261 行
{
    UnitAiControl.instance.PauseAI(this);
    target = null;                                            // ❌ 清空嘲讽目标去采集/救援
    ...
}
else                                                          // ③ 拖到空地：第 3307~3308 行
{
    UnitAiControl.instance.PauseAI(this);                     // 暂停 AI 期间跳过 NeedSetTarget
    target = null;                                            // ❌ 清空嘲讽目标并跑向 endPos
    ...
}
...
```

且 `Unit.Update()`（第 3358~3366 行）消费 `"drag"` 缓存时也仅检 `if (CanMove)`，技能结束后即使已被嘲讽仍会延迟执行缓存拖拽。

## 三、 修复建议

1. **拖拽入口与缓存**：在 `MoveControllerUI.LineEndMove()`（第 1214 行前）、`Unit.DragMove()`（第 3323 行）及 `Unit.Update()` 的 `"drag"` 缓存执行处（第 3360 行）补充 `!HasRidicule` 校验，嘲讽期间拦截拖拽起手/执行/缓存。
2. **点击地板入口与缓存**：将 `MoveControllerUI.cs` 第 468 行与 `Unit.cs` 第 3369 行 `"clickMove"` 缓存执行处的 `CanMove` 判断改为 `CanMove && !HasRidicule`（或统一抽离“玩家可控移动门禁”供摇杆、拖拽、点地板与指令缓存复用）。
