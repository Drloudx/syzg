## 一、 问题总览

| 序号 | 操作方式 | 游戏内实际表现 | 严重程度 |
| --- | --- | --- | --- |
| 1 | **嘲讽期间拖拽角色头像（或场景直接拖线）到空地** | **不会清除嘲讽 Buff 与禁技**，但能立刻打断角色对嘲讽者的追击与普攻，强行把人拉走风筝 | **高** |
| 2 | **嘲讽期间拖拽头像到其他怪物或采集物 / 倒地队友** | 可强行跑向非嘲讽怪物，或跑去触发采集 / 救援进入 `isInCollecting`，中断攻击嘲讽者 | **中~高** |

## 二、 根因：其余移动入口均已锁死嘲讽，唯独拖拽与点地板漏检

从源码可以确认，设计上原本明确要求**被嘲讽期间禁止玩家手动脱离**（并非故意保留的解控手段），但各入口校验写法不统一：

| 控制 / 移动入口 | 源码位置 | 是否拦截嘲讽（`HasRidicule`） | 实际表现 |
| --- | --- | --- | --- |
| 施加嘲讽瞬间 | `Buff_Ridicule.cs` 第 32~65 行 | **已拦截** | 强制调用 `UnitCollectReset()` 打断采集、置 `inJoyMoving = false` 打断摇杆并交回 AI |
| 虚拟摇杆移动 | `JoystickPanel.cs` 第 252 行 | **已拦截**（`unit.CanMove && !unit.HasRidicule`） | 被嘲讽时摇杆完全推不动 |
| 队友结束摇杆同步 | `BattleManager.cs` 第 697 行 | **已拦截**（检查 `moveUnit.HasRidicule`） | 不受摇杆跟队拉扯 |
| 职业 AI 走位 | `UnitAI.cs` 第 880 行 | **已拦截**（`!self.HasRidicule`） | 禁止自行拉扯站位 |
| **拖拽头像 / 场景拖线** | `CombatPanel.cs` 第 5887~5900 行<br>`MoveControllerUI.cs` 第 1214 行<br>`Unit.cs` 第 3110~3314 行 | **未拦截** | **直接进入 `DragMove()`**，改写目标或强制寻路移动 |
| **点击地板移动** | `MoveControllerUI.cs` 第 435~480 行 | **未拦截**（只检查 `unit2.CanMove`） | **直接暂停 AI 清空目标并寻路** |

问题出在通用门禁 `Unit.CanMove` 未纳入 `!HasRidicule`（而同为目标反转控制的混乱状态 `!confusion` 写在了里面）：

```csharp
// Unit.cs 第 450~460 行
public bool CanMove
{
    get
    {
        if (!isDieOrNearDie && noMove == 0 && !inSkill && !confusion && !isInCollecting) // ← 写了 !confusion，未写 !HasRidicule
        {
            return !unitMove.navAgent.isPause;
        }
        return false;
    }
}
```

## 三、 不同操作下的具体表现与修改建议

### 1. 拖拽角色头像或场景拖线：打断追击并强制走位 / 采集

* **游戏内表现**  
  角色中嘲讽后头顶依然挂着嘲讽图标且无法放技能，但玩家长按左上角角色头像（或在战斗画面直接拖住角色）拉线松手后：
  * **拖到空地**：角色立刻停手不再打嘲讽者，转头跑向拖放的空地；只要在抵达终点前不断重复拖线，就能全程带着角色绕场风筝。
  * **拖到其他怪物**：角色先朝拖中的非嘲讽怪物跑过去，走到射程停下后才在下一帧被 AI 拉回嘲讽者。
  * **拖到采集物 / 倒地队友**：角色会跑过去并进入采集或救援状态，期间完全停止攻击嘲讽者。

* **原因定位**  
  拖拽角色头像会通过 `SetPlayerUIItemDrag` 赋值 `MoveControllerUI.instance.dragUnit`，松手经 `LineEndMove()` 直接进入 `Unit.DragMove()`，三个分支均未检查 `HasRidicule`：
  ```csharp
  // Unit.cs 第 3150~3307 行（DragMove 内部）
  if (RaycastHit2D.op_Implicit(hitMon))                // ① 拖到其他怪物
  {
      UnitAiControl.instance.PauseAI(this);
      target = ...;                                    // ← 直接把 target 改写为非嘲讽怪物
      lockTarget = true;
      ...
  }
  else if (interTemp != null && ...)                   // ② 拖到采集物 / 倒地队友
  {
      UnitAiControl.instance.PauseAI(this);
      target = null;                                   // ← 清空嘲讽目标，走去 StartCollect()
      ...
  }
  else                                                 // ③ 拖到空地
  {
      UnitAiControl.instance.PauseAI(this);            // ← 暂停 AI（AI 暂停期间跳过 NeedSetTarget）
      target = null;                                   // ← 清空嘲讽目标并强制寻路到 endPos
      ...
  }
  ```
  跑路途中因 `unitAI.isPause == true`，`UnitAI`（第 421 行）会直接跳过索敌逻辑；直到走到终点执行 `ContinueAI()` 恢复 AI 后，才由 `AiTriggerManager.NeedSetTarget()`（第 236~240 行）重新拉回 `target = ridicule`。

* **修改建议**：
  1. 在 `MoveControllerUI.cs` 选中 `dragUnit` / `LineEndMove()` 入口及 `Unit.DragMove()` 头部增加 `!HasRidicule` 校验：角色处于嘲讽期间禁止拖拽拉线（直接拦截并提示，或禁止起手拉出引导线）；
  2. 同步在 `Unit.CheckDoCacheDirective()`（第 3339~3347 行）补上 `!HasRidicule` 判断，避免技能施放前缓存的 `"drag"` 指令在技能结束且已中嘲讽时被延迟放行。

### 2. 开启“点击地板移动”后直接点击地板：同样绕过嘲讽

* **游戏内表现**  
  系统设置打开“点击地板移动”（`dragOrClickMove`）后，即使角色正处于嘲讽控制下且虚拟摇杆推不动，直接点击地板依然会让当前主控角色中断攻击嘲讽者、立刻朝点击位置跑去。

* **原因定位**  
  ```csharp
  // MoveControllerUI.cs 第 435~480 行
  if (GameDataManager.clientData.systemData.dragOrClickMove && clickFloor && downUpDis <= 3f)
  {
      ...
      if (unit2.CanMove)   // ← 仅检查 CanMove，漏掉 !unit2.HasRidicule
      {
          action();        // ← 内部 PauseAI(unit2)、unit2.target = null 并寻路到点击点
      }
      else if (!unit2.isDieOrNearDie)
      {
          unit2.CacheDirectives.Add("clickMove", action); // ← Unit.cs 第 3348 行缓存执行也只检 CanMove
      }
  }
  ```

* **修改建议**：在 `MoveControllerUI.cs`（第 468 行）与 `Unit.cs`（第 3350 行 `"clickMove"` 缓存执行处）同步改为 `unit2.CanMove && !unit2.HasRidicule`（或评估将 `!HasRidicule` 直接并入单独的“玩家可控移动门禁”方法，统一供摇杆、拖拽、点地板与指令缓存复用）。
