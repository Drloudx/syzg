## 二、 嘲讽重叠、顶替与连锁失效问题

### 1. 近卫 1 秒小嘲讽到期，引发全队 6~8 秒长嘲讽连锁自杀

* **游戏内表现**  
  乌帕·萝特（2 技能 3/6 秒）或斯卡莉安（8 秒）刚嘲讽住 Boss，只要队伍里有任何**近卫职业**角色普攻触发职业被动「挑衅」（仅持续 1 秒），**1 秒一到，Boss 身上的长嘲讽会跟着近卫嘲讽一起全部消失**，Boss 立刻恢复自由索敌和放技能。

* **原因定位**  
  1. **两者“类型名”不同，所以同时挂在 Boss 身上**：  
     近卫被动（`HeroJob1Buff2`）挂的嘲讽类型名是 `"heroJob1Buff1_1"`（1 秒），而乌帕、斯卡莉安、菲娜等挂的是 `"taunt"`（3~8 秒）。`BuffControl.RemoveOldBuff()` 只会顶掉同类型 Buff，因此两个嘲讽实例会并存，但 `Unit.ridicule` 全局只有 **1 个位置**，被后挂的近卫覆盖：
     ```
     乌帕 6 秒嘲讽先挂上  → target.ridicule = 乌帕，target.noSkill = 1
     近卫 1 秒被动后触发  → target.ridicule = 近卫（覆盖），target.noSkill = 2
     ```
  2. **1 秒到期后，短嘲讽把全局字段抹空，长嘲讽下一帧集体自杀**：
     ```csharp
     // Buff_Ridicule.cs 第 75~88 行（近卫 1 秒到期时）
     target.ridicule = null;                // ← 不管上面还有没有其他嘲讽，直接置空！
     target.noSkill--;

     // Buff_Ridicule.cs 第 67~73 行（同帧/下一帧：乌帕还剩 5 秒的嘲讽在 Update 里轮询）
     private void Update()
     {
         if (!target.HasRidicule)           // ← 查唯一字段 target.ridicule，已是 null → 返回 false
         {
             BuffControl.instance.BuffOver(this); // ← 长嘲讽误以为目标已脱控，主动销毁自己并归零 noSkill
         }
     }
     ```

* **修改建议**：在 `Unit` 上改为维护有效嘲讽列表（记录各自的施法者与剩余时间），`EndAction()` 仅移除自己这一条记录；只有当所有有效嘲讽全部结束时，才把 `target.ridicule` 置为 `null` 并恢复 AI；`Update()` 只校验**自身记录的施法者**是否存活，不依赖全局单字段自杀。

### 2. 同为通用 `"taunt"` 时，后上的短嘲讽直接顶掉长嘲讽

* **游戏内表现**  
  即使队伍里没有近卫，只要在斯卡莉安（8 秒）或乌帕（6 秒）控住目标期间，菲娜（3 秒）、黄金史莱姆（3 秒）、圣骑士史莱姆（3 秒）或吵吵蕈（3 秒）后手再嘲讽一次，**原长嘲讽剩余时间会立刻缩短为 2~3 秒**。

* **原因定位**  
  `buff.json` 中这些嘲讽（`hero061Skill2AddBuff2`、`033Taunt01`、`hero059TauntBuff`、`pet_10702Taunt`、`pet_106JumpTaunt`、`pet_01602AddBuff`）的 `buffType` 全都是 `"taunt"`，且 `canOverlay: false`。  
  进入 `BuffControl.AddBuff()`（第 432 行）时，`RemoveOldBuff()` 会**无条件移除旧的同类型长嘲讽**，再用新技能的短 `buffTime` 重新挂一遍。

* **修改建议**：同 `buffType` 嘲讽覆盖时，比较剩余时间（仅在 `新时长 >= 原剩余时间` 时刷新时长，或只刷新嘲讽来源、保留 `Mathf.Max(原剩余时长, 新时长)`）；近卫 1 秒被动建议与主动强嘲讽分层治理。

### 3. 嘲讽召唤物或后手角色死亡，会连带清空其他人的长嘲讽

* **游戏内表现**  
  迈妮娅（`hero_046`）2 技能召唤的稻草人（只有本体 20% 最大生命值）或低血近卫挂上嘲讽后一旦阵亡，**场上另一名存活队友事先挂好的长嘲讽也会同步失效**。

* **原因定位**  
  迈妮娅假人脚本（`Hero046Skill2.cs:97-103`）是以**召唤物自己**作为施法者挂上嘲讽的，`target.ridicule` 被覆盖成这个假人。当假人被打死时：
  ```csharp
  // Unit.cs 第 419~429 行
  public bool HasRidicule
  {
      get
      {
          if ((Object)(object)ridicule != (Object)null)
              return !ridicule.isDieOrNearDie; // ← 假人已死，直接返回 false
          return false;
      }
  }
  ```
  `HasRidicule` 变为 `false` 后，场上其他存活队友挂在同一个敌人身上的 `Buff_Ridicule.Update()` 会立刻判定 `!target.HasRidicule`，**把自己的长嘲讽一并销毁**。

* **修改建议**：纳入第 1 节的多嘲讽源列表改造——某一个嘲讽施法者死亡时，只剔除该施法者对应的嘲讽，并顺延把 `target.ridicule` 切换到下一位仍存活的嘲讽施法者。

## 三、 嘲讽期间怪物/Boss 依然放技能与相关边界问题

### 1. 33 个非英雄 AI 未接入 `noSkill` 检查（Boss 与小怪规则不统一）

* **游戏内表现**  
  `buff.json` 对所有嘲讽的说明都是“强制攻击施放者，且**无法释放技能**”（眩晕会直接暂停 AI，而嘲讽不暂停 AI、只给 `target.noSkill++` 并打断当前技能）。  
  但实战中，不少怪物和 Boss 在头顶挂着嘲讽图标时，只有**刚中嘲讽的那一下**被打断，随后到了时间照样放出技能。

* **原因定位**  
  问题出在 **AI 放技能的入口根本没统一检查 `noSkill`**，全靠每张 AI 表自己配跳转条件：
  ```
  Buff_Ridicule.StartAction() 挂上嘲讽 → target.noSkill++（此时不会暂停 AI）
                                               ↓
            UnitAI.DoSkill()（第 1633~1681 行）准备放技能：
            检查了 isPause / isFixing / inSkill / needTarget，唯独没检查 self.noSkill == 0！
                                               ↓
          ├─ 完整配齐 triType: 14（20 个非英雄）──→ 进 SkillBase 拦住 noSkill > 0（不能放技能）
          ├─ 混配/错挂回边（14 个非英雄）────────→ 部分技能或全部技能仍可绕过禁技
          └─ 完全漏配 triType: 14（33 个非英雄）──→ 绕过检查，嘲讽期所有技能照常释放！
  ```

* **全量状态机核对（`ai.json` 共 72 个含技能状态 `type: 1` 的 AI，已全部列全）**

### 2. 自动移动召唤物脚本越界覆写 `ridicule`

* **问题说明**：`Buff_autoMoveSum.cs`（第 190~198 行）在移动结束回调中，误用 `self.ridicule` 来临时记录召唤者的目标，并在超距或目标无效时执行 `self.ridicule = null;`。若自动移动召唤物被敌方施加了真嘲讽，该回调会直接抹空 `ridicule`，导致嘲讽提前失效。
* **修改建议**：将 `Buff_autoMoveSum.cs`（第 192~197 行）改写为使用 `self.target`，停止读写 `self.ridicule`。

## 四、 同类状态隐患：混乱 (`Buff_Confusion`)

* **问题说明**：`Buff_Confusion.cs`（第 22~50 行）在挂载时设 `target.confusion = true;`，结束时设 `target.confusion = false;` 并再次翻转 `target.targetType`。与已使用 `++ / --` 引用计数的 `noSkill`、`noMove`、`noAtk`、`baTi` 不同，`confusion` 没有计数保护。目前配置里只有 `buff.json[2101]` 一个混乱 Buff，暂无多来源冲突；一旦后续新增其他 `buffType` 的混乱来源，就会和嘲讽一样出现“先结束者提前解控且敌我目标反转错乱”。
* **修改建议**：为 `Unit.confusion` 改为引用计数管理，仅在计数归零时还原 `confusion` 与 `targetType`。
