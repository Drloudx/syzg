## 二、 战斗逻辑与数值注入 Bug 详情

### 1. 「时之沙漏」（`skillCool_1001`）冷却缩减完全失效

* **配置与 UI 表现**：
  * `relicInfo.json[skillCool_1001]` Lv.1~5 描述为全局冷却缩减 `6% / 12% / 18% / 24% / 30%`，`skillTrigger.json[relics_skillCool_1001].levelData[1..5].unitData.skillCool` 分别为 `6 / 12 / 18 / 24 / 30`。
  * `BattleManager.GetSpRelicAllAttr()`（`BattleManager.cs` 第 12737~12765 行）能正常累加 `unitData.skillCool`；`RelicDetailPanel.cs`（第 124~127 行）与 `RelicItemToTalTips.cs`（第 87 行）亦正常按 `/ 100f` 展示「冷却缩减 +X.XX%」。
* **底层根因**：
  `BattleManager.InitSpRelicHeroAddAttr(Unit hero, UnitBattleAttribute right)`（`BattleManager.cs` 第 12932~12964 行）在将法盘汇总属性 `right` 注入英雄 `hero.unitData` 时，**完全遗漏了 `skillCool` 字段**，既未执行 `unitData.coolDown += right.skillCool;`，也未在更新后调用 `UIManager.combatPanel.UpdateCdByCdDown(hero);` 重算 `SkillCdData.totalTime`。

  ```csharp
  // BattleManager.cs 第 12953~12964 行（节选）
  unitData.rebDam += right.rebDam;
  unitData.vampire += right.vampire;
  unitData.cureAdd += right.cureAdd;
  unitData.maxSpAddNum += right.maxSp;
  unitData.maxSpAdd += right.maxSpPer;
  unitData.phyAtkAdd += right.phyAtkPer;
  unitData.magicAtkAdd += right.magicAtkPer;
  unitData.magicDefAdd += right.magicDefPer;
  unitData.phyDefAdd += right.phyDefPer;
  // ❌ 缺失：unitData.coolDown += right.skillCool;
  // ❌ 若在 InitCombatPanel 之后重刷，还需调用 UIManager.combatPanel.UpdateCdByCdDown(hero);
  hero.unitData.curSp = hero.unitData.maxSp;
  hero.unitData.curHp = hero.unitData.maxHp;
  ```

* **实际后果**：
  在 `CombatPanel.UpdateCdByCdDown()`（`CombatPanel.cs` 第 6303 行）中，技能最终冷却计算公式为 `skills[i].totalTime = skills[i].baseTotalTime * (1f - unit.unitData.coolDown / 100f)`。由于 `right.skillCool` 从未写入 `unitData.coolDown`，活动本内无论装备多少「时之沙漏」，英雄进图后的技能实际 CD 与未装备时完全相同。

### 2. 核心遗器「涓流长卷」（`core_102`）Tag 3「受击 2 次触发」实际需受击 3 次

* **配置与描述**：
  * `core_102` 共鸣 Tag 3 描述：`"自身每受到 {2} 次伤害时，对目标施加 {洪流} 效果。"`
  * `buff.json[relicBuff_Core102_1..5].para` 配置 `tag3Para_hitCountAddBuff = 2`。
* **底层根因**：
  `RelicBuff_Core_102.cs` 第 40 行初始化 `beHitCount = 0;`，第 123~134 行 `"beHit"` 分支采用**先比较、后自增**逻辑：

  ```csharp
  else if (curType == "beHit")
  {
      if (beHitCount >= tag3Para_hitCountAddBuff)
      {
          UIManager.combatPanel.AddBuff(addNewBuff, tar, self);
          beHitCount = 0;
      }
      else
      {
          beHitCount++;
      }
  }
  ```

  * 第 1 次受击：`beHitCount == 0 < 2` → 自增为 `1`（未触发）；
  * 第 2 次受击：`beHitCount == 1 < 2` → 自增为 `2`（未触发）；
  * 第 3 次受击：`beHitCount == 2 >= 2` → 施加「洪流」并重置为 `0`。
* **实际后果**：实际每受击 **3 次**才触发 1 次施加「洪流」，与描述的「每受到 2 次伤害」差 1 次。

### 3. 核心遗器「幽夜大弓」（`core_101`）`hit` 标记首次命中后未重置

* **底层根因**：
  `RelicBuff_Core_101.cs` 第 58~59 行初始化 `hit = false; timer = cdAll;`，并在 `Update()` 与 `HitAction()`（第 105~136 行）中按如下逻辑运行：

  ```csharp
  private void Update()
  {
      timer += Time.deltaTime;
      if (timer >= cdAll)
      {
          HitAction();
          if (hit)
          {
              timer = 0f;
          }
      }
  }
  
  public void HitAction()
  {
      ...
      if ((Object)(object)tar != (Object)null)
      {
          EffectControl.instance.CreateBulletEffect(...);
          hit = true;
      }
  }
  ```

* **实际后果**：首次触发 `HitAction()` 命中敌人将 `hit` 置为 `true` 后，代码中从未将 `hit` 重置回 `false`。后续每次冷却转好时，若射程（`checkRange = 8`）内恰巧无敌人（`tar == null`），尽管未发射利箭，`if (hit)` 仍会成立并将 `timer` 清零，导致白白重新等待一轮 `30` 秒（或 Tag 2 下的 `24` 秒）冷却。

## 五、 修复建议

1. **`BattleManager.InitSpRelicHeroAddAttr`（`BattleManager.cs` 第 12932~12964 行）**：
   补全 `unitData.coolDown += right.skillCool;`，并在刷新属性后（或 `InitSpRelicAttrAndBuffToTeam` 末尾）对非初始化路径补充 `UIManager.combatPanel?.UpdateCdByCdDown(hero);`。
2. **`RelicBuff_Core_102.BuffAction`（`RelicBuff_Core_102.cs` 第 123~134 行）**：
   改为先自增后判断：`beHitCount++; if (beHitCount >= tag3Para_hitCountAddBuff) { ... beHitCount = 0; }`，使其按描述每受击 2 次触发。
3. **`RelicBuff_Core_101.Update` / `HitAction`（`RelicBuff_Core_101.cs` 第 105~136 行）**：
   每次 `HitAction()` 前将 `hit = false;`（或 `HitAction()` 返回 `bool` 并在 `timer = 0f` 后立即重置 `hit = false;`），避免空转重置冷却。
4. **配置表对齐**：
   * 核对并统一 `cirtDam_1001`（`7%~35%` vs `9~45`）、`core_104` Lv.2/4 `damHpRate`（`0.045/0.075` vs `0.04/0.07`）、`core_102` Lv.2/4 `muPower`（`0.52/0.87` vs `0.53/0.88`）、`petDmg_2001` Lv.4（`0.144` vs `0.145`）以及 6 个属性伤害/减免遗器的 `baseValue` 精度与文本描述。
