## 一、 问题总览

对 `1.7.15` 版本 `campResearch.json` 全表与客户端对接代码排查后，发现冒险线营地研究存在 **3 组明确缺陷**（涉及 5 个研究项）：

| 编号 | 研究名称 / ID | 现象与实际影响 | 根因类型 |
| --- | --- | --- | --- |
| **问题 1** | **破甲战术**（`globalAttr_phyAtkPen`）<br>**元素克制**（`globalAttr_magicAtkPen`） | 点「破甲战术」对全队完全无效；点「元素克制」会同时加到**物理穿透**与魔法穿透（叠加穿透未 `/ 100f` Bug 后，点 1 级魔法穿透即全员 100% 无视双防） | 代码 Getter 引用错字段 |

## 二、 逐项复现与底层代码根因

### 问题 1：营地「物理穿透」读错成「魔法穿透」（附 100% 真伤连带效应）

#### 1. 现象
1. 在营地研究升级「破甲战术（`globalAttr_phyAtkPen`）」1~10 级，物理角色的实际物理穿透不增加；
2. 在营地研究升级「元素克制（`globalAttr_magicAtkPen`）」≥ 1 级后，不仅魔法角色，连**全身 0 物理穿透的物理角色**（如米托拉等）在进战斗后也会无视怪物物理防御。

#### 2. 源码定位
在 `HeroBattleAttributeGroup.cs` 中，`AddCampResearchAttribute` 已正确从 `playerAbilityInitData` 分别读取 `globalAttr_phyAtkPen` 与 `globalAttr_magicAtkPen`（第 1258–1265 行）：

```csharp
if (playerAbilityInitData.ContainsKey("globalAttr_phyAtkPen"))
{
    campResearch_phyAtkPen = playerAbilityInitData["globalAttr_phyAtkPen"];
}
if (playerAbilityInitData.ContainsKey("globalAttr_magicAtkPen"))
{
    campResearch_magicAtkPen = playerAbilityInitData["globalAttr_magicAtkPen"];
}
```

但汇总物理穿透属性 `PhyAtkPen` 时（第 403 行），末尾错拼成了 **`campResearch_magicAtkPen`**：

```csharp
// HeroBattleAttributeGroup.cs 第 403、405 行
public float PhyAtkPen => base_phyAtkPen + equip_phyAtkPen + equipSuit_phyAtkPen + heroStarSkill_phyAtkPen + heroPotential_phyAtkPen + heroArchive_phyAtkPen + heroHomeLevel_phyAtkPen + campResearch_magicAtkPen;

public float MagicAtkPen => base_magicAtkPen + equip_magicAtkPen + equipSuit_magicAtkPen + heroStarSkill_magicAtkPen + heroPotential_magicAtkPen + heroArchive_magicAtkPen + heroHomeLevel_magicAtkPen + campResearch_magicAtkPen;
```

同时因 `UnitAttribute.cs`（第 436–437 行）未将百分数 `/ 100f`，`DamageResolver.cs`（第 134、151 行）又直接按小数上限 `Mathf.Min(num8 + damageInfo.ignoreDef, 1f)` 计算，`>= 1` 的营地魔穿直接让全队物/魔角色全部触发 **100% 无视防御**（详见专题分析：[【已废弃】英雄物理魔法穿透数值未换算导致100%无视防御异常分析.md](./【已废弃】英雄物理魔法穿透数值未换算导致100%无视防御异常分析.md)）。

### 问题 2：「野营篝火」战后魔力恢复完全失效（`globalAttr_restoreMp` vs `globalAttr_restoreSp`）

#### 1. 现象
1. 研究「野营篝火（`globalAttr_restore`）」1~5 级（描述为“战斗结束后恢复生命值和魔力值 `1% ~ 5%`”）；
2. 进图战斗胜利结束时，角色会跳绿色回血数字，但**不会按营地研究恢复魔力**；若无其他战后回蓝来源（如亚空回廊全局 Buff 等），`BattleManager` 完全不触发 `RestoreSp`（或恢复量不含营地研究加成）。

#### 2. 配置与源码对比
在 `campResearch.json` 中，`globalAttr_restore` 各级 `actionPara` 配置的魔力 Key 名均为 **`globalAttr_restoreMp`**：

```json
"globalAttr_restore": {
  "name": "野营篝火",
  "level": [
    {
      "level": 1,
      "addDes": "1%",
      "actionPara": {
        "globalAttr_restoreHp": 0.01,
        "globalAttr_restoreMp": 0.01
      }
    }
    // ... 2~5 级同理，最高 0.05
  ]
}
```

而客户端 `HeroBattleAttributeGroup.cs`（第 1250–1257 行）读取的却是 **`globalAttr_restoreSp`**：

```csharp
if (playerAbilityInitData.ContainsKey("globalAttr_restoreHp"))
{
    campResearch_restoreHp = playerAbilityInitData["globalAttr_restoreHp"];
}
if (playerAbilityInitData.ContainsKey("globalAttr_restoreSp"))
{
    campResearch_restoreSp = playerAbilityInitData["globalAttr_restoreSp"];
}
```

后续链路（`UnitAttribute.cs` 第 394–395 行 → `BattleManager.cs` 第 4224–4273 行 `RestoreHp` / `RestoreSp`）：

```csharp
// UnitAttribute.cs 第 394~395 行
restoreHp = heroDataById.unitData.restoreHp + heroBattleData.attributeGroup.restoreHp * 100f;
restoreSp = heroDataById.unitData.restoreSp + heroBattleData.attributeGroup.restoreSp * 100f;
```

由于 `playerAbilityInitData` 中存在的是 `globalAttr_restoreMp`，`ContainsKey("globalAttr_restoreSp")` 恒为 `false`，导致 `campResearch_restoreSp` 永远是 `0f`，战后回蓝加成彻底失效。

### 问题 3：「伤口处理 / 快速搭建」冷却缩减错大 10 倍，Lv.3 变负冷却

#### 1. 现象
1. 研究「伤口处理（`itemCooldown_potion`）」或「快速搭建（`itemCooldown_device`）」：
   - 点到 **1 级**（面板文案显示减少 **4%** 冷却）：实机战斗药水/道具冷却直接缩短 **40%**；
   - 点到 **2 级**（面板文案显示减少 **8%** 冷却）：冷却直接缩短 **80%**；
   - 点到 **3 级**（面板文案显示减少 **12%** 冷却）：战斗中使用药水或道具后**冷却时间直接变成负数，可无冷却连续使用**。

#### 2. 配置与源码定位
在 `campResearch.json` 中，两项研究的 `addDes` 均为 `4%` / `8%` / `12%`，但 `actionPara` 错配为 **`0.4` / `0.8` / `1.2`**（相比正确小数 `0.04` / `0.08` / `0.12` 放大了整整 **10 倍**）：

```json
"itemCooldown_potion": {
  "name": "伤口处理",
  "level": [
    { "level": 1, "addDes": "4%",  "actionPara": { "itemCooldown_potion": 0.4 } },
    { "level": 2, "addDes": "8%",  "actionPara": { "itemCooldown_potion": 0.8 } },
    { "level": 3, "addDes": "12%", "actionPara": { "itemCooldown_potion": 1.2 } }
  ]
},
"itemCooldown_device": {
  "name": "快速搭建",
  "level": [
    { "level": 1, "addDes": "4%",  "actionPara": { "itemCooldown_device": 0.4 } },
    { "level": 2, "addDes": "8%",  "actionPara": { "itemCooldown_device": 0.8 } },
    { "level": 3, "addDes": "12%", "actionPara": { "itemCooldown_device": 1.2 } }
  ]
}
```

客户端 `QuickBattleItem.cs`（第 739–743 行）与 `BattleItem.cs`（第 456–460 行）直接按 `1f - ability` 计算冷却并赋值，没有做 `Mathf.Max(0f, ...)` 等边界限制：

```csharp
// QuickBattleItem.cs 第 739~743 行
public static float GetBattleItemCD(Item item)
{
    string key = "itemCooldown_" + item.use2Info.cdName;
    return item.use2Info.cd * (1f - GameDataManager.serverData.campResearchData.GetPlayerAbility(key));
}

// BattleItem.cs 第 456~460 行
BattleItemCd battleItemCd = from.cd.Find((BattleItemCd x) => x.type == conf.use2Info.cdName);
if (battleItemCd != null)
{
    battleItemCd.cd = (battleItemCd.time = QuickBattleItem.GetBattleItemCD(conf));
}
```

因此 Lv.3 时 `1f - 1.2f = -0.2f`，算出的 `cd` 与 `time` 均为负值，冷却条瞬间结束。
