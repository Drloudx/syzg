## 二、 召唤物穿透继承割裂与 `100%` 无视魔防问题

### 1. 德莉护卫连带触发 `100%` 无视魔防

* **游戏内表现**  
  德莉本身带任意 `≥ 1%` 魔法穿透装备、词条或营地研究进图后，1 技能「征召号令」（`06002`）与天赋「仁义王道」（`06004`）召唤的弓箭/剑盾护卫，打高魔防目标时伤害同样完全不吃魔防减免（等价 **100% 穿透**）。

* **原因定位**  
  `UnitAttribute.cs`（第 437 行）给德莉赋值时未把百分数除以 `100f`（例如 `2%` 存成 `2f`），而 `Unit.InitSummonUnitIE()` 继承法穿时也直接原样乘以配置比例 `1f`：
  ```csharp
  // Unit.cs 第 2122~2125 行（召唤物初始化）
  if (summonData.magicAtkPenPrecent != 0f)      // 德莉 06002 与 hero060Talent 均填了 1
  {
      unitData.magicAtkPen = summoner.unitData.magicAtkPen * summonData.magicAtkPenPrecent; // ← 直接拿到 2f
  }
  ```
  ```
  德莉 2% 魔穿 → UnitAttribute.cs 存成 2f → Unit.cs 继承为 2f
                                                  ↓ 护卫攻击全为 damageType = "magicAtk"
  DamageResolver.cs 第 134 行：Mathf.Min(2f + ignoreDef, 1f) = 1f → 目标魔防 × (1 - 1) = 0
  ```
  *(边界：4 星分裂体 `fenlie` 未配 `magicAtkPenPrecent`，`magicAtkPen` 为 `0f`；战斗中仅靠 `Buff_AttributeAdd.cs` 第 132 行临时加的法穿已除以 `100f`，这两类不会触发 `100%` 穿防。)*

* **修改建议**：修复 `UnitAttribute.cs`（第 436~437 行）除以 `100f`（见 [【已废弃】英雄物理魔法穿透数值未换算导致100%无视防御异常分析.md](./【已废弃】英雄物理魔法穿透数值未换算导致100%无视防御异常分析.md)）后，`Unit.cs` 按比例乘法即可自然恢复正常小数口径，不需重复除 `100f`。

### 2. 穿透继承只配给德莉与彩虹史莱姆，乌尔勒等老召唤未同步

* **游戏内表现**  
  全游戏所有角色召唤物中，**只有德莉**能继承召唤师穿透；同样纯靠召唤物打输出的物理主 C **乌尔勒**（`hero_065`）、写明“继承自身 50% 属性”的 **安娜**（`hero_029`）以及其余全部召唤角色/装备/遗器，召唤物穿透全部为 `0`。

* **原因定位**  
  `1.7.15` 对比 `1.6.x`（`data-before-1.7.15-20261109`）在 `SummonData.cs`（第 19~21 行）与 `Unit.cs`（第 2122~2129 行）同时新增了 `magicAtkPenPrecent` 与 `phyAtkPenPrecent`，但配置表只填了 3 处：

  | 对象 | 技能 / Buff | `magicAtkPenPrecent` | `phyAtkPenPrecent` | 实际情况 |
  | --- | --- | --- | --- | --- |
  | **德莉 (`hero_060`)** | `06002`、`hero060Talent` | **`1`**（100%） | `0` | **全英雄唯一配置者**（4 星分裂体未配） |
  | **乌尔勒 (`hero_065`)** | `06502`、`hero065Talent` | `0` | **未配置（`0`）** | `1.7.15` 刚把 `hero065Talent` 攻击继承从 `0.6` 调到 `1`，但未补物穿 |
  | **安娜 (`hero_029`)** | `02902`、`02903` | **未配置（`0`）** | `0` | 文案写“继承自身 `50%` 属性”，实际只继承攻/防/生命 |
  | **其余英雄 / 装备 / 遗器** | 贝拉多娜、露帕、迈妮娅、洛莉安等 | `0` | `0` | 均仅继承攻/防/生命（奥格冰岩 `extendSummoner: false` 全不继承） |
  | **彩虹史莱姆 (`pet_118`)** | `skill:pet_11802` | **`0.5`** | **`0.5`** | 全表另唯一 1 例；`SkillPet_11802.cs`（第 112 行）继承**宠物本体**自身双穿 |

  *(注：`phyAtkPenPrecent` 在全英雄里**零人使用**，与 `HeroBattleAttributeGroup.cs` 误用 `campResearch_magicAtkPen`、`Buff_AttributeAdd.cs` 缺 `phyAtkPen` 分支一样，属于 `1.7.15` 物理穿透体系未收口表现。)*

* **修改建议**：明确“召唤物是否普遍继承穿透”的统一规则；若按主力输出或“继承全部属性”口径开放，应为乌尔勒（`06502` / `hero065Talent` 补 `phyAtkPenPrecent`）及安娜（`02902` / `02903` 补 `magicAtkPenPrecent`）同步补齐配置。

### 3. `SummonData.Clone()` 漏拷贝穿透与 `mons` 字段（潜在隐患）

* **游戏内表现**  
  当前暂时未直接表现出来，但一旦给调用了 `Clone()` 的技能（如安娜召唤精灵）配上穿透继承或随机 `mons` 列表，**进游戏后穿透与随机列表会直接归零失效**。

* **原因定位**  
  ```csharp
  // SummonData.cs 第 41~61 行
  public SummonData Clone()
  {
      return new SummonData
      {
          isPet = isPet, monTypeId = monTypeId, ..., maxCount = maxCount
          // ← 漏拷 magicAtkPenPrecent、phyAtkPenPrecent、mons！
      };
  }
  ```
  * `SkillPet_11802.cs`（第 142~165 行）因此不得不重写了一个 `CreateSummonData()` 来绕开 `Clone()`；
  * 全英雄里目前唯一直接调用 `this.summonData.Clone()` 的是安娜的 `Hero029_Skill1.cs`（第 172 行）与 `Hero029_Skill2.cs`（第 182 行）。

* **修改建议**：在 `SummonData.Clone()` 中补齐 `magicAtkPenPrecent`、`phyAtkPenPrecent` 及 `mons`（浅/深拷贝）的赋值。

## 三、 德莉（`hero_060`）技能与星阶机制其余异常

### 1. 4 星「生生不息」（`06008`）：分裂错认召唤师，小史莱姆攻防反超原护卫

* **游戏内表现**  
  解锁 4 星后，护卫退役或死亡分裂出的 2 只小型侍从（`060_1fenlie` / `060_2fenlie`），单发攻击与血量远高于“原护卫的 50%”；以技能 1 前中期为例，分裂出来的**小剑盾/小弓箭魔攻反而比分裂前的本体护卫还要高**，同时分裂体吃不到德莉的法穿。

* **原因定位**  
  `skillTrigger.json[06008]` 描述写明“每个小型侍从继承**原侍从 `50%`** 的最大生命值、攻击力和防御力”，但 `MonDeadFenLieSkill.cs` 调用 `CreatSummon` 时传错了召唤师对象：
  ```csharp
  // MonDeadFenLieSkill.cs 第 45~49 行（护卫死亡/退役分裂时）
  if ((Object)(object)self.summoner != (Object)null)
  {
      BattleManager.instance.CreatSummon(self.summoner, summData, pos);   // ← 传入了德莉本体！
      BattleManager.instance.CreatSummon(self.summoner, summData, pos2);  //   实际按德莉的 50% 算！
  }
  ```
  * 剑盾原护卫 `060_2` 仅继承德莉 `12%~24%` 攻击、弓箭原护卫 `060_1` 在 Lv1~7 继承 `30%~39%` 攻击；分裂体却直接拿到 **德莉本体 `50%` 攻击、`50%` 生命、`50%` 防御**；
  * `skill.json[mon_060_1_03]` 与 `mon_060_2_03` 未配置 `magicAtkPenPrecent`，因此分裂体法穿为 `0`。

* **修改建议**：若按原意“原侍从的 50%”实现，将 `CreatSummon` 首参改为 `self`（同时补录根召唤师/胜负归属引用防止阵营统计错位），或相应修正 `06008` 文案与 `summData` 比例，并明确分裂体是否应同步继承 `magicAtkPenPrecent`。

### 2. 2 星「火力全开」（`06006`）：攻速施加时机错位，且只持续 `5` 秒

* **游戏内表现**  
  解锁 2 星后，德莉施放 2 技能「魔弹号令」（`06003`）时在场侍从**不会获得攻速提升**；攻速只在侍从**刚被召唤出来的瞬间**亮 `5` 秒，之后再放 2 技能也不会刷新。

* **原因定位**  
  1. `Hero060Skill2.cs` 施放 `06003` 时完全没有给侍从挂 `star2Buff`；该 Buff 被错写进了 `Hero060Skill1.cs`（第 206~209 行）和 `Hero060Talent.cs`（第 100~103 行）的**生成回调**里：
     ```csharp
     // Hero060Skill1.cs 第 206~209 行 & Hero060Talent.cs 第 100~103 行
     if (star2)
     {
         UIManager.combatPanel.AddBuff(star2Buff, unitTemp, self); // ← 只在出生时挂一次，06003 里没调用
     }
     ```
  2. `buff.json[hero060Star2_1..4]` 未配 `newBuffTime`，回退读取基础 Buff `hero060Star2AtkSpeedBuff.buffTime = 5`，**实际仅 5 秒**（文案写 `10` 秒）。

* **修改建议**：将 `AddBuff(star2Buff, ...)` 从 `Hero060Skill1` / `Hero060Talent` 出生回调移入 `Hero060Skill2.SumDoSkill()`，并在 `hero060Star2_1..4` 补齐 `newBuffTime = 10`。

### 3. 1 星「衣锦还乡」（`06005`）：增伤覆盖天赋侍从，回血只认 1 技能侍从

* **游戏内表现**  
  天赋自动召唤出来的侍从能吃到 1 星 `30%~60%` 增伤，但这些天赋侍从被打死或退役顶替时，**不会给德莉回复 `5%` 最大生命**（只有 1 技能招出的护卫会触发回血）。

* **原因定位**  
  ```csharp
  // Hero060Star1.cs 第 24~43 行
  monsTemp.Add(component.longTwoSummonData.monTypeId);  // 只加了 060_1（含皮肤）
  monsTemp.Add(component.nearOneSummonData.monTypeId);  // 只加了 060_2（含皮肤）——漏了 060_1Talent / 060_2Talent
  component.star1SummonDamAdd = sumDamAdd;
  component2.star1SummonDamAdd = sumDamAdd;             // ← 增伤却两边都开启了
  ```

* **修改建议**：对照 `06005` 文案决定 1 星“增伤 + 回血”是否统一涵盖天赋侍从；若要同步涵盖，将 `Hero060Talent.summonData.mons` 也加入 `monsTemp`（或统一用召唤来源校验）。

### 4. 2 技能「魔弹号令」（`06003`）：剑盾护卫强化“横向劈砍”实际只打单体

* **游戏内表现**  
  释放 2 技能强化剑盾护卫后，虽然动作看似横向劈砍且文案写“对范围内的敌人造成其 180% 魔法攻击加成的魔法伤害”，但实战周围其余敌人**不受任何波及伤害**，依然只打正前方的单个目标。

* **原因定位**  
  ```csharp
  // Hero060SumNearSkillBuff.cs 第 114~133 行

      if ((Object)(object)target.target != (Object)null)
      {

      }
      ...
      BuffControl.instance.BuffOver(this); // ← 第 123 行直接卸掉 Buff

  ```

* **修改建议**：在 `Hero060SumNearSkillBuff` 的横向劈砍命中事件中按范围筛选敌方目标循环结算伤害（并核对动画事件 `hit1`/`hit2` 与 `BuffOver` 时序，避免提前卸载）。

### 5. 侍从初始化冗余覆写 `phyAtk`（100% 德莉魔攻）

* **游戏内表现**  
  当前暂未直接影响伤害，但侍从底层面板上的物攻 `phyAtk` 会被强行改成 **100% 德莉魔攻**（远高于按 `atkPercent` 继承的 `magicAtk`），一旦后续出现按 `phyAtk` 结算或联动的效果就会出错。

* **原因定位**  
  `Hero060Skill1.cs`（第 190 行）与 `Hero060Talent.cs`（第 84 行）在 `Unit.InitUnit()` 正常按 `atkPercent` 算完后，又硬编码执行了一次覆盖：
  ```csharp
  unitTemp.unitData.phyAtk = self.unitData.magicAtk; // ← 冗余覆写成 100% 德莉魔攻（暂因护卫技能全走 magicAtk 未暴露）
  ```

* **修改建议**：清理 `Hero060Skill1.cs` 第 190 行与 `Hero060Talent.cs` 第 84 行的冗余 `phyAtk` 覆写。
