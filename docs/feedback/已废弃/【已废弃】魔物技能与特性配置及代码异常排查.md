## 二、 代码与机制问题详述

### 1. 草原黏团 & 魔水粘团：主动技能放出去不分裂

* **游戏内表现**  
  两只魔物的主动技（`pet_03602` / `pet_05802`）描述均为在场上分裂召唤两只小黏怪，但实际战斗中不会播放技能动画，也不会召唤出任何小黏怪。

* **原因定位**  
  `SkillControl.cs`（第 626~629 行）将这两只魔物的主动技能都绑定到了 `SkillPet_03602`，而该类的 `SkillAction()` 方法体**完全是空的**：
  ```csharp
  // SkillPet_03602.cs 第 18~20 行
  public void SkillAction()
  {
      // ← 既没有调用 self.PlayAnim(...) 触发 "hit1" 召唤回调，也没有调用 SkillComplete()
  }
  ```
  ```
  玩家召唤魔物释放主动技 → 调用 SkillPet_03602.SkillAction()
                               ↓
                    方法体为空，动画未播放
                               ↓
              绑在 "hit1" 上的 HitAction1() 永不触发
                               ↓
                    小黏怪不会生成，技能无法正常收尾
  ```

* **修改建议**：在 `SkillPet_03602.SkillAction()` 中补上播放技能动画（`self.PlayAnim(info.animationNames[0], loop: false, self.unitData.animTimeScale, SkillComplete);`），或按普通黏团技能补齐对应动画与 `HitAction1` 触发链路。

### 2. 繁茂杜吉芽：特性“友方有护盾加 12%~18% 水伤”恒为 `0%`

  ```csharp
  // PetBuff_06304.cs 第 66~86 行

  if ((Object)(object)buffBase != (Object)null && ((Component)buffBase).tag.Contains(targetBuffTag))
  {                                          // ↑ 致命错误：读成了 Unity 组件的 GameObject.tag（"Untagged"）
  ```

  3. 第 85 行 `EndAction()` 改为扣减 `target.unitWaterDamAddValue`。

### 3. 宝石迷迷可：特性把“近卫队友”算成“水属性队友”，暴伤漏乘人数

  - 上阵纯近卫队伍但没有水属性角色时，加成是 **0**；
  - 上阵水属性法师/射手，反而会触发暴击与暴伤加成；
  - 即使满足 2 名及以上，暴击率正常叠加，但**暴击伤害永远只加 1 份**。

  ```csharp
          {
              result = BattleManager.instance.heroElementDic[checkJob];
          }
      }
      ...
  }

  // ② 暴伤漏乘人数 num

  {
      target.unitData.crit += (float)num * data["crit"].baseValue; // ← 有乘 (float)num
  }
  ```

* **修改建议**：将 `PetBuff_07404.CheckJob()` 改为查询 `heroRaceDic` / `pvpMonRaceDic`，并在 `critDam` 赋值处补乘 `(float)num *`。

### 4. 东天之青龙：特性“自适应额外伤害”每次普攻打两段

* **游戏内表现**  
  图鉴特性“玉珑加护”（`pet_07904`）描述：支援角色释放“治愈魔法”后全队获得 6 层玉珑；每次普攻消耗 1 层，对目标额外造成 `24%~48%` **自适应攻击力**的魔法伤害。实战中每次消耗 1 层玉珑，**会在目标身上同时跳出两次额外伤害**（一次按物理攻击算，一次按魔法攻击算）。

* **原因定位**  
  `buff.json[pet_07904_1..7]` 的子 Buff 参数里同时填了物理版 `damage` 和魔法版 `damage2`，而执行脚本 `PetBuff079AddBuff.cs`（第 56~60 行）没有比较攻击力取其高，直接两句连发：
  ```csharp
  public void BuffAction()
  {
      UIManager.combatPanel.CalculateMaster(atkUnit, self, damage, ...);   // ← 物攻倍率 24%~48%
      UIManager.combatPanel.CalculateMaster(atkUnit, self, damage2, ...);  // ← 魔攻倍率 24%~48%，两段全打
      overLayNum--;
      ...
  }
  ```

* **修改建议**：在 `PetBuff079AddBuff.BuffAction()` 中对比 `self.unitData.phyAtk` 与 `self.unitData.magicAtk`，仅选择较大一侧对应的 `damage` 或 `damage2` 结算一次伤害。

### 5. 格里芬：高阶主动技能伤害归零 + 特性缺层 / 低级缺防

* **游戏内表现**
  1. **主动技升到 3~4 级反而丢伤害**：技能（`pet_09702`）1~2 级升空期间每 `0.5` 秒造成 `44% / 88%` 物理攻击的沙尘伤害，但升到 **3 级、4 级后技能描述直接显示 `{0%物理攻击}`**，升空期间每跳只造成保底 `0%` 倍率伤害。
  2. **特性叠层少 1 层**：特性（`pet_09704`）描述“自身或周围伙伴放技能自身获 1 层地岩；地属性角色放技能额外获 2 层（应共获 3 层）”，实际地属性角色放技能**只叠 2 层**。
  3. **特性 1~2 级加防御为 `0%`**：描述写每层提高 `0.5%` 物理防御，实际 1~2 级面板物理防御增益为 `0%`。

* **原因定位**
  - **主动高阶倍率归零**：`skill.json[pet_09702]` 中 `flyDamage.muPower` 配置断崖清零：
    | 技能等级 | 文案描述倍率 | `flyDamage.muPower` 实际值 |
    | --- | --- | --- |
    | Lv1 | `44%` | `0.44` |
    | Lv2 | `88%` | `0.88` |
    | **Lv3** | **`0%`** | **`0`** ← 异常 |
    | **Lv4** | **`0%`** | **`0`** ← 异常 |
  - **特性叠层硬编码覆盖**：`buff.json[pet_09704_1..7]` 配置了 `"elementAddLayer": 2`，但 `PetBuff_09704.cs`（第 42~50 行）硬编码了覆盖值：
    ```csharp
    if (unit.unitData.Element == checkElement)
    {
        addBuffCount = 2; // ← 覆盖成了 2 层，没有加上原本的 1 层和 elementAddLayer 变量
    }
    else
    {
        addBuffCount = 1;
    }
    ```
  - **1~2 级物理防御配 `0`**：`buff.json[pet_09704_1]` 与 `pet_09704_2` 的 `phyDef` 配成了 `{"baseValue": 0, "percent": 0}`（Lv3~Lv6 为 `0.01`，Lv7 为 `0.02`）。

* **修改建议**
  1. 补齐 `skill.json[pet_09702]` Lv3~Lv4 的 `flyDamage.muPower`（如按 1~2 级递增应为 `1.32` / `1.76`，以策划原案为准）；
  2. `PetBuff_09704.cs` 第 44 行改为 `addBuffCount = 1 + elementAddLayer;`；
  3. `buff.json[pet_09704_1..2]` 的 `phyDef.percent` 补为 `0.005`。

### 6. 格莉姆、雷素、真护之黑龙：正面特性与护盾误标 `"减益"`，会被己方净化清除

### 2. 3 组魔物同队上阵时，队伍被动 Buff 会互相顶替

- **机制原因**：`BattleManager.InitPetTeamPaSkill()`（第 9301~9358 行）按出战宠物顺序为角色添加队伍被动 Buff；而 `BuffControl.RemoveOldBuff()`（第 973~984 行）在添加新 Buff 时，若目标身上已有**相同 `buffType`** 且模板 `canOverlay` 为 `false`（`trigger_pet_atk` 与 `trigger_pet_hp` 均为 `false`），会**先删掉旧 Buff 再挂新 Buff**。
- **撞车清单**（以下 3 组每组共享同一个 `newBuffType`，同队携带且对同一名角色生效时，后者直接顶掉前者）：

| 撞车的 `newBuffType` | 魔物 A | 魔物 B | 修改建议 |
