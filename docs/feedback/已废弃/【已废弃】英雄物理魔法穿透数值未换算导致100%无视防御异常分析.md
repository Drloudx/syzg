## 一、 问题概述

在游戏 **1.7.15** 版本最新实机测试与客户端底层源码核查中发现，角色面板的**物理穿透（`phyAtkPen`）**与**魔法穿透（`magicAtkPen`）**存在严重的单位换算缺失 Bug：

1. **穿透 $\ge 1\%$ 直接等同 `100%` 真实穿防**：角色自身、装备、随机词条或养成系统只要提供 **$\ge 1$ 点**（即 $\ge 1\%$）物理穿透或魔法穿透（例如常见法杖自带 `2%` 魔法穿透、或随出 `1%` 穿透词条），在进入伤害公式结算时不会按 `0.01` / `0.02` 计算，而是直接按 **`1.0` / `2.0`** 被上限函数钳位为 **`1.0`（100% 无视防御）**。
2. **附带连带错位 Bug（营地物理穿透读错字段）**：`HeroBattleAttributeGroup.PhyAtkPen` 最后一项错误累加了 `campResearch_magicAtkPen`（营地魔法穿透）而非 `campResearch_phyAtkPen`，导致：
   - 营地研究升级物理穿透对物理角色无效；
   - 一旦营地研究点出 $\ge 1\%$ 魔法穿透，不仅全部魔法角色变成 100% 无视魔防，**连全部物理角色也会被连带变成 100% 无视物防**。

## 二、 复现条件与实机对比证据

### 1. 复现步骤
1. 进入求生者草原「自由探索 → 营地周边 → **密林深处**」（目标为 **Lv.1 角猪**：原表物防 `132`、魔防 `50`、火弱点 `20%`；Lv.1 强度系数 `1.36` → 进图实际物防 **`179.52`**、魔防 **`68`**，注意房间 `levelScale = 0.4` 源码中仅缩放攻击与生命，不缩放双防）。
2. **对照组 A（艾薇杜尔 Lv.1，无任何穿防装备，仅自身被动 `ignoreDef = 0.06`）**：
   - 面板：`phyAtk = 476`，装备/养成物理穿透 `0`。
   - 实机打出：1 技能 **`334` / `768`**、2 技能 **`701`**。
   - 按 `179.52` 物防、正常 `6%` 无视防御公式计算：1 技能 `334` / `768`、2 技能 `701`，**100% 吻合**（证明未被错误穿防）。
3. **实验组 B（给上述同一艾薇杜尔佩戴任意物理穿透词条）**：
   - 仅增加少量物理穿透后再次攻击同一 Lv.1 角猪。
   - 实机打出：1 技能第一/二段 **`907`**（`0` 物防理论值 `908`）、2 技能第二段 **`1,906`**（`0` 防理论值 **`1,906`**）。
   - **现象**：角猪 `179.52` 物理防御的约 `30%` 减伤瞬间完全消失，伤害直接跃升至与 `0` 防完全一致。
4. **实验组 C（缇莎 Lv.43，佩戴自带 `2%` 魔法穿透的法杖，+15% 火伤头盔，魔法攻击 `3284`）**：
   - 攻击同一 Lv.1 角猪（`68` 魔防）：
   - 按 `2%` 正常魔穿与 `68` 魔防计算：1 技能（`200%`）应为 `8,854`，2 技能（`100%`）应为 `4,427`；
   - **实机实际打出**：1 技能 **`9,064`**（`0` 防理论 `3284 × 2 × 1.2 × 1.15 = 9,063.84`），2 技能 **`4,532`**（`0` 防理论 `3284 × 1 × 1.2 × 1.15 = 4,531.92`）。
   - 实机同样完全无视了角猪的 `68` 点魔法防御。

## 三、 代码底层根因分析

排查反编译源码 `Assembly-CSharp` 可精准定位以下三处关键代码链路：

### 1. 源头单位均为「百分数」（例如 `2%` 存为 `2f`）

在配置汇总类 `HeroBattleAttributeGroup.cs` 中，装备、套装、星阶、潜能、档案、家园与营地的穿透均为**百分数直加**：

```csharp
// HeroBattleAttributeGroup.cs 第 403、405 行
public float PhyAtkPen =>
    base_phyAtkPen + equip_phyAtkPen + equipSuit_phyAtkPen + heroStarSkill_phyAtkPen
    + heroPotential_phyAtkPen + heroArchive_phyAtkPen + heroHomeLevel_phyAtkPen
    + campResearch_magicAtkPen; // ⚠️ 额外 Bug：此处误加了 campResearch_magicAtkPen

public float MagicAtkPen =>
    base_magicAtkPen + equip_magicAtkPen + equipSuit_magicAtkPen + heroStarSkill_magicAtkPen
    + heroPotential_magicAtkPen + heroArchive_magicAtkPen + heroHomeLevel_magicAtkPen
    + campResearch_magicAtkPen;
```

例如武器「湖晶法杖」配置 `magicAtkPen = 2`（表示 `2%`），汇总后 `MagicAtkPen` 的值就是 **`2.0f`**（而非 `0.02f`）。

* **对照正常路径 1（`Buff_AttributeAdd.cs`）**：战斗中 Buff 写入穿透时**显式做了 `/ 100f`**：
  ```csharp
  // Buff_AttributeAdd.cs 第 130~133 行
  if (data.ContainsKey("magicAtkPen"))
  {
      target.unitData.magicAtkPen += data["magicAtkPen"].baseValue / 100f * (float)numTemp;
  }
  ```
* **对照正常路径 2（`RelicDetailPanel.cs` / `RelicItemToTalTips.cs`）**：展示遗器汇总穿透时同样除以了 `100f`（`spRelicAllAttr.magicAtkPen / 100f`）。

---

### 2. 致命遗漏：`UnitAttribute.cs` 初始化英雄时直接赋值，未除以 `100f`

在 1.7.15 版本的 `UnitAttribute.cs` 中，英雄进图初始化战斗属性时直接将百分数原样赋给了 `unitData`：

```csharp
// UnitAttribute.cs 第 436~437 行
phyAtkPen = heroBattleData.attributeGroup.PhyAtkPen;
magicAtkPen = heroBattleData.attributeGroup.MagicAtkPen;
```

此处未作 `/ 100f` 换算，导致 `2%` 穿透在 `unitData.magicAtkPen` 中以 **`2f`** 存入。

*(注：同类隐患也存在于怪物/宠物初始化 `UnitAttribute.cs:633-634, 685-686, 751-752` 及 PvP 打包 `BattleManager.cs:9745-9746`。)*

---

### 3. 结算消费端：`DamageResolver.cs` 按「小数比例」上限钳位 `1f`

进入最终伤害计算类 `DamageResolver.cs`：

```csharp
// DamageResolver.cs 第 120、134、151 行
num8 = ((damageInfo.damageType == "phyAtk") ? self.unitData.phyAtkPen : self.unitData.magicAtkPen);
...
num8 = Mathf.Min(num8 + damageInfo.ignoreDef, 1f);
...
num14 = num13 / (num13 + num7 * (1f - num8)) * num6;
```

当佩戴 `2%` 魔穿武器或 `1%` 物穿词条时：
1. `num8` 取到 `2f`（或 `1f`）；
2. `Mathf.Min(2f + ignoreDef, 1f)` 结果恒为 **`1f`**；
3. 防御项 `num7 * (1f - 1f)` 直接变成 **`0f`**，目标怪物或敌方单位的双防在每次伤害计算中被**完全清零**；
4. 而像艾薇杜尔被动天赋这样通过技能参数 `damageInfo.ignoreDef` 传入的 `0.06f`（本来就是小数），在 `phyAtkPen == 0f` 时只算 `Mathf.Min(0f + 0.06f, 1f) = 0.06f`，反而是唯一正常生效的 `6%` 破防。

## 四、 供参考的排查与修复建议

修复时需注意 **`UnitDataShowPanel.cs` 与 `Buff_AttributeAdd.cs` 对 `unitData.phyAtkPen / magicAtkPen` 的口径混用**，建议统一为「内部全用小数比例（`0.02f` = `2%`）」：

1. **修正 `HeroBattleAttributeGroup.cs`（第 403 行）营地字段错拼**：
   ```csharp
   public float PhyAtkPen => base_phyAtkPen + equip_phyAtkPen + equipSuit_phyAtkPen + heroStarSkill_phyAtkPen + heroPotential_phyAtkPen + heroArchive_phyAtkPen + heroHomeLevel_phyAtkPen + campResearch_phyAtkPen;
   ```
2. **统一 `UnitAttribute.cs` 英雄/怪物/宠物初始化除以 `100f`**（使 `unitData.phyAtkPen`、`unitData.magicAtkPen` 与 `Buff_AttributeAdd.cs:132` 及 `DamageResolver.cs:134` 完全保持一致的小数比例口径）：
   ```csharp
   // UnitAttribute.cs 第 436~437 行（及怪物/宠物/PvP对应入口排查）
   phyAtkPen = heroBattleData.attributeGroup.PhyAtkPen / 100f;
   magicAtkPen = heroBattleData.attributeGroup.MagicAtkPen / 100f;
   ```
   *(若在 `HeroBattleAttributeGroup` 的 getter 或 `InitUnitBaseAttributeData` 处换算，需确保不重复除以 100；且注意确认 `Buff_AttributeAdd.cs` 第 297、476 行对 `phyAtkPen` 是否对称补齐了 `/ 100f`。)*
3. **同步修正战斗内属性面板展示 `UnitDataShowPanel.cs`（第 215–216 行）**：
   当前为：
   ```csharp
   "物理穿透" => curUnit.unitData.phyAtkPen + "%",
   "魔法穿透" => curUnit.unitData.magicAtkPen + "%",
   ```
   内部改为小数口径后，此处可直接复用同文件第 221 行的 `GetPercent(...)`（即 `value * 100f + "%"`），否则会把 `2%` 错显示为 `0.02%`。
4. **顺手补齐 `Buff_AttributeAdd.cs` 中的物理穿透（`phyAtkPen`）分支**：
   目前 `Buff_AttributeAdd.cs` 在第 130 / 297 / 476 行仅处理了 `magicAtkPen`（且正确执行 `/ 100f`），**缺少 `phyAtkPen` 对应分支**，建议对称补全。
