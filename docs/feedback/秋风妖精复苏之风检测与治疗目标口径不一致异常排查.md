# Bug 排查：秋风妖精「复苏之风」施放检测与治疗选人口径不一致（`pet_07102`）

> **最新核对版本**：**1.7.15**（`cdnVer: 38`，热更包 `codeVersion: A0A4112C5087F29074EA0C41AD03EE6F`）  
> **核对日期**：2026-11-26  
> **类型**：魔物主动技能 AI 施放检测与目标选取逻辑矛盾  
> **状态**：**未修复**（`SkillPet_00602.cs` 仍存在前后端/前后段口径不一致）

## 一、 现象与核心结论

**秋风妖精**（`pet_071`）的主动技能 **「复苏之风」**（`pet_07102`）在脚本 `SkillPet_00602` 中把**“能否触发施放”**和**“实际奶谁”**写成了两套互相矛盾的规则：

1. **AI 施放前检测**（`CheckFriendsHp()`）排除了所有召唤物（`canelSummon: true`），**只检查非召唤物友方（英雄本体）是否掉血**。
2. **实际加血选目标**（`SkillPointAction()`）调用 `self.GetFriends(...)`（底层 `cancelSummon: false`），**把召唤物也纳入候选池**，再按 `curHp / maxHp`（血量百分比）从低到高排序治疗第 1 名。

这导致两种反直觉的实战结果：

* **仅召唤物掉血、英雄全部满血时**：`CheckFriendsHp()` 返回 `false`，秋风妖精**完全不会施放「复苏之风」**（CD 就绪也原地不放）。
* **任意英雄只掉过一点血（如 99%），而召唤物残血（如 40%）时**：检测通过并触发施放，但选目标会把召唤物算进来并按百分比排序，**这口治疗会直接落到召唤物身上**。

在 `SkillPet_00602.cs` 中：

public bool CheckFriendsHp()
{
    // ❌ 传入 canelSummon: true，过滤掉所有 summonUnit == true 的单位（含召唤物及魔物自身）
    List<Unit> unitsByTargetType = CombatCheckRange.GetUnitsByTargetType(self.unitType, null, canelSummon: true);
    if (unitsByTargetType.Count > 0)

            if (unitsByTargetType[i].unitData.curHp != unitsByTargetType[i].unitData.maxHp)

底层工具函数在 `CombatCheckRange.cs` 中的真实过滤差异如下：

* `CheckFriendsHp()` 走 `GetUnitsByTargetType(..., canelSummon: true)` → `AddUnitsFromSource` → `IsValidUnit`（第 643~645 行）：`if (cancelSummon) return !unit.summonUnit;`。由于角色召唤物与出战魔物自身均有 `summonUnit == true`，**仅英雄本体能触发 `CheckFriendsHp()`**。
* `SkillPointAction()` 走 `self.GetFriends(..., passSelf: false, 999f)`（第 216~221 行）→ `GetTargetsByPos` → `FillTargetsByPos` → `AddTargetsFromSource`（第 432 行）：`IsValidUnit(unit, self, cancelSummon: false)`，**包含场上除施法者自身外的全部友方单位（含召唤物）**。

## 五、 修复建议

根据策划对「复苏之风」文案「**治疗生命值百分比最低的友方单位**」的定位，建议二选一统一口径：

1. **按文案支持治疗召唤物（推荐，与技能描述及青龙 `SkillPet_07902` 一致）**：
   * 修改 `SkillPet_00602.CheckFriendsHp()`（第 19 行）：将 `canelSummon: true` 改为 `canelSummon: false`（或改用与 `SkillPointAction` 相同的 `self.GetFriends(UnitRangeCheckType.circle, passSelf: false, 999f)`），确保仅召唤物掉血时也能正常触发施放；若希望保留“不因秋风妖精自身掉血触发空放”，传入 `self` 排除自身即可：
     ```csharp
     List<Unit> unitsByTargetType = CombatCheckRange.GetUnitsByTargetType(self.unitType, self, canelSummon: false);
     ```
2. **若设计意图为“仅治疗角色本体、不治疗召唤物”**：
   * 修改 `SkillPet_00602.SkillPointAction()`（第 49 行）：改用 `CombatCheckRange.GetHeroTeamOrPvpHero(self.unitType, self)`（`canelSummon: true`）筛选目标，与 `SkillPet_09802` / `SkillPet_10802` 对齐，并同步将 `skill.json[pet_07102]` 文案中的“友方单位”明确为“友方伙伴”。
