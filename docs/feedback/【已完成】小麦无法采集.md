# 【已完成】Bug 反馈：小麦采集物无法采集（对象名被特效代码改写）

> **最新核对版本**：**1.7.15**（`cdnVer: 38`，`codeVersion: A0A4112C5087F29074EA0C41AD03EE6F`）  
> **历史比对版本**：1.6.1（三测）、1.7.2  
> **核对日期**：2026-11-24  
> **类型**：客户端逻辑 Bug  
> **状态**：**已修复**（`RoomCreateController.cs` 已移除对植物采集物 `GameObject.name` 追加后缀的改名代码，保留原始 `uid` 命中 `allCollectObjDic`）

## 一、现象

**关卡里的小麦看得见、能走过去，但没有任何采集交互。**

| 项 | 表现 |
|---|---|
| 视觉 | 小麦模型正常显示 |
| 靠近 | 没有出现采集按钮 / 采集动作条 |
| 点击 | 无任何反应 |
| 资源扣除 | 体力不减少（说明采集动作根本没触发） |
| 地图提示 | 「可能获得：小麦」正常显示 —— 说明配置上它本该可采 |
| 图鉴 | 采集图鉴的「小麦」条目**在当前正常游玩途径下无法解锁** |

1. 进入 **第一章 · 秋日荒野 · 风车平野**（关卡 `stage_c1_area2_2`）

## 四、客户端根因定位

在 `RoomCreateController.CreatObj()` 中，有两段相距约 130 行的代码互相冲突。

### ① 先给对象名加后缀（为了 shader 特效）

在最新 1.7.15 客户端源码中位于 **第 2808~2812 行**（1.6.1 旧版位于约 2529 行）：

```csharp
// RoomCreateController.cs 第 2808 行
if (baseObjData.effectMaterial == "plant")
{
    GameObject obj = objGo;
    ((Object)obj).name = ((Object)obj).name + "_" + baseObjData.atlas + "_plant";
}
```

`plant_xiaomai03` 的配置：

```json
"effectMaterial": "plant",
"atlas": "room_assets_obj_0"
```

所以对象名从初始的 **`obj394`** 被改写成了 **`obj394_room_assets_obj_0_plant`**。

### ② 采集初始化按名字查字典（约 130 行后）

在最新 1.7.15 客户端源码中位于 **第 2938~2943 行、第 3017 行**（1.6.1 旧版位于约 2656 行）：

```csharp
// RoomCreateController.cs 第 2938 行
if (BattleManager.instance.allCollectObjDic.ContainsKey(((Object)objGo).name))
{
    // 采集相关逻辑全部在这里面
    RoomInterObjData interObjData = BattleManager.instance.allCollectObjDic[((Object)objGo).name].interObjData;
    RoomCollectData data = BattleManager.instance.allCollectObjDic[((Object)objGo).name].collectData;
    ...
    // 第 3017 行
    component6.InitInterObjItemData(BattleManager.instance.allCollectObjDic[((Object)objGo).name], InterType.collect);
}
```

而 `allCollectObjDic` 的 key 来源（`BattleManager.InitInterDic()`，最新 1.7.15 位于 **第 8923 行**，1.6.1 旧版位于约 7192 行）：

```csharp
// BattleManager.cs 第 8923 行
allCollectObjDic.Add(battleData.spObj[i].stageObjUid, roomInterObjActionClass);
//                  ↑ 配置里的 uid = "obj394"，不带后缀
```

### ③ 冲突点

```
allCollectObjDic 的 key   = "obj394"
objGo.name               = "obj394_room_assets_obj_0_plant"
                            ↓
ContainsKey(...) 返回 false
                            ↓
整段采集初始化逻辑被完全跳过
                            ↓
小麦未挂载采集组件 → 走过去没反应、点击无任何交互
```

### ④ 关于 `_plant` 后缀的作用

这个后缀本身的目的是**视觉特效**，链路是：

```csharp
// RoomCreateController.cs 第 2697 行：
objGo.AddEColor("plantObj");

// E_color.cs 第 376 行、第 419~421 行、第 1239 行：
_material.SetTexture("_NoiseTex", SceneFXManager.instance.plantNoiseTex.texture);

// E_color.cs 第 891~908 行 —— 植物随风摆动
_material.SetFloat(ShaderProps.Wind, W_eft.Wind.x * W_eft.Wind.y * ((Component)this).transform.localScale.x / 5f);
```

真正驱动这些摆动与贴图效果的是 `objGo.AddEColor("plantObj")` 以及 `effectPara` 中的 `ba_plant_tilt_area` 特效预制体，走的是材质与特效组件分支。

**修改 `((Object)obj).name` 这一步并非植物摆动特效的必要条件，反而导致采集逻辑因 Key 不匹配而中断。**

## 六、顺带反馈：一处模型/掉落错配

关卡 **`c1_4_a_f1A_3`**（第一章 · 秋日荒野 · 关卡 1-4「种子」第 3 区域）：

```
obj272  (x=17, y=33)  → 模型 plant_xiaomai03（小麦外观）  采集 id = collect_ym（亚麻掉落）
obj273  (x=18, y=33)  → 模型 plant_xiaomai03（小麦外观）  采集 id = collect_ym（亚麻掉落）
```

**用小麦的模型配了亚麻的采集 id**，疑似复制粘贴疏漏：
- 这 2 株在实机里外观显示为**小麦**，且由于使用了 `plant_xiaomai03`，同样踩中了改名 Bug 导致无法采集；
- 建议一并修正：若此处本意是亚麻，模型应换为 `plant_yama03`；若本意是小麦，采集 ID 应修正为 `collect_xm`。
