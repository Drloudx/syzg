> **最新核对版本**：**1.7.15**（`cdnVer: 38`，`codeVersion: A0A4112C5087F29074EA0C41AD03EE6F`）  
> **核对日期**：2026-11-24  
> **类型**：战斗逻辑 / 角色技能与召唤物机制联动异常  
> **严重程度**：高（导致全队无预警被己方持续灼烧、残血甚至阵亡，即使清场战后仍在掉血）

## 一、 问题概述

当队伍中同时上阵 **夏库塔拉（已激活 4 星天赋【烈焰舞步】）** 与 **安娜** 时，安娜召唤出的**风精灵**会引发异常的友军伤害连锁：

1. 风精灵获得夏库塔拉 2 技能【沙炎舞步】光环后，会将身边全部**己方队友判定为伤害目标**；
2. 不仅每秒对周围队友造成高额魔法伤害，还会将持续 5 秒的**【灼烧】减益状态（DOT，`buff_017`）**直接施加给全队队友；
3. 即使场上全部敌方怪物已被肃清（画面显示“通往下一个区域”），全队队友依然会持续大额掉血，导致意外减员。

---

## 二、 复现条件与步骤

### 1. 必要前置条件
1. **夏库塔拉**：星阶达到 4 星，已激活 4 星被动【烈焰舞步】（`hero008Star4`）。
2. **安娜**：在队伍中，战斗中施放技能召唤出**风精灵**（`hero029_2`）。

### 2. 触发过程
1. 战斗中安娜施放 2 技能召唤出风精灵。
2. 夏库塔拉施放 2 技能【沙炎之舞】，为全队（包含召唤物风精灵）赋予【沙炎舞步】光环。
3. 当风精灵靠近任意友方英雄（例如近战走位堆叠、或战后全队集合走向传送门时）：
   - 风精灵身边的沙炎舞步光环开始每秒向身边的友军结算魔法伤害。
   - 所有靠近风精灵的友方英雄头上冒出紫色魔法伤害字样（如 `747`、`627` 等，随目标魔防减免浮动）。
   - 友方英雄头像下方出现火焰图标（`buff_017 灼烧`，层数持续叠加刷新）。
   - 战斗结束显示“通往下一个区域”后，全员仍在持续大额扣血。

## 三、 代码底层根因分析（技术定位）

排查客户端底层逻辑，该现象主要与**「召唤物全局索敌目标类型变更」与「范围光环依赖宿主目标类型」**的联动机制相关：

### 1. 关键诱因：`Mon_hero029_2_normalAtk.cs` 变更了全局 `targetType`

安娜召唤物风精灵（`hero029_2`）的普攻技能绑定脚本为 `Mon_hero029_2_normalAtk.cs`。  
在该脚本的初始化函数第 24 行：

```csharp
public void InitSkillParamData()
{
    bulletId = info.aniEvents[0].arg["bulletId"].ToString();
    muPower = float.Parse(info.aniEvents[0].arg["muPower"].ToString());
    self.targetType = self.unitType; // <=== 关键影响行
}
```

* **逻辑分析**：在实现风精灵普攻对友方进行治疗的逻辑时，脚本通过 `self.targetType = self.unitType;` 将索敌目标类型改为了自身单位类型。
* **实际影响**：由于风精灵属于我方召唤物，其 `self.unitType` 为 `UnitType.Player`，该赋值使得风精灵实体的全局 `targetType` 被改为了 `UnitType.Player`（友方）。

---

### 2. 机制联动：`Hero008Skill2VBuff.cs` 读取宿主的 `targetType`

夏库塔拉 2 技能【沙炎之舞】（`Hero008_Skill2.cs`）会遍历 `UnitType.Player`，将光环 `Hero008Skill2VBuff` 赋予全队（包含风精灵）。  
在光环每秒跳动逻辑 `Hero008Skill2VBuff.cs` 第 40~50 行中：

```csharp
public override void SpAction()
{
    // target 为持有该 Buff 的宿主单位（在风精灵身上时，target 即为风精灵）
    foreach (Unit target in target.GetTargets(UnitRangeCheckType.circle, range))
    {
        UIManager.combatPanel.CalculateMaster(target, self, damage, FloatingWordType.Bleed, lockTarget: true);
        if (!string.IsNullOrEmpty(addBuffIdStar4))
        {
            UIManager.combatPanel.AddBuff(addBuffIdStar4, target, self);
        }
    }
}
```

* **逻辑分析**：
  1. `target.GetTargets(...)` 底层调用扩展方法 `CombatCheckRange.GetTargets`，其依据是宿主单位当前的 `self.targetType`。
  2. 正常英雄单位的 `targetType` 为 `Monster`，索敌返回敌方目标；
  3. **在风精灵身上，因其 `targetType` 被上述代码变更为 `Player`，导致其索敌返回的结果为我方全体英雄（`allHeros`）**。
  4. 进而使风精灵身上的光环将附近的友军作为结算目标，执行了伤害与状态附加。

---

### 3. 伤害放大：夏库塔拉 4 星天赋附加【灼烧】

若夏库塔拉未激活 4 星天赋，沙炎舞步仅造成少量火伤；但在激活 4 星天赋（`Buff_Hero008Star4.cs`）后，光环参数被注入了 `addBuffId = "hero008TalentBuff01"`（灼烧 DOT）。  
风精灵在光环作用于友方时，**同步将持续 5 秒的【灼烧】Debuff 附加给了全体友方**，导致友军受到持续的高额火属性魔法伤害，即使战斗结束清场后依然会持续掉血。

---

### 4. 全包排查与影响范围确认

经对客户端全部 2,673 个 C# 代码文件进行全面排查：
1. **全游戏唯一性**：全游戏中仅 `Mon_hero029_2_normalAtk.cs`（安娜风精灵普攻）在脚本初始化时改写了实体的全局 `targetType = self.unitType;`；
2. **其他召唤物正常**：安娜 1 技能的火精灵（`hero029_1`，使用 `Mon_hero029_1_Skill1.cs`）以及其他召唤角色（如卡蜜拉召唤物、露帕召唤物等）均未修改该属性；
3. **其他角色正常**：其他带有全队/范围增益效果的英雄（如达莉、非娜、菲拉等）也均无直接索取宿主目标类型的范围伤害联动。

因此，该友伤异常**仅在同时上阵「夏库塔拉（4星）」与「安娜（召唤风精灵）」时出现**，为特定机制碰撞引起的个例。

## 四、 供参考的排查与处理方向

可参考以下解决思路：

### 方向一：调整风精灵普攻的友方检索方式
在 `Mon_hero029_2_normalAtk.cs` 的 `InitSkillParamData` 中：
* 移除 `self.targetType = self.unitType;`，保持召唤物实体的全局 `targetType` 依然为正常的 `UnitType.Monster`；
* 普攻若需对友方目标治疗，可参考其他辅助/治疗角色的实现方式，在 `SkillAction` 内局部调用 `GetFriends` 或 `GetHeroTeamOrPvpHero` 检索友军。

### 方向二：为夏库塔拉光环增加阵营过滤校验
在 `Hero008Skill2VBuff.cs` 的 `SpAction()` 循环内增加阵营判断过滤，避免光环伤害波及友方：

```csharp
public override void SpAction()
{
    foreach (Unit subTarget in target.GetTargets(UnitRangeCheckType.circle, range))
    {
        // 增加阵营校验：过滤己方单位，避免因宿主 targetType 异常导致误伤队友
        if (subTarget.unitType == self.unitType)
        {
            continue;
        }

        UIManager.combatPanel.CalculateMaster(subTarget, self, damage, FloatingWordType.Bleed, lockTarget: true);
        if (!string.IsNullOrEmpty(addBuffIdStar4))
        {
            UIManager.combatPanel.AddBuff(addBuffIdStar4, subTarget, self);
        }
    }
}
```
