## 二、 嘲讽重叠、顶替与连锁失效精确定位

### 1. 近卫 1 秒小嘲讽到期，引发全队 6~8 秒长嘲讽连锁自杀

* **机制根因**：
  1. 近卫被动（`HeroJob1Buff2`）挂的嘲讽类型名是 `"heroJob1Buff1_1"`（1 秒），而乌帕、斯卡莉安、菲娜等挂的是 `"taunt"`（3~8 秒）。`BuffControl.RemoveOldBuff()`（第 973~984 行）只顶同 `buffType`，因此两个嘲讽实例会并存，但 `Unit.ridicule` 全局只有 **1 个引用槽位**，被后挂的近卫覆盖（`target.ridicule = 近卫`）。
  2. 1 秒到期后，短嘲讽直接把全局字段置空，长嘲讽在 `Update()` 里轮询后自杀：
     ```csharp
     // Buff_Ridicule.cs 第 25 行（挂载时直接覆盖单字段）
     target.ridicule = self;
     target.noSkill++;

     // Buff_Ridicule.cs 第 67~73 行（长嘲讽在 Update 里轮询全局单字段）
     private void Update()
     {
         if (!target.HasRidicule) // ❌ 查唯一字段 target.ridicule，已被置 null → 返回 false
         {
             BuffControl.instance.BuffOver(this); // ❌ 误判已脱控，主动销毁自己
         }
     }

     // Buff_Ridicule.cs 第 75~88 行（近卫 1 秒到期时）
     public override void EndAction()
     {
         ...
         target.ridicule = null; // ❌ 不管是否还有其他有效嘲讽，直接置空
         target.noSkill--;
     ```
* **修复点**：在 `Unit` 上改为维护有效嘲讽列表（记录各自施法者与对应 Buff 实例）；`EndAction()` 仅移除自己这一条，仅当所有有效嘲讽全部结束或全部施法者死亡时才置空 `target.ridicule`；`Update()` 只校验自身记录的施法者是否存活。

### 2. 同为通用 `"taunt"` 时，后上的短嘲讽直接顶掉长嘲讽

* **配置现状**：`buff.json` 中以下嘲讽的 `buffType` 全为 `"taunt"` 且 `canOverlay: false`：
  - `hero061Skill2AddBuff2`（斯卡莉安，8s）
  - `033Taunt01`（乌帕·萝特，3s）
  - `hero059TauntBuff`（菲娜，3s）
  - `pet_10702Taunt`（黄金史莱姆，3s）
  - `pet_106JumpTaunt`（圣骑士史莱姆，2s）
  - `pet_01602AddBuff`（吵吵蕈，3s）
* **源码定位**：进入 `BuffControl.AddBuff()`（第 432 行）调用 `RemoveOldBuff()`（第 973~984 行）时，只要 `buffType` 相同且 `!canOverlay`，无条件销毁旧的长嘲讽，用短 `buffTime` 重挂。
* **修复点**：同 `buffType` 嘲讽覆盖时比较剩余持续时间（仅在 `新时长 >= 原剩余时间` 时刷新时长，或只切换来源而保留 `Mathf.Max(原剩余时长, 新时长)`）；近卫 1 秒被动建议与主动强嘲讽分层治理。

### 3. 嘲讽召唤物或后手角色死亡，连带清空其他人的长嘲讽

* **源码定位**：迈妮娅（`hero_046`）假人（`Hero046Skill2.cs` 第 97~103 行）以召唤物 `unitTemp1` 作为施法者挂上嘲讽，`target.ridicule` 被覆写为假人。当假人阵亡时：
  ```csharp
  // Unit.cs 第 419~429 行
  public bool HasRidicule
  {
      get
      {
          if ((Object)(object)ridicule != (Object)null)
              return !ridicule.isDieOrNearDie; // ❌ 假人阵亡直接返回 false
          return false;
      }
  }
  ```
  `HasRidicule` 变 `false` 后，存活队友挂在同目标身上的 `Buff_Ridicule.Update()` 会立刻自杀销毁。
* **修复点**：纳入多嘲讽源列表改造——单个嘲讽施法者死亡时只剔除该源，并顺延切换 `target.ridicule` 至下一位存活施法者。

## 三、 嘲讽期间怪物/Boss 依然放技能与越界覆写定位

### 1. 非英雄 AI 未统一接入 `noSkill` 检查

* **源码定位**：`Buff_Ridicule.StartAction()` 仅递增 `target.noSkill++` 并打断当前技能，**不暂停 AI**；而 AI 放技能入口 `UnitAI.DoSkill()`（`UnitAI.cs` 第 1633~1665 行）只检查 `isPause` / `isFixing` / `inSkill` / `isSkillShowing` / `needTarget`，**完全没检查 `self.noSkill == 0`**：
  ```
  UnitAI.DoSkill()（缺 self.noSkill == 0 检查）
    ├─ 完整配齐 triType: 14（20 个非英雄）──→ 进 SkillBase 拦住 noSkill > 0
  ```
