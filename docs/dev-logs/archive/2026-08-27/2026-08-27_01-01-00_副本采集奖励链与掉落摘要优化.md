# 副本采集奖励链与掉落摘要优化
> 生成时间：2026-08-27T01:01:00+08:00
> 触发来源：富集区重复展示每个采集实体且缺少具体奖励，房间掉落摘要存在重复，随机装备展示项无法打开详情。

## 修改范围
- `src/utils/dungeonData.js`
- `src/views/DungeonsView.vue`
- `docs/SPEC.md`
- `public/data/parsed/dungeons.json`、`dist/`（由构建流程重新生成）

## 数据与源码核查
- `RoomInterObjActionClass` 先用场景 `caijiTypeId` 读取 `RoomCollectData`，再用 `RoomCollectData.collectTypeId` 读取 `RoomCollectTypeData`；采集奖励取后者的 `reward`。
- 铜矿富集区的 `tks001.collectTypeId = tks`，对应奖励 `collect_tks`：铜矿石 2~3 个，另有 4% 概率获得伴生矿。
- 药草富集区的 `collect_cy.collectTypeId = cy`，对应奖励 `collect_cy`；活血草与蓝露草也分别关联完整奖励池。
- `collect_white` 与 `collect_green` 在 `consume.json` 中均为消耗 1 体力。
- `show_02wq/show_02fj/show_03wq/show_03fj` 均是 `item.json` 中存在的展示物品，可交给全局物品详情弹窗打开。

## 变更详情
- 修正副本采集解析链，补上 `roomCollect.json.collectTypeId` 的中间关联，恢复具体采集奖励、名称和消耗。
- 同一房间内相同采集类型合并为一项并记录数量，避免重复列出每个场景实体。
- 上方房间交互显示“采集物名称 ×数量”，下方仅为每种采集物展示一组奖励。
- “可能掉落”汇总怪物和采集奖励，按物品 ID 去重，并按品质从高到低排列。
- 随机装备展示项与普通物品一样支持点击打开详情。
- 原始 JSON 保持不变。

## 验证与测试
- `npm run verify` 通过（预解析产物、旧脚本残留检查、完整构建）。
- 产物抽查：铜矿富集区解析为铜矿石 ×5、岩盐 ×1；药草富集区解析为药浆草 ×4、活血草 ×2、蓝露草 ×1，均包含具体奖励与 1 体力消耗。
- 全量核对：正式副本 2461 条合并后采集项的奖励池缺失数为 0；1161 条多实例采集项已记录合并数量。
- 去重后 `parsed/dungeons.json` 由约 25.3 MB 降至约 21.9 MB。
