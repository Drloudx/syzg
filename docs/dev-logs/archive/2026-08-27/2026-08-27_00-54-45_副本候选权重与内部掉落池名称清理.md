# 副本候选权重与内部掉落池名称清理
> 生成时间：2026-08-27T00:54:45+08:00
> 触发来源：随机候选逐项显示相同的“权重 1”信息；怪物可能掉落错误展示 `3boos大` 内部掉落池名称。

## 修改范围
- `src/views/DungeonsView.vue`
- `docs/SPEC.md`
- `dist/`（由构建流程重新生成）

## 数据核查
- 全量统计 `dungeonBattleRoutes.json`：共 3726 条候选房间权重，全部为 `1`，无其他数值。
- `c3_d1_midBoss1` 的繁茂杜吉芽配置 `caijiTypeId = main30005_boss_1`，击败后自动触发该奖励池。
- `roomCollect.json` 将该池内部命名为 `3boos大`；真正奖励来自 `reward.json` 的 `main30005_boss_1`，包括 3 阶武器、3 阶防具及材料/符石。

## 变更详情
- 随机候选只显示房间名称，移除无区分度的“权重 1”；路线说明同步去掉权重措辞。
- “可能掉落”仅展示奖励池内的真实奖励，不再把掉落池名称当成物品标签。
- 房间掉落明细标题改为“怪物名 + 自动掉落”，不暴露 `3boos大` 等内部配置名。
- 搜索索引的页面运行期匹配不再包含内部掉落池名称。
- 原始 JSON 保持不变，仅修正展示与解释边界。
