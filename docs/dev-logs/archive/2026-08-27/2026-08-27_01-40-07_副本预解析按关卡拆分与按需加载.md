# 副本预解析按关卡拆分与按需加载
> 生成时间：2026-08-27T01:40:07+08:00
> 触发来源：副本预解析单文件达到 22.86MB，用户要求最大文件不得超过 2MB，并降低手机端加载与解析压力。

## 修改范围
- `scripts/parse/dungeons.mjs`
- `scripts/parse/index.mjs`
- `scripts/dev/verify.mjs`
- `src/views/DungeonsView.vue`
- `docs/SPEC.md`
- `docs/ARCHITECTURE.md`
- `public/data/parsed/dungeons.json`、`public/data/parsed/dungeons/*.json`、`dist/`（由构建流程重新生成）

## 变更详情
- 将原 22.86MB `dungeons.json` 改为副本/关卡摘要索引，房间、路线和掉落按 41 个关卡拆成独立详情文件。
- 索引保留去重搜索词，副本、关卡、怪物、采集与掉落搜索无需预加载详情。
- 详情生成阶段只保留页面实际读取字段，移除重复奖励来源、内部奖励 ID、房间制作字段等非展示数据；原始 JSON 不修改。
- 副本页面点击关卡后才请求详情；加入加载/错误状态、并发请求防串页和会话内 Promise 缓存。
- 删除浏览器端同时加载 11 张原始表重新组合副本数据的重型回退；断网仍通过 `fetchWithFallback` 读取本地拆分产物。
- 构建生成器与 `npm run verify` 都会拒绝超过 2MB 的详情文件，新关卡随原表更新自动生成。

## 验证与测试
- `npm run data:build` 通过：索引 58KB，生成 41 个详情文件，最大 `c2_d4.json` 为 760,760 字节（约 743KB）。
- 索引引用完整性通过：41 个关卡均存在详情文件，ID、房间、路线和奖励数组结构有效。
- 本地 HTTP 抽查通过：索引及最大详情文件均返回 200。
- `npm run verify` 通过：预解析、2MB 限制、完整构建及 `dist` 中 41/41 个详情文件检查全部通过。
- Chrome 无头浏览器直链 `#/dungeons?battle=c2_d4` 验收通过，已渲染关卡标题、随机房间路线和房间内容与掉落来源。
