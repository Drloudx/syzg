# [2026-08-23 04:19:04] 移动端加载优化：构建期预解析单文件 + 去除数据缓存破坏

## 1. 需求与背景
- 用户反馈：手机端任务图鉴点进页面加载很久（截图显示长时间停留在「正在装配任务数据...」）。
- 用户确认方案 A：构建期预解析单文件 + 去缓存破坏；并希望英雄、魔物（宠物/怪物）等页面一并处理；脚本统一放一个文件夹，处理后的数据统一放独立文件夹。

## 2. 排查与技术方案
### 根因（任务页实测链路）
1. `loadTaskData()` 一次 `Promise.all` 拉取 17 个原始 JSON（约 8.2MB），其中 reward.json 3.5MB、task.json 1.2MB、room/item/mon 各约 1MB；CDN 实测合计约 10s（手机网络更慢）。
2. `fetchWithFallback` 给所有 JSON 加 `?t=${Date.now()}`，强制禁用 HTTP 缓存，每次进页面都重新下载。
3. CDN 上 6 个文件（condition/dialogIndex/dialogSegments/hero/hero/levelStage/battle）返回 200 + 507B HTML（SPA 回退页），`JSON.parse` 失败后逐个降级本地再读，白跑往返。
4. 解析逻辑在主线程同步执行（任务/步骤/奖励/剧情索引全量遍历）。懒加载（useLazyList）只优化 DOM 渲染，救不了上面的数据加载与解析。

### 方案
- **构建期预解析**：把「17 文件拉取 + 解析」从手机搬到打包机（`scripts/parse/`），浏览器端只读一个成品单文件。
- **脚本统一目录**：`scripts/parse/`（shared.mjs + 各域 mjs + index.mjs 入口）。
- **产物统一目录**：`public/data/parsed/`（与已有 roles/equips/search-index 同目录）。
- **去缓存破坏**：`fetchWithFallback` 仅在 `import.meta.env.DEV` 时加时间戳，生产走 CDN/浏览器缓存。
- 复用同一套纯解析函数（与浏览器端一致），保证展示结果不变；预解析文件缺失时运行时回退到原多文件加载（兼容旧热更包）。
