# 2026-10-07 开发汇总

## 任务图鉴：剧情搜索命中后自动定位

### 需求

任务页支持按剧情原文搜索（2026-10-06 已做）。但搜到之后，用户点开任务还得自己翻步骤、
找剧情、再往下滚 —— 等于把搜索的价值又还回去了。本次做到**点开即见**：
自动展开命中所在的步骤与该段剧情，并把那句话滚进视野（不做高亮）。

### 索引改为可定位

原索引是「每任务一段全文」，只能回答"这个任务命中了吗"，无法回答"命中在哪一步、
哪段剧情、第几行"，因此没法定位。

改为按 `步骤下标:剧情下标` 分块、块内保留**行数组**（`form: per-dialog-lines`）。
该 key 与 `TasksView` 的 `dialogOpen` 键一致，可直接用来展开对应剧情。

**实测这个形状与一坨文本的压缩后体积几乎相同**（brotli 0.58 MB，差 < 1%）：
块边界与换行本来就存在，拆成数组只是把它显式化，没有引入额外冗余。
产物 raw 2211 KB（1510 个剧情块 / 29182 行）。

### 行文本必须与页面渲染同源（原本不一致）

原先索引自己写了一套"只剥 `[show]/[l]/[cm]`"的清洗，而页面用的是
`cleanDialogueLine` —— 后者还会把 `{myName}` / `主角` 换成「小工匠」、
`{callNameN}` 换成「他（她）」。于是：

- 用户**看到的是**「小工匠，你醒了。」，搜「小工匠」却搜不到（索引里是 `{myName}`）；
- 就算搜到了，索引行与页面渲染行也对不上，无法定位。

改为复用 `cleanDialogueLine`。**索引里的每一行就是页面上那一行的文本。**

另外索引产出的条目粒度也改为**逐条镜像页面渲染**：页面把 `option` 合成**一条**
条目（所有选项收在一起），索引一开始却把每个选项各推一行，导致含选项的剧情
行号错位、滚动落到错误的行。

### 定位实现里踩到的三个坑（都会重复踩）

1. **滚动偏移不能用 `offsetTop` 相减**。`offsetTop` 相对 `offsetParent`，
   而命中行与 `#taskModalScroll` 中间隔着 `.step-accordion` / `.dialog-lines`
   等定位元素，相减得到的值偏出可视区（实测滚到 649、命中行却在 1026）。
   必须用 `getBoundingClientRect()` 相减 —— 与 `utils/scrollTarget` 的
   `alignElementInScrollTarget` 同一算法。
2. **必须等布局稳定再滚**。剧情展开后内容会**二次增长**：实测
   `scrollHeight` 从 1377 涨到 2191（先展开步骤，随后剧情正文把高度撑开）。
   在涨的过程中滚，算出的目标位置在布局稳定后已经不对。
   现在逐帧等到高度连续两帧不变再滚。
3. **`ensureDialogSearch` 必须返回在途 Promise**。原写法是"已在加载中就 `return`"，
   对"别重复请求"够用，但调用方 `await` 到的是 `undefined`，紧接着读命中仍是空。
   冷链接（`?task=...&q=...`）正好命中这个时序：watch 先发起加载、
   `openDetail` 随后调用被早退挡住 → 详情打开了但**没有定位**。

### 顺带修掉两个既有缺陷

- **`?q=` 从 URL 进不来**：`searchQuery` 只在 setup 里读一次，而本站是 hash 路由、
   站内跳转不重建组件 → 分享出去的搜索链接对方点开看不到结果。
  新增 `watch(() => route.query.q)` 做单向「URL → 状态」同步。
- **`watch(searchQuery)` 没有 `immediate`**：搜索词来自 URL 时初始化就已有值、
   不触发 change，索引永远不加载。补 `immediate: true`。

### 验证

| 项 | 结果 |
| --- | --- |
| 索引行 vs 渲染条目 | 1510 个剧情块**逐一对应**（单测锁住） |
| 边界用例 | 「小工匠」（称呼）/「弟子」（选项）/「契约」（普通）均 `inView: true` |
| 冷链接 `?task&q` | 自动展开并定位，`inView: true` |
| 正常浏览（无搜索） | 列表点击、`?task=` 冷链接均**不跳**（`scrollTop: 0`） |
| 单测 | 277 / 0 |
| `app-shell` UI 回归 | 31 passed |
| `npm run verify` | 全部通过 |

> 测试方法上又踩了一次"单次运行 / 同会话状态"的坑：早期用同一个 page 连续
> 导航去测"不搜索时不该跳"，读到 649 误判成乱跳 —— 实际是上一轮搜索的残留状态。
> 改用独立 `browser.newContext()` 后结果为 0。**测导航行为要给干净的上下文。**
