# 2026-10-07 开发汇总

## 任务图鉴：剧情搜索命中后自动定位

### 需求

任务页支持按剧情原文搜索（2026-10-06 已做）。但搜到之后，用户点开任务还得自己翻步骤、
找剧情、再往下滚 —— 等于把搜索的价值又还回去了。本次做到**点开即见**：
自动展开命中所在的步骤与该段剧情，并把那句话滚进视野（不做高亮）。

### 索引改为可定位

原索引是「每任务一段全文」，只能回答"这个任务命中了吗"，无法回答"命中在哪一步、
哪段剧情、第几行"，因此没法定位。

改为按 `步骤下标:剧情下标` 分块、块内保留**行数组**（`form: per-dialog-lines`）。
该 key 与 `TasksView` 的 `dialogOpen` 键一致，可直接用来展开对应剧情。

**实测这个形状与一坨文本的压缩后体积几乎相同**（brotli 0.58 MB，差 < 1%）：
块边界与换行本来就存在，拆成数组只是把它显式化，没有引入额外冗余。
产物 raw 2211 KB（1510 个剧情块 / 29182 行）。

### 行文本必须与页面渲染同源（原本不一致）

原先索引自己写了一套"只剥 `[show]/[l]/[cm]`"的清洗，而页面用的是
`cleanDialogueLine` —— 后者还会把 `{myName}` / `主角` 换成「小工匠」、
`{callNameN}` 换成「他（她）」。于是：

- 用户**看到的是**「小工匠，你醒了。」，搜「小工匠」却搜不到（索引里是 `{myName}`）；
- 就算搜到了，索引行与页面渲染行也对不上，无法定位。

改为复用 `cleanDialogueLine`。**索引里的每一行就是页面上那一行的文本。**

另外索引产出的条目粒度也改为**逐条镜像页面渲染**：页面把 `option` 合成**一条**
条目（所有选项收在一起），索引一开始却把每个选项各推一行，导致含选项的剧情
行号错位、滚动落到错误的行。

### 定位实现里踩到的三个坑（都会重复踩）

1. **滚动偏移不能用 `offsetTop` 相减**。`offsetTop` 相对 `offsetParent`，
   而命中行与 `#taskModalScroll` 中间隔着 `.step-accordion` / `.dialog-lines`
   等定位元素，相减得到的值偏出可视区（实测滚到 649、命中行却在 1026）。
   必须用 `getBoundingClientRect()` 相减 —— 与 `utils/scrollTarget` 的
   `alignElementInScrollTarget` 同一算法。
2. **必须等布局稳定再滚**。剧情展开后内容会**二次增长**：实测
   `scrollHeight` 从 1377 涨到 2191（先展开步骤，随后剧情正文把高度撑开）。
   在涨的过程中滚，算出的目标位置在布局稳定后已经不对。
   现在逐帧等到高度连续两帧不变再滚。
3. **`ensureDialogSearch` 必须返回在途 Promise**。原写法是"已在加载中就 `return`"，
   对"别重复请求"够用，但调用方 `await` 到的是 `undefined`，紧接着读命中仍是空。
   冷链接（`?task=...&q=...`）正好命中这个时序：watch 先发起加载、
   `openDetail` 随后调用被早退挡住 → 详情打开了但**没有定位**。

### 顺带修掉两个既有缺陷

- **`?q=` 从 URL 进不来**：`searchQuery` 只在 setup 里读一次，而本站是 hash 路由、
   站内跳转不重建组件 → 分享出去的搜索链接对方点开看不到结果。
  新增 `watch(() => route.query.q)` 做单向「URL → 状态」同步。
- **`watch(searchQuery)` 没有 `immediate`**：搜索词来自 URL 时初始化就已有值、
   不触发 change，索引永远不加载。补 `immediate: true`。

### 验证

| 项 | 结果 |
| --- | --- |
| 索引行 vs 渲染条目 | 1510 个剧情块**逐一对应**（单测锁住） |
| 边界用例 | 「小工匠」（称呼）/「弟子」（选项）/「契约」（普通）均 `inView: true` |
| 冷链接 `?task&q` | 自动展开并定位，`inView: true` |
| 正常浏览（无搜索） | 列表点击、`?task=` 冷链接均**不跳**（`scrollTop: 0`） |
| 单测 | 277 / 0 |
| `app-shell` UI 回归 | 31 passed |
| `npm run verify` | 全部通过 |

> 测试方法上又踩了一次"单次运行 / 同会话状态"的坑：早期用同一个 page 连续
> 导航去测"不搜索时不该跳"，读到 649 误判成乱跳 —— 实际是上一轮搜索的残留状态。
> 改用独立 `browser.newContext()` 后结果为 0。**测导航行为要给干净的上下文。**

## 安全加固一：响应头（CSP / HSTS / X-Frame-Options）

### 做了什么

`public/_headers` 新增全站（`/*`）安全头：

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:; media-src 'self'; font-src 'self'; connect-src 'self';
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
```

### 每条指令为什么是这个值（都对着本项目实际写法核过）

| 指令 | 值 | 依据 |
| --- | --- | --- |
| `script-src` | `'self'`（**不带 unsafe-inline**） | 这是 CSP 的核心价值。本站扛得住：`index.html` 与构建产物里**内联 `<script>` 0 个**，`onclick=` 等内联事件处理器**全仓 0 处** |
| `style-src` | `'self' 'unsafe-inline'` | Vue 的 `:style` 绑定会写成内联 style，**全仓 141 处**（招募坐标、地图节点、吉祥物、营地研究树）。不放开会让动态定位全废 |
| `img-src` | `'self' data: blob:` | `data:` = 点选验证码的 32 张 base64 蛋图（内联进 SVG `<image href>`）；`blob:` = 招募页 Spine 贴图（`URL.createObjectURL`） |
| `media-src` | `'self'` | 招募页 BGM 用 `new Audio(...)` |
| `frame-ancestors` | `'none'` | 防第三方 iframe 嵌套（`X-Frame-Options` 的现代写法，两个都写兼容老浏览器） |

### 自测工具（关键交付）

CSP 的误伤特点是**不报错、只静默失效**（图不显示、音不播、样式错位），
所以"配好了"不能靠肉眼看。新增 `scripts/dev/check-csp.mjs`（`npm run csp:check`）：

1. 从 `public/_headers` **解析出真实 CSP**（不另抄一份，避免"测的和上的不是同一个值"）；
2. 起本地静态服务托管 `dist/`；
3. 用 Playwright **给每个响应注入该 CSP**（等价于 Pages 套 `_headers`）；
4. 监听 `securitypolicyviolation` + 控制台，收集违规；
5. 走 8 个关键页 + 注册页人机验证，逐页截图。

**实测结果：9 个场景全部零违规**（含 8 张 `data:` 蛋图确实渲染出来）。
截图在 `scratch/csp-shots/`。

### 这个脚本自身踩的三个坑（都会重复踩）

1. **第一版是"空转"**：只点了「含『登录』字样的按钮」，而顶栏账号入口是
   `<button title="账号">`（文案里没有"登录"）→ 什么都没测到却报了 ✅。
   现在**断言蛋图数量 > 0**，测不到就判失败，不给假结论。
2. **注册页的邮箱框 placeholder 是「用来收验证码，也是以后的登录账号」**——
   里面**没有"邮箱"二字**。用 `/邮箱/` 宽匹配会命中登录页那个「注册时用的邮箱」，
   于是注册表单邮箱始终为空、被「请填邮箱」挡下，蛋图永远出不来。
3. **静态服务没有 `/api`** → 人机验证弹窗显示「无法连接账号服务器」→ 蛋图不渲染。
   现在就地用项目自己的 `buildCaptcha()` 出一道真题并 mock 该接口
   （**只 mock 取题，不 mock 提交**）。

> ⚠️ **开发环境不受 `_headers` 影响**（Vite 不读它），本地 `npm run dev` 看不到 CSP 行为。
> ⚠️ **Android 原生壳也不受它影响**（加载 `https://localhost` 的包内文件）——
> 这是"原生端没有 CSP 保护"，不是配置错误，如实记录。

## 安全加固二：密码盐改为每用户独立随机（对齐主流）

### 改动

原先 `salt = HMAC(SALT_SECRET, 'salt:' + 邮箱)` **派生**；现在**注册时客户端
`crypto.getRandomValues` 随机生成 32 字节**（64 位小写 hex），随注册请求提交，
服务端校验形状后原样存进 `users.pw_salt`。

### 为什么改

原先的派生盐满足"每人不同"但**不是随机**，偏离了 bcrypt / Argon2 / scrypt
这些主流密码哈希的通行做法（它们都是每条记录一次 CSPRNG）。

**关键转折点**：盐后来**必须入库**了（为了支持换邮箱 —— 现算会与注册时不同，
用户换完邮箱再也登不上，见方案 §4.2.1）。**一旦盐进了数据库，派生盐相对随机盐
就只剩缺点**：

| 攻击者拿到 | 随机盐 | 派生盐 |
| --- | --- | --- |
| 只有 D1 备份 | 攻不动 | 攻不动 |
| D1 备份 + `SALT_SECRET` | 仍需逐用户爆破 | **可自己算出所有盐 → 预计算可行** |

### 性能：无影响（甚至更快）

- 随机盐 `crypto.getRandomValues` ≈ 0.001ms，比一次 HMAC 还便宜；
- 只在**注册那一次**执行，登录直接从库里读 `pw_salt`；
- **真正的开销 PBKDF2 60 万轮完全没动**。

### 协议本身没变

盐仍是 **64 位小写 hex、客户端当 UTF-8 字符串用**（不做 hex 解码），
所以 `tests/ui/password-kdf.spec.js` 的跨端比对依然有效。

### 未注册邮箱返回"占位盐"

`HMAC(SALT_SECRET, 'placeholder:' + 邮箱)`，确定性。

⚠️ **这不是为了防枚举**（用户明确决定不做防枚举），而是**流程可用性**：
登录页提交前要先取盐，若对未注册邮箱直接报错，用户会在还没点登录时
就看到一个"邮箱不存在"式的错误。返回形状正常的占位盐，让流程走到服务端比对、
统一返回「邮箱或密码不对」，与主流站点体验一致。

它对同一邮箱**稳定**（不会两次请求返回不同值），所以不会因为"响应随机"
变成新的枚举口子 —— **这是副作用，不是目的**。

### 测试改动

- `auth-crypto.test.mjs`：改用 `generatePasswordSalt` / `placeholderPasswordSalt`；
  新增 5 条（随机盐 300 次不重复、形状、占位盐稳定性、随机盐不受 SALT_SECRET 影响等）；
- **所有注册调用点都要传 `salt`**，且**必须用随机盐、不能用 `/api/auth/salt` 的占位盐**
  （用占位盐会注册成功但**永远登不上**）。已改：
  `tests/helpers/accountApi.mjs`、`tests/api/auth-flow.mjs`、`tests/api/comments-auth.mjs`；
- `auth-flow.mjs` 新增两条断言：**随机盐 ≠ 占位盐**、**盐形状不对 → 400**。

### 安全加固的验证

| 项 | 结果 |
| --- | --- |
| 单测 | **280 / 0** |
| 端到端 `auth-flow` | **103 / 0**（含注册→存盐→登录全链路） |
| 端到端 `comments-auth` | **42 / 0** |
| UI `account-modal`（真表单注册） | **19 passed** |
| CSP 自测（9 场景） | **零违规** |
| `npm run verify` | 全部通过 |

> 端到端跑的是**真实流程**：注册时客户端随机生成盐 → 服务端存 → 登录时取回同一个盐
> → 派生出同一个 verifier。这是随机盐改动的**唯一可靠证据**，比读代码强。

### 安全加固未做

- **TOTP 二次验证**：全仓无实现，属独立功能，需要单独排期；
- **Argon2id**：Cloudflare Workers 不支持（`node:crypto` 明确排除 `argon2`，
  且 CPU 限流器无法中断密码学循环，故对 PBKDF2 直接入口封顶 10 万轮）。
  本项目把 KDF 放在**用户设备**上跑（PBKDF2 60 万轮 = OWASP 推荐值），
  而设备上的 `crypto.subtle` **同样只有 PBKDF2** —— 这是两端受限下的交集，不是偷懒。
- **防枚举**：用户明确决定不做。
