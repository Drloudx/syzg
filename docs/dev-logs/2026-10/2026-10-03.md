## 讨论区中间区域的自动刷新（主题三）

**现象**（用户反馈）：别的设备发了消息，**右栏出现了、中间区域没有**，必须重开一次聊天。

**根因**：中间区域**根本没有自动刷新**。`CommentsPanel` 只在 `pageKey`/`recent` 变化时
`load()`，而站内讨论区的 `pageKey` 永远是 `site:general` 不会变；`commentEvents` 广播
只在同一标签页内传、**不跨设备**。右栏则是 30 秒轮询——所以"右边有了、中间没有"同时成立。

**改法**（间隔先定 20 秒，当天晚些按用户要求改为 **1 分钟**，并抽成
`config/discussions.js` 的 `DISCUSSION_POLL_MS` 供中间与右栏共用）：

- 新增 `composables/useVisibilityPolling.js`，中间与右栏共用，四个边界集中一处：
  后台完全停跑、切回立即补一次、预渲染不跑、用 `setTimeout` 递归避免请求堆积；
  右栏原先自己写的 `setInterval` + `visibilitychange`（两处重复绑定）随之删除；
- `CommentsPanel.mergeNewComments()`：**只并新增，不替换列表**。
  不能复用 `load()`——它会用服务端那一页整体替换 `comments`，
  而用户可能已"上滑加载更早消息"拉进来好几页，替换等于**把历史丢掉**；
  同时不显示加载态、失败不弹错（轮询比人眼快，闪加载态更烦）；
- 合并后 `commentsLength` 变化照旧走 `DiscussionsView` 的 watcher，
  于是"贴底就跟随、翻历史就原地不动"的规则自动生效。

**验证**

- 新增 `verify-cross-device-poll.mjs`（两个独立浏览器上下文＝两台设备）**8/8**：
  中间区域 7.4s 出现、右栏 7.0s 出现、更早消息一条不丢、翻历史不被拽到底部、
  页面隐藏期间 0 次请求、无 JS 报错、测试数据自清；
- 新增 `measure-poll-cadence.mjs` / `measure-poll-cost.mjs` 量真实节奏与成本：
  `comments` 间隔 **60024ms**（= 配置值）；每周期 2 个请求 / 约 6.8 KB；
  隐藏 25 秒 → **0 次请求**；切回前台 2.5 秒内**立即产生请求**；
- 既有 6 套全部复跑通过：`verify-post-scroll` 12/12、`verify-no-flicker` 9/9、
  `verify-discussions` 36/36、`verify-chat-order` 11/11、`verify-autoscroll` 6/6、
  `verify-discussions-order` 9/9。

> 额度账（按 1 分钟）：1 人停留 1 小时 ≈ 120 次请求；5 人 × 4 小时/天 ≈ **2400 次/天**，
> 占 Functions 免费版 10 万次/天的约 **2.4%**。早期按 20 秒估的 7200 次/天已作废。
> **轮询只挂讨论区**；物品详情等页面的评论面板不轮询（首页点开极频繁，
> 不能放大成"停留期间每 1 分钟一次"）。
>
> 另：当天还回答了"要不要做即时推送（SSE）"，结论与依据（Workers 请求间无共享内存、
> 必须引入 Durable Object 或外部 pub/sub、EdgeOne 对流式响应未验证）记在
> [评论后端方案](../../technical/COMMENTS_BACKEND.md) 的「要不要做即时推送」一节。

## Bug 修复

### 讨论区发表时的"闪一下"：根因是滚动跟随的时机与位移方式

**现象**（用户原话）：中间区域发消息的时候闪一下。

**先排除的假设（都有实测数据，不是推断）**

| 假设 | 实测结论 |
| --- | --- |
| 交接文档成因③"面板高度用 `--vh100` 推算有偏差" | **不成立**。6 种视口（1025×780 / 1161×661 / 1280×800 / 1440×900 / 1731×927 / 1920×1080）下面板底边恒定在视口下 20px，输入区底边最小余量 36px，`.app-container` 纵向溢出 **0px**。 |
| 发表区高度 / 滚动区可视高度 / 滚动条宽度抖动 | **不成立**。逐帧采样全程零变化（174 / 530 / 15px）。 |
| 列表被整体重建（交接文档成因①） | **不成立**。列表 subtree 的 MutationObserver 只记录到 `+1/-0` 一次。 |
| 滚动锚定打架（成因②） | 已被 `overflow-anchor: none` + `scrollbar-gutter: stable` 处理，无需再改。 |

顺带纠正一处**测量自身的假报**：全程 1920×1080 报出的「29px 变化」是我第一个扫描脚本的首帧取自
"页面尚未落定"所致，把首帧换成稳定后的帧即消失。已换成"起采样前先等固定帧数"。

**真正根因**（逐帧数据）

新评论插入后，滚动到最新有两个缺陷，叠起来就是用户看到的"闪"：

1. **晚了两帧才滚**：`scrollToLatestAfterLayout()` 用双 `requestAnimationFrame` 等布局，
   于是先绘制出"新消息已插进视野、但列表还没跟下去"的中间态，紧接下一帧整块再动一次。
   实测帧序：`#24 items 20→21`、`#25 scrollTop 仍 1040`、`#26` 才变 —— 中间白白画了一帧。
2. **一次瞬移**：`el.scrollTop = el.scrollHeight` 是瞬间跳变。用户往上翻着历史时点发表，
   实测 `scrollTop 577 → 1196`（**619px 在一帧内甩过去**）。

**修法**（`src/views/DiscussionsView.vue`，滚动位置收敛为**唯一决策点**）

- `watch(commentsLength, { flush: 'post' })`：在 **DOM 更新之后、浏览器绘制之前**决定滚动，
  让"插入"和"滚动"落在同一帧；
- **首次载入直接落到底**（打开就该停在最新，不要动画）；**之后的增量走 260ms 动画曲线**
  （easeOutCubic，目标每帧重取，因为新评论高度要等布局）；
- **只在"插入前就贴着底部"时才自动跟随**（阈值 120px ≈ 一行半消息）。
  用户往上翻着历史时**原地不动**，不再被拽走；
- 动画首帧**同步推进**（不用 `requestAnimationFrame(step)` 启动，否则第一次位移又被推到下一帧）；
- 用户自己滚动（`scroll` 事件）立刻放弃动画，不与用户抢滚动位置；
- 上滑加载更早消息仍走 `suppressAutoScroll`，位置交给 `CommentsPanel` 的锚点补偿。

### 列表与发表区之间的间距：去掉空带 → 卡片对齐滚动条 → 再补回呼吸间距

用户看着截图逐轮校出来的，三个约束互相牵制（详见 [评论后端方案](../../technical/COMMENTS_BACKEND.md)）：

1. **先去掉一条 20px 空带**：`.discussion-composer` 原有 `margin-top:10px` + `padding-top:10px` +
   分隔线，横在"最后一条留言"和"署名行"之间，看起来像列表底下多出一块无用区域。→ 去掉。
2. **再修「滚动条比卡片长」**：`UiSection` 自带 `margin-bottom:18px`，而 `.comments-panel` 正是
   讨论区滚动区里的最后一个区块，这 18px 就成了滚动容器底部的空白尾巴，让滚动条比最后一张卡片
   长出一截（实测尾距 19px）。→ `DiscussionView` 用 `:deep(.comments-panel)` / `:deep(.comments-list)`
   就地清零（**不动全局 `UiSection`**，其他页面仍需要章节间距），尾距 **19px → 1px**。
3. **最后补回 10px 呼吸间距并整体上移**：完全不贴死后用户反馈"挨得太近"。
   → 发表区 `padding-top: 10px`，**同时把面板底部内边距 14px 收到 6px**，
   让"卡片＋滚动条"这一整块整体上移，而不是把发表区顶出面板。
   实测：`scrollBottom 699 = composerTop 699 = lastCardBottom 699`、`gapCardToIdentity 11px`、
   `composerBottom 872`、`.app-container` 溢出 0。

### 滚动动画加"只增不减"保证

新评论插入后浏览器会再微调一次 `scrollHeight`（换行/图片解码），直接写目标值会出现 **1px 回落**
（帧序里抓到过）。改成 `rendered = want > rendered ? want : rendered` 后回落归零。
回归断言的回落容差同时放到 2px（`scrollTop` 是双精度值，取整噪声），
旧实现的失败幅度是**整条总位移**，2px 容差不会让它漏判——A/B 复跑仍是旧实现 10/12、修复版 12/12。
