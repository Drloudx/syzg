# 2026-10-05 开发汇总

> 主题一：**移动端贴边二合一悬浮拉手（`EdgeFloatingWidget`）**
> 解决手机端详情页与讨论区底部输入发表区与原右下角固定操作按钮（「回到顶部」和「功能导航」）相互重叠遮挡的问题。
> 采用吸边半圆小把手 + 横向平滑展开一体化原木胶囊，全场景智能寻迹置顶。
>
> 主题二：**长列表虚拟化快滑感知与图片请求防挤占调度（Fast-scroll Throttle）**
> 解决用户在物品图鉴长列表中猛力向下滑动时，中间划过的海量图片塞满浏览器网络队列，导致停下的位置迟迟无法加载、产生“从头开始一张张慢加载”的排队感。

## 1. 移动端贴边二合一悬浮拉手（`EdgeFloatingWidget`）

### 1.1 背景与问题演进
- **重叠遮挡痛点**：在移动端打开物品详情等弹窗后，底部的评论发表区（富文本输入框 + 发送按钮）紧贴底部，与右下角全局悬浮的「功能导航」汉堡按钮以及「回到顶部」圆钮发生物理遮挡，输入和点击极易误触；
- **排查并放弃的过渡方案**：
  - *输入框 sticky 吸底*：占用了手机屏幕 1/3 的黄金可视区域，装备与图鉴正文严重受限，且割裂羊皮纸弹窗视觉；
  - *底部极窄胶囊条 + 嵌套抽屉*：交互层级过深，点击发表需要再弹一层窗口，操作链路繁琐；
- **最终落地方案**：用户构想并敲定的**贴边吸附二合一拉手（方案 A）**。

### 1.2 结构与交互实现
- **收起态**：贴边极简小拉手（22×52px，原木质感，三道小抓手防滑纹与指示箭头），紧贴屏幕边缘，不占视口内容；
- **展开态**：无缝一体化原木胶囊外壳（`.edge-widget-capsule`），展开时拉手作为右/左端封口，平滑伸出「顶部」与「导航」两枚独立操作按钮，彻底消除分裂缝隙；
- **自由拖拽与持久化**：
  - 垂直方向通过 pointer 事件支持单指/鼠标自由拖动，松手自动避开顶栏（80px）与底栏安全区（80px）；
  - 自动通过 `localStorage` 记住上次位置；
  - 水平方向跨越屏幕中线（35%~65%）自动磁吸换边到左/右侧屏缘；
- **全局整合**：
  - `UiBackToTop.vue`：在移动端媒体查询（`<= 1024px`）下设置 `display: none !important`，桌面端保持原固定圆钮；
  - `App.vue`：挂载 `EdgeFloatingWidget`，移动端隐藏原 `nav-fab-btn`，统一由拉手挂件承接。

### 1.3 移动端全场景智能寻迹置顶
- **踩坑排查**：初版调用 `resolveScrollTarget()` 未传参，兜底返回了 `window` 并执行 `window.scrollTo`。在移动端，主页面长列表由带有 `[data-main-scroll]` 属性的内部容器（`.ui-card-grid-scroll` / `#itemsGridScroll`）独立滚动，`window` 滚动偏移本就是 0，导致点击「顶部」毫无响应。
- **重构寻迹策略（`onBackToTopClick`）**：
  1. **前台弹窗**：若当前打开了 `UiModal`（如物品详情），优先定位其最上层 `.ui-modal-body` 滚动置顶；
  2. **主页面状态**：精准遍历当前页内可见的 `[data-main-scroll]`、`.ui-card-grid-scroll` 核心滚动容器执行 `scrollTo({ top: 0, behavior: 'smooth' })`；
  3. **桌面端与全局**：兜底滚动 `.app-container` 与 `window`。

## 2. 长列表快滑感知与图片请求防挤占调度（Fast-scroll Throttle）

### 2.1 现象与根因剖析
- **现象**：在物品图鉴全量无筛选状态下，手机端用力快速向下滑动长距离并停下时，停下的区域图片迟迟不显示，反而像是在“从头开始一张张往后慢慢加载”。
- **根因**：
  1. 物品数据（`items.json`）在初始化时已全部加载进本地内存，但视图层采用 `@tanstack/vue-virtual` 虚拟网格（`UiVirtualGrid`）；
  2. 惯性飞速划动过程中逐帧快速挂载新行；每张卡片自带 `<img loading="lazy" src="...">`，浏览器在 1~2 秒内瞬间收到上百张新图片的下载请求，塞爆了 HTTP/2 连接并发池（实测禁用缓存峰值 450+ 个）；
  3. 当手指停在目标区域时，当前视口图片的请求排在网络队列的最末端，必须等待飞速划过的那几百张废弃图片排队传输，产生“从头慢慢加载”的排队感。

### 2.2 主流解决方案落地
采用工业级大型电商/图鉴类应用的**“滚动停顿优先加载（Scroll-Idle Priority Loading）”**策略：

1. **快滑状态实时感知（`UiCardGrid.vue`）**：
   - 监听捕获阶段滚动事件，基于位移差与时间差（$\Delta y / \Delta t$）计算即时滚动速度；
   - 速度阈值设为 `0.8px/ms`（约 `800px/s`），超过即判定为“飞速划过”，开启 `isFastScrolling = true` 并向下 `provide`；
   - 监听现代手机浏览器的原生 `scrollend` 事件，配合 `120ms` 空闲防抖计时器，手指停顿或惯性滑动结束的瞬间立刻解除快滑状态。
2. **图片并发防挤占调度（`UiItemCard.vue`）**：
   - 维护会话级内存缓存 `window.__loadedUiItemImages = new Set()`；
   - **已看过的图片**：无论划动速度多快，直接秒出（0 延迟）；
   - **未看过的冷图片**：
     - 飞速划过期间暂不挂载 `<img>`，保留原生品质底框与名称；
     - 停顿或惯性停止后，当前视口内卡片立刻挂载 `<img>`，独享 100% 浏览器并发带宽，秒级渲染；
   - **平滑过渡**：配合 `0.15s` 轻度渐入（`opacity: 0 -> 1`），避免生硬跳变。
