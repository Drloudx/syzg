- 第四轮（用户实机对照 + 卡死排查）：揭晓殿堂背景同样移除 Rconer/Rconer2 并改为 `inset:0` 整幅铺满（图1 两侧竖向阴影条同源）；结算卡的职业/属性角标改为**仅「新获得」显示**（prefab 中两者在 `new` 组内，实机重复获得卡无角标）；结算背景按实机截图提亮（`brightness(2.1) saturate(0.85)` 对齐游戏 `bg_bottom + bg_toplight` 的亮灰蓝观感）。**卡死根因**：`gachaSpinePlayer.createSpineScene` 每次为图集页新建 `GLTexture` 但 `dispose()` 只释放 SceneRenderer——揭晓每换一个角色泄漏一整张贴图，多次抽卡后 GPU 显存耗尽把整个窗口挂死（无法点击、无法 F12，JS 主线程仍响应，与探测结果吻合）；`dispose()` 现在逐一释放场景创建的 `GLTexture`。已验证结算页空闲 60s+ 主线程稳定（12 动画、37MB 堆内存持平）。
- 第五轮：结算卡补上**碎片溢出转化记忆结晶**的展示（源码 `CheckHeroExcit` case "3"）——`converted` 时图标换 `duplicate.overflow.icon`（回忆结晶 `item_20026`）、数量为转化数 `overflow.count`，与碎片小图标同位（底衬上、×N 左侧）；角色抽卡的跳过按钮从 HUD 视口锚定（109×51 右下角）改为 prefab 设计坐标 **gacha_btn_skip 128×60 @(548,-302)**（随画布缩放），与魔物蛋池（GachaPetPanel）完全一致，翻卡段与揭晓段同步调整。
- 第六轮：**卡死第二层修复**——蛋池「十连 → 跳过 → 关闭结算」必现的整窗挂死：翻卡/蛋池面板每次抽卡新建 WebGL 画布，`dispose()` 释放纹理后上下文仍要等 GC 回收，反复抽卡累积几十个大纹理上下文把 GPU 进程压垮；`gachaSpinePlayer` 新增 `dropContext()`（`WEBGL_lose_context`），翻卡/蛋池面板卸载与揭晓整体卸载时主动丢弃上下文（揭晓**逐角色切换不可调用**——小人画布复用同一上下文）。结果一览舞台改回默认 contain（与蛋池结算一致：窄窗口/开 F12 半屏时蜂窝网格等比缩小完整显示，此前 `fit="height"` 会左右裁掉网格）；结晶（converted）同样垫 `gacha_card_reget` 阴影底衬；解除结算卡与卡内元素的 `pointer-events:none`，碎片/结晶可被浏览器元素选择器（F12）拾取检查。翻卡与揭晓舞台同步从 `fit="height"` 改回 contain——窄窗口下画面完整不裁切（与蛋池口径一致），全宽窗口两种模式构图相同。
