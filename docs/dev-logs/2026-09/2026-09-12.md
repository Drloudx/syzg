## 四轮：舞台口径改游戏 fit-height + 点击零延迟 + 等待姿态修正

> 用户指出按键/构图比例仍与游戏不符、点击抽卡有明显延迟，并提示参考「vue-myrzg - 抽卡有一点用副本」（其抽卡动画可取，UI 不可取）。

### 根因与修复

- **比例观感根因 = 舞台缩放口径**：游戏 NGUI UIRoot **按高度缩放**（画面撑满、宽度随窗口延伸，屏幕边按钮跟随窗口边缘）；本站 GachaStage 一直是 contain（信箱式），窗口比例不同就整体显小/留黑边——这就是「比例不对」的来源。`GachaStage` 新增 `fit='height'` 模式（scale = 视口高/750，画布宽 = 视口宽/缩放，居中裁切）与 `hud` 具名槽（不随画布缩放、视口边缘锚定），抽卡三面板（CardPanel/PetPanel/RevealPanel）全部切到 height + hud；卡池列表页保持 contain。分享/跳过按钮移入 hud（share 82×82、skip 109×51，约游戏 0.85 比例，贴边 24-28px + 安全区）。
- **点击延迟根因 = 现场拉资源**：面板挂载后才 fetch atlas/skel/贴图（数百 KB）。`gachaSpinePlayer` 增加模块级资源缓存 + `preloadGachaSpineAssets`，两套骨骼清单集中到 `components/gacha/gachaSpineAssets.js`（`<script setup>` 不能 export），`GachaView` 进页 400ms 后台预热——实测点击后 ~22ms 面板挂载（浏览器实测，此前为可感知的数百 ms~秒级）。
- **备份实现取经**：`gachaSpine.js` 的三处做法搬入——① 相机 `pad` 取景（pet 1.08，袋身约占画布 92%，替代手工 scale/translate）；② `defaultMix = 0.12` 动画混合；③ PMA 直传（本站保留既有预乘方案，行为一致）。
- **等待姿态修正**：`startopen_waitclick` 实际渲染是「趴桌只露头发」（单独渲染验证），与游戏等待画面（坐姿+触摸继续）不符；等待阶段改播 `idle`（坐姿）。
- **fit-height 配套**：`card-cam`/`pet-cam`/`card-dark` 从固定 1534×750 改 inset:0（宽视口不再右侧露黑带）；CardPanel 在 Spine 下垫 `gacha_cardforeground_output`（1680×1000 桌面底图，prefab 本就打包）补齐 elsa 桌面 ±767 之外的两侧。
