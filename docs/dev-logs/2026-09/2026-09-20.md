# 2026-09-20 开发汇总

## UI 与交互

### 新增「关卡图鉴」`/chapters`（`ChaptersView.vue`）

主线章节关卡的查询页：章节页签 + 难度筛选 + 搜索 + 单列虚拟列表 → 关卡详情弹窗。

- 列表与任务图鉴同构（`UiFilterPanel` + `UiVirtualGrid` 单列 + `UiListRow`），卡片显示短号、名称、难度标签、推荐等级与常规掉落图标。
- 关卡详情：`UiSegmentedTabs` 切简单/普通/困难，展示体力消耗、限时、解锁条件、首次通关奖励、通关掉落，以及**房间内容与掉落来源**（按波次列怪物、采集物与自动掉落，含女神/泉水等结构化效果）。
- 搜索覆盖关卡名、短号、描述与构建期汇总的 `searchText`，**可按掉落物或怪物名反查关卡**（实测搜「哈萨琳之手」命中 4 关）。
- URL：`chapter` / `stage` / `diff` / `q`。深链 `?stage=c1_13&diff=困难` 可直达并选中对应难度页签；关闭详情只清理 `stage/diff`，保留章节与筛选。
- 黑名单沿用副本图鉴口径：命中地区名（黑森林、霜烬平原）的章节**整章不出现在按钮与列表**，直接链接也不打开，避免按钮与内容不一致。
- 导航新增「关卡图鉴」入口（`NavigationMenu.vue`，图标复用已有的 `Common_Atlas/map_info.webp`，未新增图片资源）。

实测（Chrome，桌面 1440×900 / 手机 390×844）：全部 62 关（黑名单隐藏第四章 15 关、第五章 15 关）、第一章 15 关、`1-1` 详情 4 个房间 / 12 个采集与掉落块 / 55 张奖励卡、深链选中「困难」、手机端无横向滚动且弹窗不超视口、**桌面与手机均零失败请求、零 console 错误**。

### 章节地图（世界地图 + 拼块）

页面顶部加游戏原版的世界地图，点击地区切章节。

- 底图 `map_w1_bg.png`（1680×1680）+ 6 块章节彩色拼块，WebP q85 后合计 **0.51 MB**（原 PNG 3.47 MB）。
- **拼块坐标是测出来的，不是配置**：`ChapterPanel` 的 prefab 导出里只有 UI 组件、没有 GameObject/Transform，拿不到 localPosition。但 `map_w1_cN_lock.png` 是底图对应区域的单色版，于是用模板匹配在底图上定位——匹配分是随机基线的 **0.4%～7.1%**，把 6 块按测得坐标贴回底图后边缘逐块吻合。坐标固化为 `scripts/parse/chapterMapLayout.mjs`，`scripts/dev/measure-chapter-map-tiles.mjs` 可随时重测（本次重测结果与固化值完全一致）。
- **命中判定不能用矩形热区**：拼块包围盒重叠严重（c0 的框有 57% 被 c3 压住），实测「落在 c0 框里但归属 c3」的点若按矩形判定会点错章节；而不透明区域之间也有 7.8% 重叠，所以归属必须按渲染顺序定。构建期把「每个像素最终由哪一块画在上面」烘焙成 256×256 归属图（RLE 后 4.6 KB，编进 `chapters.json`），运行时按格查表——不用 canvas 取 alpha，因为原生端图片走 CDN，跨域会污染 canvas。
- 拼块只渲染可见章节：黑森林、霜烬平原被黑名单隐藏后，地图上那两块保持底图原样，正好等同游戏里未探索的样子，与列表口径一致。
- 未选中具体章节时整张地图保持原色；选中后当前地区高亮、其余压暗，底部标签显示当前章节与关卡数。
- **地图视图与列表视图是两屏，互斥**（用户明确要求）：桌面端「未选章节且没有搜索词」时整块区域只有地图，筛选面板与列表都不渲染；点地块切到列表视图，地图不再出现；点章节行的「全部」回到地图视图。幽夜古堡、黏滑溪谷不在世界地图上，由画布的 `extra` 插槽在地图视图里补入口——否则地图视图没有任何路径能进这两个章节。
- **地图只在桌面端出现**：手机宽度下拼块里的章节名只有约 9px 高、读不清，一张读不了的地图占掉大半屏反而更差；手机端直接给关卡列表，用章节按钮切章节。
- 画布高度**对齐左右两侧面板的底部**，不取视口底：两侧 sticky 面板要留底部安全区（实测面板底 781、视口 801），按视口算画布会比面板长出一截、看起来没对齐。取不到面板时退回 `视口底 − 10`。描边改用全局 `.paper-panel`，与左侧导航面板同一套 2px 描边/阴影/圆角。
- 地图铺满内容栏：底图是正方形而区域是长方形，所以画布内放一个正方形**舞台**按 cover 缩放居中，超出部分裁掉（裁的是边缘云朵，大陆不动）；**命中判定随之改用舞台矩形**，否则 cover 后画布矩形与底图不再一一对应。
- **关卡列表显隐按端区分**：手机端常驻；桌面端属于列表视图。例外是输入搜索词——否则「按掉落物反查关卡」在「全部」下没法用，此时切到列表视图跨章节出结果。
- 画布 `aria-hidden`，等价的可聚焦控件是同一页的章节按钮（键盘用户用它切换），避免重复暴露一套语义。

**踩到并修掉的一个坑**：换章节时原本调 `UiVirtualGrid.scrollToItem(0)` 重置列表，但它用 `align:'center'` 会滚动**整个页面**，把上方的地图直接推出视口——地图点击因此「点了没反应」（实际是第二次点击落到了别处）。`UiVirtualGrid` 本身已在 `items` 变化时把列表滚回顶部，那句是多余的，删掉即恢复。

## Bug 修复

### 物品来源漏出被隐藏地区

现象：黑森林、霜烬平原在副本图鉴里已经隐藏，但物品详情的「掉落来源」仍列出 `垂死菌林 · 菌林·噩梦`、`伊菲卡温泉谷 · 温泉谷·度假区` 等副本，以及 `委托兑换 · 黑森林`。

根因分两处，**不是同一层能一起解决的**：

1. `searchData.js` 的黑名单过滤只作用于 `searchIndex`，**没有过滤 `itemSources`**——兑换等来源的名字里直接带地区名（「委托兑换 · 黑森林」），于是从物品详情漏出。
2. 副本来源的**名字里不含地区名**（「垂死菌林」属于黑森林、「伊菲卡温泉谷」属于霜烬平原），所以只加文本过滤抓不到；必须按副本的 `mapName` 判断。

修复：

- `dungeonData.js` 的 `buildDungeonItemSources` 跳过 `isBlacklisted({ id, name, label: dungeon.mapName })` 的副本。
- `searchData.js` 在组装完 `itemSources` 后按来源自身的 `id/name/desc/type` 再过一遍黑名单，并丢掉过滤后为空的条目。

验证：`item_10022`（金铃草）来源由 45 条降到 27 条，**0 条再含黑森林/霜烬平原/垂死菌林/伊菲卡温泉谷**；全量 `item-sources.json` 7321 条、`search-index.json` 1839 条，命中被隐藏地区的均为 **0**；浏览器打开物品详情逐词检查无泄漏。

**同一根因的第二个漏点**：`DungeonsView.filteredDungeons` 用 `dungeon.chapter`（值是 `c4`）去匹配黑名单，而黑名单里存的是地区名（`黑森林`）——模糊匹配打不中，于是**筛选按钮被隐藏、副本卡片却还在**（页面上仍能看到「黑森林 · 4 个关卡」）。改用 `dungeon.mapName`。

逐页扫描（17 条路由的可见文本里找这四个词）：除 `/recipes` 外全部干净。

- `/recipes` 仍出现「黑森林松茸」——那是**材料名本身带这个词**，不是地区条目。该物品在物品图鉴里已被模糊名单隐藏，但配方页把它当食材列出来。**未改动**：直接抹掉食材名会让配方看起来缺料，是否隐藏需要产品判断（见「未完成事项」）。

### 隐藏幽夜古堡与黏滑溪谷

`config/blacklist.js` 的模糊名单补入 `幽夜古堡`、`黏滑溪谷`，与黑森林/霜烬平原同口径：章节按钮、关卡列表、世界地图入口、搜索与物品来源一并隐藏。

- 先确认影响面：这两个词在物品/任务/成就/怪物/事件/兑换产物里命中数均为 **0**，加进全局模糊名单不会误伤其他图鉴。
- 关卡图鉴可见章节变为 4 个（求生者草原 / 秋日荒野 / 索利德山地 / 魔爪湖畔，共 44 关），世界地图左下角的两个特殊章节入口随之消失（它们由 `visibleChapters` 推导，不是写死的）。

### 测试断言跟进

- `source-completion.spec.js` 的「event and explore sources open the exact existing detail」原用 `item_10036`（绿榛菇），它**唯一**的事件来源在黑森林，该地区进黑名单后不再产出，断言随之失效。换成 `item_20017`（精英冒险家手记，事件 + 探索来源都在可见地区），并在用例里注明换因。
- 其余当时报失败的用例（`acquisition-rules` × 2、`source-completion-followup` × 2）单独重跑**全部通过**，属长跑偶发，未改。

## 数据与解析

### 新增关卡图鉴产物

- `scripts/parse/chapters.mjs`：`parsed/chapters.json`（章节索引 + 世界地图数据，226 KB）+ `parsed/stages/{stageId}.json`（按关卡懒加载，92 个共 2.28 MB，平均 26 KB）。
- `chapters.json` 的 `map` 段含底图/标题条路径、画布尺寸、6 块拼块矩形与命中归属图；坐标与归属图都是构建期常量或构建期烘焙结果，运行时不重算。
- 数据链全部走完整原表：`chapterInfo.json`（章节名/描述/mapArea/额外难度解锁条件）→ `area.json[mapArea].map`（关卡节点与顺序）→ `levelStage.json`（关卡名/短号/battle1..3）→ `battle.json`（等级/体力/限时/奖励组/房间结构）→ `room.json`（`battleData` 下的怪物波次、采集物、效果）→ `reward/consume/item/mon/roomCollect/roomCollectType/equipGroup`。
- **不使用副本专用裁剪表**：`dungeonBattle.json` 只含 69 个副本关卡、不含 `cN_M_x`，所以章节关卡必须读完整的 `battle.json`（585 条）。路线布局在 `chapters.mjs` 内联提取，等价 `extractDungeonRoutes.mjs` 对副本做的事，因此**没有新增派生输入**。
- 章节范围：`chapterInfo` 的 `c0`～`c5` + `area.datas[sp1_map/sp2_map]`（幽夜古堡、黏滑溪谷，这两个特殊章节没有 `chapterInfo` 条目，名称取 `area.name`）。共 8 章 92 关，与 `levelStage.json` 的 92 条完全一致（构建期有完整性断言，多一个少一个都会报错）。
- 三难度的房间配置**各自独立**（`roomTypeId` 带难度后缀，`c2_6_a_*` vs `c2_6_b_*`），不能合并成一份布局；实测 39 个多难度关卡没有一组房间内容逐字节相同。
- `room.json` 的字段位置与副本派生表不同：`monRounds`/`spObj`/`npcList` 在 `battleData` 下，描述字段是 `des` 而不是 `desc`。构建期统一摊平成副本解析期望的形状。
- 解锁文案按源码 `LevelStageShowPanel.RefreshUI` 生成：普通取 `chapterInfo[chapter].exBattleOpenCondition` + `exBattleOpenConditionDes`，困难取「通关 普通难度 解锁」。地图连线与 `hide` 都不是解锁前置，不混用。
- `hide: true`（92 关中 74 关）在游戏里是「未解锁时在地图上隐藏」；本站不连账号，**不做解锁模拟**，一律正常展示。

### 抽出共享模块（消除副本页与新页面的重复）

关卡图鉴与副本图鉴消费同一套「关卡 → 房间 → 候选变体 → 怪物/采集/效果 → 奖励池」结构，展示必须一致，因此把逻辑与卡片样式收敛到一处：

| 模块 | 内容 |
| --- | --- |
| `src/utils/roomDisplay.js` | 波次文案、宝箱档位排序、奖励池分组、概率标签、可点击判断、奖励卡 rule（原 `DungeonsView.vue` 内 11 个本地函数） |
| `src/components/RewardPools.vue` | 奖励池列表 + `UiRewardCard` 网格（`dense` 三列变体、可选来源标签、移动端断点） |
| `src/components/RoomContentList.vue` | 房间卡片：效果、波次、NPC、采集物、怪物自动掉落（保留 `data-source-entry` 供来源直达定位） |
| `scripts/parse/roomEffects.mjs` | 女神/泉水效果解析（`buffGive`/`spObjAddBuff` → `battleBuffTeam → battleBuffCard → buff`），`update-dungeon-room-effects.mjs` 与 `chapters.mjs` 共用 |
| `scripts/parse/compact.mjs` | 详情产物字段裁剪，`dungeons.mjs` 与 `chapters.mjs` 共用 |

`DungeonsView.vue` 相应改为引用这些模块，房间/奖励池的模板与样式不再留在页面里。
