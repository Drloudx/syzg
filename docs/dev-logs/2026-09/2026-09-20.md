# 2026-09-20 开发汇总

## UI 与交互

### 新增「关卡图鉴」`/chapters`（`ChaptersView.vue`）

主线章节关卡的查询页：章节页签 + 难度筛选 + 搜索 + 单列虚拟列表 → 关卡详情弹窗。

- 列表与任务图鉴同构（`UiFilterPanel` + `UiVirtualGrid` 单列 + `UiListRow`），卡片显示短号、名称、难度标签、推荐等级与常规掉落图标。
- 关卡详情：`UiSegmentedTabs` 切简单/普通/困难，展示体力消耗、限时、解锁条件、首次通关奖励、通关掉落，以及**房间内容与掉落来源**（按波次列怪物、采集物与自动掉落，含女神/泉水等结构化效果）。
- 搜索覆盖关卡名、短号、描述与构建期汇总的 `searchText`，**可按掉落物或怪物名反查关卡**（实测搜「哈萨琳之手」命中 4 关）。
- URL：`chapter` / `stage` / `diff` / `q`。深链 `?stage=c1_13&diff=困难` 可直达并选中对应难度页签；关闭详情只清理 `stage/diff`，保留章节与筛选。
- 黑名单沿用副本图鉴口径：命中地区名（黑森林、霜烬平原）的章节**整章不出现在按钮与列表**，直接链接也不打开，避免按钮与内容不一致。
- 导航新增「关卡图鉴」入口（`NavigationMenu.vue`，图标复用已有的 `Common_Atlas/map_info.webp`，未新增图片资源）。

实测（Chrome，桌面 1440×900 / 手机 390×844）：全部 62 关（黑名单隐藏第四章 15 关、第五章 15 关）、第一章 15 关、`1-1` 详情 4 个房间 / 12 个采集与掉落块 / 55 张奖励卡、深链选中「困难」、手机端无横向滚动且弹窗不超视口、**桌面与手机均零失败请求、零 console 错误**。

### 章节地图（世界地图 + 拼块）

页面顶部加游戏原版的世界地图，点击地区切章节。

- 底图 `map_w1_bg.png`（1680×1680）+ 6 块章节彩色拼块，WebP q85 后合计 **0.51 MB**（原 PNG 3.47 MB）。
- **拼块坐标是测出来的，不是配置**：`ChapterPanel` 的 prefab 导出里只有 UI 组件、没有 GameObject/Transform，拿不到 localPosition。但 `map_w1_cN_lock.png` 是底图对应区域的单色版，于是用模板匹配在底图上定位——匹配分是随机基线的 **0.4%～7.1%**，把 6 块按测得坐标贴回底图后边缘逐块吻合。坐标固化为 `scripts/parse/chapterMapLayout.mjs`，`scripts/dev/measure-chapter-map-tiles.mjs` 可随时重测（本次重测结果与固化值完全一致）。
- **命中判定不能用矩形热区**：拼块包围盒重叠严重（c0 的框有 57% 被 c3 压住），实测「落在 c0 框里但归属 c3」的点若按矩形判定会点错章节；而不透明区域之间也有 7.8% 重叠，所以归属必须按渲染顺序定。构建期把「每个像素最终由哪一块画在上面」烘焙成 256×256 归属图（RLE 后 4.6 KB，编进 `chapters.json`），运行时按格查表——不用 canvas 取 alpha，因为原生端图片走 CDN，跨域会污染 canvas。
- 拼块只渲染可见章节：黑森林、霜烬平原被黑名单隐藏后，地图上那两块保持底图原样，正好等同游戏里未探索的样子，与列表口径一致。
- 未选中具体章节时整张地图保持原色；选中后当前地区高亮、其余压暗，底部标签显示当前章节与关卡数。
- **地图视图与列表视图是两屏，互斥**（用户明确要求）：桌面端「未选章节且没有搜索词」时整块区域只有地图，筛选面板与列表都不渲染；点地块切到列表视图，地图不再出现；点章节行的「全部」回到地图视图。幽夜古堡、黏滑溪谷不在世界地图上，由画布的 `extra` 插槽在地图视图里补入口——否则地图视图没有任何路径能进这两个章节。
- **地图只在桌面端出现**：手机宽度下拼块里的章节名只有约 9px 高、读不清，一张读不了的地图占掉大半屏反而更差；手机端直接给关卡列表，用章节按钮切章节。
- 画布高度**对齐左右两侧面板的底部**，不取视口底：两侧 sticky 面板要留底部安全区（实测面板底 781、视口 801），按视口算画布会比面板长出一截、看起来没对齐。取不到面板时退回 `视口底 − 10`。描边改用全局 `.paper-panel`，与左侧导航面板同一套 2px 描边/阴影/圆角。
- 地图铺满内容栏：底图是正方形而区域是长方形，所以画布内放一个正方形**舞台**按 cover 缩放居中，超出部分裁掉（裁的是边缘云朵，大陆不动）；**命中判定随之改用舞台矩形**，否则 cover 后画布矩形与底图不再一一对应。
- **关卡列表显隐按端区分**：手机端常驻；桌面端属于列表视图。例外是输入搜索词——否则「按掉落物反查关卡」在「全部」下没法用，此时切到列表视图跨章节出结果。
- 画布 `aria-hidden`，等价的可聚焦控件是同一页的章节按钮（键盘用户用它切换），避免重复暴露一套语义。

**踩到并修掉的一个坑**：换章节时原本调 `UiVirtualGrid.scrollToItem(0)` 重置列表，但它用 `align:'center'` 会滚动**整个页面**，把上方的地图直接推出视口——地图点击因此「点了没反应」（实际是第二次点击落到了别处）。`UiVirtualGrid` 本身已在 `items` 变化时把列表滚回顶部，那句是多余的，删掉即恢复。

## 重构与维护

### 关卡图鉴视图与地图细节（用户反馈轮）

- **地图视图出现多余滚动条**：`.chapter-map` 底部留了 14px 外边距，画布虽然与左右面板底对齐，但外边距把 `.app-main` 撑高 14px，页面因此可以滚动。改为 `margin: 0`，实测 `.app-container` 溢出为 **0**、页面不再滚动（1920×920 与 1360×801 两种视口）。
- **视图状态改为显式**：原先从 `chapterId`/搜索词推导「地图还是列表」，导致「全部章节」的列表没有可分享的 URL。改为显式的 `view` 状态，并同步到 URL（`view=list`）。
- **交互按用户指定重做**：删掉「收起地图」折叠（地图不再可折叠）；右上角换成与底部标签同款的胶囊「展开列表」，点击直接切列表视图；列表视图在搜索框右侧加「进入地图」（手机不显示，因为手机不出地图）。
- 标题条宽度按用户给的值改为 `min(50%, 260px)`，仍固定左上角。

### 关卡图鉴细节（用户反馈第二轮）

- **地图加悬停浮动**：默认状态所有拼块同色、分不清指着哪一块。改为鼠标进入后指着的那块放大 1.045、提亮、加投影并提到最上层，其余压暗到 0.55；已选中章节时其余块再压一档。实测悬停前后 `transform` 由 `none` 变 `matrix(1.045…)`、`z-index` 由 `auto` 变 2。
- **章节按钮去掉编号数字**：显示「索利德山地」而不是「2 索利德山地」。
- **关卡卡片只显示一个难度标签**：按当前难度筛选显示对应难度，「全部」时默认显示「普通」（关卡没有普通则退回第一个可用难度）；**推荐等级跟着难度走**——三难度的 `battleLevel` 不同（如 1-1 是 2/12/17），索引里按难度存 `levels` 而不是单一 `level`。
- **详情弹窗徽标行没有间距**：`.detail-badges` 在 DungeonsView/EventsView/TasksView 各定义了一份，而 ChaptersView 用了却没定义，于是 `UiTag` 之间只剩空白字符的间距。补上（`display:flex; gap:7px`）。
- **难度切换样式不搭**：原先用 `UiSegmentedTabs`，它是**深色木条**（`background: var(--wood)`，为深色底设计），放在羊皮纸弹窗里是一块突兀的深色。改用列表页同款的 `UiFilterRow` + `UiFilterPill`，不动共享组件的全局样式（`DungeonsView` 也在用 `UiSegmentedTabs`）。

验证：悬停 `transform`/`z-index`/其余块透明度均按预期变化；章节按钮为「全部 / 求生者草原 / 秋日荒野 / 索利德山地 / 魔爪湖畔」；「全部」时序章卡片显示「简单」（它没有普通），切「困难」后 1-1 显示「困难 + Lv.17」、切「简单」显示「简单」；弹窗徽标行 `display:flex; gap:7px`、难度为 3 个 `ui-filter-pill` 且 `ui-segmented` 计数为 0，点「困难」后信息行正确变为「难度 困难 / 解锁条件 通关 普通难度 解锁」。零失败请求、零 console 错误。

### 章节地区路线图（世界地图的第二级）

用户要「地区里的路线」。先量清楚可行性再动手：

- 数据齐：`area.datas[cN_map].map` 有 levelStage / area / instance / explorePoint 四类节点与 link 连线，**74 个关卡节点 + 104 条连线，端点 100% 能落到节点上（0 条悬空）**。连线不只连关卡，也连地区节点与副本入口（c1 是关卡 29 / 地区 11 / 副本 2）。
- 素材：8 张地区底图（`texture/area/bg/map_w1_cN_bg.png`）PNG 23.36 MB → WebP **q80 共 2.68 MB**（无损 14 MB）。8 张全导（含黑名单里的 sp1/sp2）——`chapters.json` 同样保留这些章节的数据，只导一半会让「取消隐藏」变成半坏状态。

实现：

- `chapters.mjs` 新增 `map.regions[cid]`：底图、画布尺寸、底图中心 `bgPos`、节点、连线（chapters.json 226 → 246 KB）。节点摆放偏移照源码 `MapPanel.InitMapPanel`：关卡与房间在 (x, y)，**地区节点上移 80、副本入口上移 75**。探索点只画点不标名——`explorePoint.json` 只有一条配置，真正的点位来自玩家存档。
- 新增 `RegionRouteMap.vue`。画布 2727×2406 ~ 3456×2144，远大于可视区（约 772×642），所以需要缩放平移：用**显式平移偏移**而不是 `scrollLeft`（缩到比容器小时 `scrollLeft` 恒为 0，拖动会完全失效），画布比容器小时锁居中、大时限制在边界内；以可视区中心为锚点缩放，避免内容乱跳。
- 初始视图**贴合节点包围盒**（加 180 边距）而不是整张画布：节点通常只占画布一小块（c1 跨度 1454×871，画布 3456×2144），按画布适配会让节点挤成一团。实测各章初始缩放 36%~55%。
- 节点标记按 `1/zoom` **反向缩放**，屏幕上恒定大小，否则缩小后标签读不清。
- 交互：Ctrl/⌘+滚轮缩放、拖动平移、双指捏合、缩放条（−/%/+/↺）。点关卡节点打开关卡详情，「世界地图」标题条在这里是**返回世界地图**按钮。
- 世界地图与地区路线图共用页面测出的同一块区域高度（把测量从 `ChapterMapCanvas` 提到 `ChaptersView`，两个组件各接一个 `height` prop），避免各测一套、也保证两级尺寸一致。

顺手修掉两个自己踩的坑：

- **底图路径拼错**：用了地区 id（`c1_map`）而不是章节 id（`c1`），拼成 `map_w1_c1_map_bg.webp`。dev server 的 SPA fallback 对不存在的图片返回 **200 + HTML**，请求不报错，只有解码失败触发 `@error` 换成占位图才暴露——从 Network 面板看是「200 成功」，很有迷惑性。
- **按钮点不动**：viewport 上有拖动监听并会 `setPointerCapture`，捕获后 `pointerup` 落在 viewport 上，按钮的 `click` 不再触发（缩放条、返回、节点、胶囊全是按钮）。改为**任何按钮上都不启动拖动**，拖动从地图空白处开始。

另修一个既有缺陷：`chapter` / `diff` / `q` / `view` 原先只在初始化时读一次，浏览器前进/后退切换章节时视图不跟随（地图层级现在也由 `chapterId` 决定，不跟随就会停在上一章的地图上）。补上 `route.query` 监听，比较后再赋值，不与自身的 `router.replace` 打架。

验证：世界地图点秋日荒野 → `?chapter=c1`、28 个节点（15 关 + 5 地区 + 2 副本 + 6 探索）、21 条连线、标签「秋日荒野 · 15 关」、初始缩放 42%；缩放 42%→57%→重置 42%；点 1-1 节点 → 弹窗「1-1 阻击」、URL 带 `stage=c1_1`、关闭正常；返回世界地图 → `/#/chapters`；「展开列表」→ `?view=list`。四个可见章节各自渲染正确（c0 6 节点/5 连线、c1 28/21、c2 24/17、c3 25/18，底图均为各自文件、非占位图）。回归：`source-completion` + `followup` + `filter-collapse` + `app-shell` 共 **60 passed / 3 failed**，3 个失败是 `app-shell.spec.js` 里先前已确认的既有失败（改动前 HEAD 上同样失败）。零失败请求、零 console 错误。

### 地区路线图：三处修正 + 换成游戏原图

用户反馈三点，前两点是我上一轮引入的 bug：

- **地图区高度变短**：地图区的 `v-if` 里带 `isDataReady`，首次挂载时元素还没渲染，`measureMapArea` 量不到元素就停在默认 640；而 `showMap` 没变化，之后也不会重测。改成 `watch([showMap, isDataReady])` 后再测。实测世界地图与地区图都对齐到左右面板底边（880 = 880），`.app-container` 溢出为 0。
- **整张地图上下镜像**：配置是 Unity UI 的 `localPosition`（**+y 向上**），CSS 的 `top` 是 +y 向下。判据取自用户给的游戏截图：2-6 在 2-5 **上方**，而配置 `y(2-6)=1095 > y(2-5)=957`。统一 `y_css = size.h − y_unity`，节点、连线、底图中心全部翻；偏移量（地区 −80、副本 −75）在 Unity 坐标里先加再翻。翻转后校验 403 个 y 值全部落在画布内。
- **换成游戏里的样子**：节点改用游戏原图——关卡是**石台**、地区是**立体图**、副本入口是**入口图**，连线改成**金色虚线**。
  - 石台不是独立素材，在 `MapPanelAtlas.png` 里。图集**不透明**且排得很密（背景色占 52.7%，几乎每列都有内容），「整列全空」式分段完全无效（切出 1 段、0 个候选），改用**连通域标记**切出 178 个块，石台在 x=402 那一竖列上（126×126，另有灰色未开放变体）。矩形固化为 `STAGE_PLATFORM_RECT`。
  - 地区立体图按 `area.icon`（如 `map_w1_c1_a1`）取 `texture/area/icon/`；副本入口图按 `instance.icon` 取，这批散在两个目录（`map_w1_cN_dM` 在 area/icon、`map_fb_*` 在 instancepanel），导入按候选路径取第一个存在的。
  - 导入清单直接读构建产物里的 `icon` 字段，不另维护一份——清单和产物脱节就会出现「有节点没图」的空白。共 52 个文件 3.65 MB（地区立体图 25 个 393 KB、副本 9 个 59 KB）。
  - **只有关卡节点可点**：地区/副本/探索点是装饰（源码里地区节点的 `BoxCollider` 是 `enabled = false`）。一开始都做成按钮，结果 104px 宽的立体图盖住关卡节点、把点击吃掉了；改成非按钮元素 + `pointer-events: none`，并让关卡节点 `z-index` 最高。
  - 顺手补 `.region-map__viewport` 的 `box-sizing: border-box`：它有 1px 边框，不写实际占位比传入的 height 多 2px，地图区就比左右面板高 2px。

验证：世界地图与地区图均对齐左右面板底边、`.app-container` 溢出 0；地区图 28 节点 / 21 连线，缩放 42%→57%→重置 42%，点 1-1 打开「1-1 阻击」详情，返回世界地图与「展开列表」均正常；四个可见章节底图与节点图各自正确、35 个节点图标全部存在；零失败请求、零 console 错误。

### 地区路线图：细节修正（第三轮反馈）

- **副本节点图用错了字段**：要用 `map.instance[].img`（`map_w1_cN_dM`，地图上的立体图），**不是** `instance.icon`——后者是副本自己的平面图标，c1/c2 那几个是 `map_fb_*`，摆上去不是游戏里的样子。改用 `img` 后 10 个副本节点全部命中 `texture/area/icon/`，顺手删掉 3 个不再引用的 `map_fb_*` 产物。
- **「世界地图」标题条位置不对**（一直在中间，之前没注意到）：`.region-map__back` 是 `<button>`，本身 shrink-to-fit，而里面的 `<img>` 用了百分比宽度 `min(50%, 260px)`，两者形成循环依赖，浏览器退化成「按钮撑满、图片居中」。给按钮显式 `width: min(50%, 260px)`、图片 `width: 100%` 后回到左上角，与世界地图画布的位置尺寸完全一致。
- **两处操作提示**：标题条右边「点击返回世界地图」、缩放条左边「按住 ctrl 可用滚轮进行缩放」，都用副本图鉴同款的 `.region-map__hint` 写法（13px、`text-shadow`、只在 `(hover: hover) and (pointer: fine)` 显示）。
- **地区地图放大**：初始缩放从「贴合节点包围盒」再乘 1.4（边距 180→120）。标记是恒定屏幕尺寸、不跟着放大，所以放大后位置铺开、标签重叠明显减少；实测 c1 从 42% 到 63%。
- **锚点只由图形决定**：名称牌改成绝对定位挂在图形下方。原先名称牌参与布局，会把节点整体上推，落点就不准。

## Bug 修复

### 物品来源漏出被隐藏地区

现象：黑森林、霜烬平原在副本图鉴里已经隐藏，但物品详情的「掉落来源」仍列出 `垂死菌林 · 菌林·噩梦`、`伊菲卡温泉谷 · 温泉谷·度假区` 等副本，以及 `委托兑换 · 黑森林`。

根因分两处，**不是同一层能一起解决的**：

1. `searchData.js` 的黑名单过滤只作用于 `searchIndex`，**没有过滤 `itemSources`**——兑换等来源的名字里直接带地区名（「委托兑换 · 黑森林」），于是从物品详情漏出。
2. 副本来源的**名字里不含地区名**（「垂死菌林」属于黑森林、「伊菲卡温泉谷」属于霜烬平原），所以只加文本过滤抓不到；必须按副本的 `mapName` 判断。

修复：

- `dungeonData.js` 的 `buildDungeonItemSources` 跳过 `isBlacklisted({ id, name, label: dungeon.mapName })` 的副本。
- `searchData.js` 在组装完 `itemSources` 后按来源自身的 `id/name/desc/type` 再过一遍黑名单，并丢掉过滤后为空的条目。

验证：`item_10022`（金铃草）来源由 45 条降到 27 条，**0 条再含黑森林/霜烬平原/垂死菌林/伊菲卡温泉谷**；全量 `item-sources.json` 7321 条、`search-index.json` 1839 条，命中被隐藏地区的均为 **0**；浏览器打开物品详情逐词检查无泄漏。

**同一根因的第二个漏点**：`DungeonsView.filteredDungeons` 用 `dungeon.chapter`（值是 `c4`）去匹配黑名单，而黑名单里存的是地区名（`黑森林`）——模糊匹配打不中，于是**筛选按钮被隐藏、副本卡片却还在**（页面上仍能看到「黑森林 · 4 个关卡」）。改用 `dungeon.mapName`。

逐页扫描（17 条路由的可见文本里找这四个词）：除 `/recipes` 外全部干净。

- `/recipes` 仍出现「黑森林松茸」——那是**材料名本身带这个词**，不是地区条目。该物品在物品图鉴里已被模糊名单隐藏，但配方页把它当食材列出来。**未改动**：直接抹掉食材名会让配方看起来缺料，是否隐藏需要产品判断（见「未完成事项」）。

### 隐藏幽夜古堡与黏滑溪谷

`config/blacklist.js` 的模糊名单补入 `幽夜古堡`、`黏滑溪谷`，与黑森林/霜烬平原同口径：章节按钮、关卡列表、世界地图入口、搜索与物品来源一并隐藏。

- 先确认影响面：这两个词在物品/任务/成就/怪物/事件/兑换产物里命中数均为 **0**，加进全局模糊名单不会误伤其他图鉴。
- 关卡图鉴可见章节变为 4 个（求生者草原 / 秋日荒野 / 索利德山地 / 魔爪湖畔，共 44 关），世界地图左下角的两个特殊章节入口随之消失（它们由 `visibleChapters` 推导，不是写死的）。
